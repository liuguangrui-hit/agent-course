1.4 审稿与返修

课后深入，约 30 分钟。需要 Claude 和 Codex 两家。

请别人审稿的价值在于他和你看问题的角度不同。两个 Agent 之间也是这样：同一个模型写完再审，它会认同自己的每一个选择。这一节讲怎样安排一次真正有用的 Agent 审稿，以及拿到意见后怎样改。

为什么要跨厂商

同一家的模型训练数据和偏好相近，写出来的句子在它看来都顺。Claude 写、Claude 审，常见的结果是挑出几个错别字，然后说整体很好。换成 Codex 审，它对 Claude 的措辞习惯没有那么宽容，反过来也一样。

安排很简单：两家的桌面应用打开同一个文件夹，一家写，一家审，意见通过文件交接。不需要复制粘贴，也不需要让它们直接对话。第 4 课会讲怎样用命令行让这一步自动发生。

审稿指令怎么写

一条好的编辑审稿指令：

你是 NeurIPS 的领域主席。只看 versions/v1/main.pdf 和 style_table.md，不看其他版本。
先只读题目和摘要，判断审稿人会不会想读下去，说明理由。
再逐节指出还在防守的句子，重复的限定和读者看不懂的地方，指到具体句子并说明往哪个方向改，不要替我重写。
不审证据是否充分，不要求补充限定。
意见存成 versions/v1/review.md，第一行写明审的是哪个文件。不要改任何文件。

它包含六个要素：

  1. 角色和目标刊会：领域主席，NeurIPS。
  2. 输入只给这一版：一个 PDF 和对照表。
  3. 第一道关口：先单独判断题目和摘要。
  4. 定位到句子，只给方向，不替你重写。
  5. 划清范围：不审证据，不要求加限定。
  6. 交接：写到哪个文件，注明审的版本，不改稿。

两点特别要注意。

先过题目和摘要这一关。 这是真实审稿人的第一反应。题目和摘要不吸引人，后面写得再好也会被带着挑剔读。让审稿 Agent 先单独判断这一关，过不了就直接退回，不必逐节细看。

不要让它要求补充限定。 Agent 审稿时有一个强烈倾向：建议你说明局限，补充条件，弱化结论。这类意见每一条都显得严谨，照改几轮，论文就回到满篇 may 的样子。编辑审稿只管读者愿不愿意读，读不读得懂；证据是否充分是科学审稿的事，分开做，分开给指令。

版本绑定

审稿意见只对它审的那一版有效。规则：

  • 意见文件的第一行写明审的是哪个文件，最好带上修改时间。
  • 稿子改了，旧意见就过期了，下一版要重审。
  • 意见存在被审的版本文件夹里，versions/v1/review.md 对应 versions/v1/main.pdf，不会张冠李戴。

审完不等于通过。review.md 存在，只说明审过了；通过与否看意见里的判定。

按意见返修

拿到意见后，有三个做法。

先列意见，再动手。 让写作的 Agent 先把每条意见列出来，说明打算怎样处理，你看过再改。不同意的意见在这一步就可以划掉。

重讲，不修补。 只改被点到的句子，结果是在原句上打补丁，稿子越来越碎。按意见整体重讲一遍，被点到的问题在重讲中自然消失。

每一轮意见都重读。 第三轮时，Agent 往往只读最近一轮意见，第一轮你纠正过的问题又回来了。历次意见都存档，重讲前全部重读。

读 versions/ 下所有的 review.md，从最早的一轮开始。列出每条意见及它是否已在后续版本中解决。
然后按仍未解决的意见和全部已解决的意见，把论文整体重讲一遍，存到下一个版本文件夹。
重讲后逐条说明处理方式，并确认此前解决过的问题没有重新出现。

把纠正过的问题记下来

每次你亲手纠正 Agent 的一个表达问题，就把它记进 style_table.md：问题，例子，改法，来源和日期。这张表会越来越长，越来越贴合你的口味。写作的 Agent 写之前读它，审稿的 Agent 审的时候对照它。练习材料里的那张表，就是这样一条一条攒出来的。

什么时候停

编辑审稿可以无限进行下去，每一轮总能挑出点什么。给它一个停止规则：审稿判定通过就交给你看；连续三轮不通过，也交给你，附上仍未解决的意见，由你裁定。你看稿时先看题目和摘要，自己有没有想读下去的冲动。

练习

为你自己的目标刊会写一条审稿指令，用它审练习 1 得到的 versions/v1/main.pdf。然后故意在指令里删掉不要求补充限定这一句，再审一次，比较两份意见。

通常会看到什么

删掉那一句后，意见里会多出好几条类似 the authors should clarify that results are limited to synthetic data 或 consider softening the claim in the title 的建议。每一条单独看都有道理，合起来会把论文推回初稿的样子。这就是要把编辑审稿和科学审稿分开的原因。

最容易出错的地方

审稿意见把限定加回来。 审稿 Agent 建议说明局限，弱化结论，照改几轮，满篇限定又回来了。编辑审稿明确不审证据，不要求补充限定。

审的是旧版本。 稿子已经改到 v3，审稿 Agent 读的还是文件夹里的 v1。指令里写死要审的文件，意见第一行写明版本。

只改被点到的句子。 每条意见改一处，十条意见打十个补丁，整篇读起来像拼接的。按意见整体重讲。

改过的问题又回来。 第一轮纠正过的题目问题，第三轮重讲时又出现了，因为它只读了最近一轮意见。每轮重讲前读全部历次意见。

审稿无限循环。 每一轮都能挑出新问题，稿子在两种风格之间来回摆。设定轮次上限，超过就交给人裁定。

延伸阅读

  • NeurIPS Reviewer Guidelines：真实审稿人被要求关注什么，可以拿来写科学审稿的指令。

1.4 Review and revision

Self-study, about 30 minutes. Needs both Claude and Codex.

A colleague’s review is worth having because they see the paper from a different angle. The same holds between two agents: when the model that wrote a paper also reviews it, it agrees with every choice it made. This page covers how to set up an agent review that actually helps, and how to revise once the comments come in.

Why use a second vendor

Models from one vendor share similar training data and preferences, so every sentence one of them writes reads smoothly to it. When Claude writes and Claude reviews, the usual outcome is a few typos and a verdict that the paper is good overall. Codex reviewing is less forgiving of Claude’s phrasing habits, and the reverse holds too.

The setup is simple. Open the same folder in both desktop apps; one writes, the other reviews, and the comments pass between them as files. No copying and pasting, and no need for them to talk to each other directly. Session 4 shows how to make this step happen automatically from the command line.

Writing the review instruction

A good editorial review instruction:

You are an area chair for NeurIPS. Look only at versions/v1/main.pdf and style_table.md, no other versions.
First read only the title and abstract and judge whether a reviewer would want to read on, and why.
Then go section by section and point out sentences that still hedge, repeated caveats and anything a reader would not follow, quoting the exact sentence and saying which way to change it. Don't rewrite it for me.
Don't judge whether the evidence is sufficient, and don't ask for added caveats.
Save your comments as versions/v1/review.md, with the first line naming the file you reviewed. Don't change any files.

It has six parts:

  1. Role and target venue: an area chair at NeurIPS.
  2. Input, this version only: one PDF and the style table.
  3. A first gate: judge the title and abstract on their own.
  4. Pin each comment to a sentence and give a direction, without rewriting.
  5. Scope: no judging the evidence, no requests for caveats.
  6. Handoff: which file to write, which version was read, no edits to the paper.

Two of these need special care.

Clear the title and abstract gate first. This is a real reviewer’s first reaction. If the title and abstract don’t draw them in, they read everything after with a critical eye, however well it is written. Have the reviewing agent judge this gate on its own first. If the paper fails it, send it straight back without a section-by-section read.

Don’t let it ask for added caveats. Agents reviewing a paper have a strong pull toward suggesting you state limitations, add conditions and soften conclusions. Each such comment looks rigorous, and after a few rounds of following them the paper is back to “may” in every sentence. An editorial review covers only whether readers want to read on and whether they can follow. Whether the evidence suffices is the job of a scientific review: run it separately, with its own instruction.

Tie each review to a version

A review applies only to the version it read. The rules:

  • The first line of the review file names the file reviewed, ideally with its modification time.
  • Once the paper changes, the old comments are out of date, and the next version gets a fresh review.
  • Comments live in the folder of the version they review: versions/v1/review.md goes with versions/v1/main.pdf, so comments never get attached to the wrong draft.

A finished review is not a pass. The existence of review.md shows only that a review happened. Whether the paper passed depends on the verdict inside.

Revising from the comments

Once you have the comments, three habits help.

List the comments before touching anything. Have the writing agent list every comment first and say how it plans to handle each one, and read the list before it revises. You can strike out the comments you disagree with at this step.

Retell, don’t patch. Changing only the sentences the comments point to patches the original text, and the paper grows more fragmented each round. Retell the whole paper following the comments, and the problems they pointed to disappear in the retelling.

Reread every round of comments. By round three the agent tends to read only the latest comments, and a problem you corrected in round one comes back. Archive every round and reread them all before each retell.

Read every review.md under versions/, starting from the earliest round. List each comment and whether a later version has resolved it.
Then retell the whole paper, following the comments still open and every comment already resolved, and save it to the next version folder.
After the retell, say how you handled each comment, and confirm that no previously resolved problem has come back.

Record the problems you corrected

Each time you correct one of the agent’s phrasing problems by hand, add it to style_table.md: the problem, an example, the fix, the source and the date. The table keeps growing and fits your taste more closely over time. The writing agent reads it before writing, and the reviewing agent checks against it while reviewing. The table in the exercise materials was built up this way, one entry at a time.

When to stop

An editorial review can go on forever, since every round finds something. Give it a stopping rule: when the review passes the paper, it comes to you to read; after three failed rounds in a row, it also comes to you, with the unresolved comments attached, and you decide. When you read the paper, start with the title and abstract and ask yourself whether you feel the urge to read on.

Exercise

Write a review instruction for your own target venue and use it to review the versions/v1/main.pdf you produced in Exercise 1. Then deliberately delete the line telling it not to ask for added caveats, review again, and compare the two sets of comments.

What you usually see

With that line gone, the comments gain several suggestions like “the authors should clarify that results are limited to synthetic data” or “consider softening the claim in the title”. Each one makes sense on its own. Together they push the paper back toward the draft. That is why editorial review and scientific review are kept apart.

Where agents go wrong most

Review comments bring the caveats back. The reviewing agent suggests stating limitations and softening conclusions. Follow it for a few rounds and caveats are everywhere again. An editorial review explicitly leaves the evidence alone and asks for no added caveats.

Reviewing an old version. The paper is already at v3, and the reviewing agent is still reading the v1 in the folder. Name the exact file to review in the instruction, and have the first line of the comments state the version.

Changing only the sentences the comments point to. One fix per comment means ten patches for ten comments, and the whole paper reads as if stitched together. Retell the whole paper following the comments.

Fixed problems come back. The title problem corrected in round one reappears in the round-three retell, because the agent read only the latest comments. Read every past round of comments before each retell.

Endless review loops. Every round finds new problems, and the paper swings back and forth between two styles. Set a cap on the number of rounds; past it, a person decides.

Further reading

1.4 审稿返修

学习目标

  1. 区分编辑审稿与科学审稿的职责，为每次审阅限定输入范围、绑定文件版本并要求明确判定。
  2. 评价审阅意见是否可定位、可处理，并通过主张检查区分需要补证、改写表达和确需收窄的意见。
  3. 依据审阅意见按叙事关系重写稿件，并记录意见冲突的处理理由与版本对应关系。

课后深入专题，约 30 分钟。

存在审稿文件，只能说明审阅已经完成。还需要确认它审的是哪一版，判断依据是什么，以及稿件是否获得通过。

审阅职责的界定

编辑审稿判断读者能否把握论文中心，科学审稿判断证据能否支撑主张。两项工作分别提供输入，分别保存意见。每次审阅只承担一项明确职责，意见才便于采用。

本节练习编辑审稿。审阅者获得本版 PDF、表达约定和实际使用的范文，先读题目与摘要，再读全文。审阅者使用独立的新会话，并尽量换用另一家厂商，以免沿用作者的解释。

以目标读者的身份审阅 versions/v1/main.pdf。
先只读题目和摘要，写出你理解的核心发现和最想追问的问题，再判断开头是否成立。
随后读全文，定位叙事断点、重复段落和图文脱节，每条说明改进方向。
将意见写到 versions/v1/review.md，首行注明文件身份，给出通过或退修判定。
只改意见文件。最后附主张检查。

审阅完成后先核对审阅者的输入，确认它只获得当前版本和范文，再看它能否独立复述核心发现。

意见的定位与改写建议

一条可处理的意见应包括所在章节、具体句子或段落、读者在何处产生困难，以及改写方向。例如，读完开篇仍不清楚为何比较两种损失，就应把先学会后退步的现象提前，并让第一张图回答这一问题。

整体较好、逻辑有待提升之类的笼统意见应当删除。意见定位到具体文本，作者才能判断它是否成立。

意见以主张检查收尾：逐条列出要求缩小标题或核心主张的建议，并说明依据。

例如，练习稿希望说明有界损失能够避免后期拟合错误标签，审阅者因为只见到合成数据而要求缩小标题。此时应先追问需要哪项实验才能在原有尺度上支撑这一主张：增加真实图像数据，改变噪声机制，并直接测量错误标签的拟合率。保留原有研究问题并补足证明，即按原尺度补证。

只有新增证据否定了主张，或主张本身无法检验时，才说明怎样改写。表达难以理解的问题则回到提纲重写。主张检查把这几类意见区分开，作者才能判断下一步应修改文字还是补做实验。

审阅版本记录

审阅意见中写明所审 PDF 的路径和 SHA-256。稿件改到下一版时，旧意见复制为历史输入，新意见仍须针对新文件作出判定。

读取本版 PDF 的 SHA-256，写进审阅记录。
返修时保留原版，生成 versions/v2/，逐条写处理说明。
标题与核心主张前后并排展示，若变小，说明是哪条证据要求的。

编辑审阅只读最终稿与范文；作者返修时读取历次用户意见和编辑意见。科学审稿的历史单独保存，以免编辑者把全文写成对质疑的逐条辩护。

依据意见重写

先把尚未解决的问题按叙事关系合并。同一个开篇问题可能在摘要、引言和结论中各出现一次，一次调整主线即可同时处理。随后按新提纲重写全文，逐项核对数据事实与已纠正的问题。

意见相互冲突时，在回复中写明采用哪种写法及其理由。若连续几轮修改只是在不同偏好之间反复，应把两种完整写法交由人工判断。课程以三轮作为人工裁定点，避免无限期修改。

练习

从真实审稿意见中选三条，改写为可执行的编辑意见。请同学只凭意见定位问题，再由作者据此重写。若对方找不到原文位置或不清楚要改变什么，说明意见仍不够具体。

常见错误与处理方法

作者把自己的解释一并交给审阅者。 先让审阅者单独读稿并记录第一反应，再由作者回复。

意见要求缩小标题，却未给出理由。 退回补充依据，按上例先列出需要增加的实验。

修改完成即宣布审稿通过。 修改者报告处理情况，审阅者针对新版本作出判定，两份记录分别保存。

1.4 Peer review and revision

Learning outcomes

After this section, students should be able to:

  1. Design a review with a single defined responsibility, a controlled input scope and a verdict tied to an identified version.
  2. Write and evaluate review comments that locate a problem in the text and indicate a direction for revision, and apply a claim check that distinguishes requests for further evidence from requests to narrow a claim.
  3. Plan a revision that resolves comments by their effect on the argument and documents how each comment was handled.

Extension reading and exercises, about 30 minutes.

A review file shows only that a review took place. Using a review also requires knowing which version the reviewer read, what the judgment rests on, and whether the verdict is a pass.

Defining the reviewer’s question

An editorial review judges whether readers can identify the main finding; a scientific review judges whether the evidence supports the claims. The two tasks receive separate inputs and their comments are saved separately. Comments are easier to act on when each review has a single, clear responsibility.

This section concentrates on editorial review. The reviewer is given this version’s PDF, the style conventions and the exemplar actually used, and is asked to read the title and abstract first, then the whole paper. The reviewer works in a separate new session, preferably from another vendor, so that it does not inherit the author’s explanations.

Review versions/v1/main.pdf as a member of the target readership.
First read only the title and abstract, write down the core finding as you understand it and the question you most want to ask, then assess whether the opening works.
Then read the whole paper and locate narrative breaks, repeated paragraphs and figures disconnected from the text, giving a direction for improvement for each.
Write the comments to versions/v1/review.md, with the file identity on the first line and a verdict of pass or return for revision.
Change only the comments file. End with a claim check.

Check the reviewer’s input to confirm that it received only this version and the exemplar, then examine whether it restated the core finding independently.

Specific and actionable comments

An actionable comment identifies the section, the specific sentence or paragraph, where the reader was impeded, and the direction of the rewrite. For example: if after the opening the reader still does not know why two losses are compared, the phenomenon of learning first and deteriorating later should come earlier, and the first figure should answer that question.

Comments such as “overall very good” and “suggest further improving the logic” are removed. Only when a comment points to the text can the author judge whether it holds.

Comments end with a claim check: every suggestion to narrow the title or a core claim is listed together with its grounds.

For example, the exercise draft aims to show that a bounded loss avoids memorizing wrong labels later in training, but the reviewer asks for a narrower title because only synthetic data were shown. The first step is to ask which experiments would support the original question: adding real image data, changing the noise mechanism and directly measuring the rate at which the model fits incorrect labels. These add evidence at the original scope of the claim and preserve the research question.

A rewrite of the claim is proposed only if new evidence refutes it or if the claim cannot be tested. If the problem is one of expression, the author returns to the outline and restructures the text. The claim check separates these kinds of comment, so that the author knows whether the next step is to revise the text or to run an experiment.

Tying each review to a specific version

The path and SHA-256 of the reviewed PDF are written into the comments. When the draft moves to the next version, the old comments are kept as historical input, and the new comments give a verdict on the new file.

Read the SHA-256 of this version's PDF and write it into the review record.
When revising, keep the original version, produce versions/v2/, and write how each comment was handled.
Show the title and core claims before and after side by side; if their scope was reduced, state which evidence required it.

The editorial reviewer reads the final draft and the exemplar; when revising, the author reads all past user comments and editorial comments. The history of scientific review is kept separately, so that the editor does not turn the whole paper into a point-by-point defense against objections.

Revising in response to the review

Unresolved problems are first grouped by their effect on the narrative. The same opening problem may appear three times, in the abstract, the introduction and the conclusion, and a single reordering of the main line resolves all three. The full text is then generated from the new outline, every factual result is checked, and previously corrected problems are verified not to have returned.

When comments conflict, the response states which approach to the narrative was adopted and why. When several rounds alternate over matters of taste, both complete versions are given to a person to decide. The course uses three rounds as the point for a human decision, to avoid indefinite editing.

Exercise

Select three comments from a real review and rewrite them as actionable editorial comments. Ask a colleague to locate the problems from the comments alone, then have the author revise accordingly. If the colleague cannot find the place or does not know what to change, the comment is not yet specific enough.

Common errors and corrections

The author passing its own explanations to the reviewer. Have the reviewer read the draft alone and record its first reaction before the author responds.

A request to narrow the title without stated grounds. Return it for justification and, as in the example above, first list the experiments that would need to be added.

Treating completed changes as a passed review. The reviser reports how each comment was handled, the reviewer gives a verdict on the new version, and the two records are kept separately.

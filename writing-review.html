1.4 审稿返修

课后深入，约 30 分钟。

有审稿文件，只能说明完成过审阅。你还需要知道它读的是哪一版，判断依据是什么，以及稿件是否通过。

明确审阅职责

编辑审稿判断读者能否抓住中心，科学审稿判断证据能否支撑主张。两项工作分别给输入，分别保存意见。一次审阅只有一个明确职责，意见才容易采用。

本节做编辑审稿。给审阅者本版 PDF、表达约定和实际使用的范文，让它先读题目与摘要，再读全文。审阅者使用独立新会话，优先换一家厂商，避免沿用作者的解释。

以目标读者的身份审阅 versions/v1/main.pdf。
先只读题目和摘要，写出你理解的核心发现和最想追问的问题，再判断开头是否成立。
随后读全文，定位叙事断点、重复段落和图文脱节，每条说明改进方向。
将意见写到 versions/v1/review.md，首行注明文件身份，给出通过或退修判定。
只改意见文件。最后附主张检查。

检查审阅者的输入，确认它只拿到了当前这一版和范文，再看它是否独立复述出了核心发现。

定位问题与改写建议

一条可处理的意见包括所在节，具体句子或段落，读者卡在哪里，以及改写方向。比如读完开篇仍不知道为什么比较两种损失，就应当把先学会后退步的现象提前，并让第一张图回答这个问题。

像整体很好、建议进一步提升逻辑这类空泛意见，直接删去。定位到文本，作者才能判断意见是否成立。

意见以主张检查收尾：逐条列出要求缩小标题或核心主张的建议，说明依据。

例如，练习稿想说明有界损失能避免后期记住错误标签，审阅者却因为只见过合成数据而要求改小标题。先问需要哪项实验才能支撑原来那个问题：增加真实图像数据，改变噪声机制，再直接测错误标签拟合率。把要回答的问题保留下来并补足证明，这就是按原尺度补证。

如果新增证据否定了主张，或主张本身无法检验，再说明怎样改写。表达难懂则回到提纲重讲。主张检查把这几种意见分清，作者才知道下一步该改文字还是做实验。

审阅版本记录

把审阅的 PDF 路径和 SHA-256 写进意见。稿件改到下一版，复制旧意见作为历史输入，新意见仍要针对新文件作出判定。

读取本版 PDF 的 SHA-256，写进审阅记录。
返修时保留原版，生成 versions/v2/，逐条写处理说明。
标题与核心主张前后并排展示，若变小，说明是哪条证据要求的。

编辑审阅读最终稿及范文，作者返修时读历次用户意见和编辑意见。科学审稿历史单独保留，避免编辑者把整篇写成对质疑的逐项辩护。

按意见重讲

先把仍未解决的问题按叙事关系合并。同一个开篇问题可能在摘要、引言和结论出现三次，一次重排主线即可同时处理。随后按新提纲重写全文，逐项核对数据事实与已纠正问题。

遇到意见冲突，在回复里写清采用哪种讲法及理由。连续几轮围绕口味来回摆动时，把两种完整写法交给人判断。课程用三轮作为人工裁定点，避免无限编辑。

练习

从真实审稿意见里挑三条，改写为可执行的编辑意见。请同学只看意见定位问题，再让作者据此重讲。若对方找不到原处或不知道要改变什么，意见还不够具体。

常见错误与处理方法

作者把自己的解释也交给审阅者。 先让审阅者单独读稿，留下第一反应，再由作者回复。

意见要求缩小标题，却没有给理由。 退回补依据，按上面的例子先列需要增加的实验。

修改完成就宣布审稿通过。 修改者报告处理情况，审阅者针对新版本给判定，两份记录分别保存。

1.4 Peer review and revision

After-class deep dive, about 30 minutes.

A review file shows only that a review took place. You also need to know which version they read, what their judgment rests on, and whether the verdict is a pass.

Give the reviewer a clear question

An editorial review judges whether readers can identify the main finding; a scientific review judges whether the evidence supports the claims. Give the two jobs separate inputs and save their comments separately. Comments are easy to act on when each review has one clear responsibility.

This section focuses on editorial review. Give the reviewer this version’s PDF, the style conventions and the exemplar actually used, and have it read the title and abstract first, then the whole paper. The reviewer uses a separate new session, preferably from another vendor, so it does not inherit the author’s explanations.

Review versions/v1/main.pdf as a member of the target readership.
First read only the title and abstract, write down the core finding as you understand it and the question you most want to ask, then assess whether the opening works.
Then read the whole paper and locate narrative breaks, repeated paragraphs and figures disconnected from the text, giving a direction for improvement for each.
Write the comments to versions/v1/review.md, with the file identity on the first line and a verdict of pass or return for revision.
Change only the comments file. End with a claim check.

Check the reviewer’s input to confirm it received only this version and the exemplar, then see whether it restated the core finding independently.

Make comments specific and actionable

A comment that can be acted on includes the section, the specific sentence or paragraph, where the reader got stuck, and the direction of the rewrite. For example, if after the opening you still do not know why two losses are compared, the phenomenon of learning first and getting worse later should come earlier, and the first figure should answer that question.

Delete empty comments like “overall very good” and “suggest further improving the logic”. Only when a comment points to the text can the author judge whether it holds.

Comments end with a claim check: list every suggestion to narrow the title or a core claim, and give its grounds.

For example, the exercise draft wants to show that a bounded loss avoids memorizing wrong labels later in training, but the reviewer asks for a narrower title because only synthetic data were shown. First ask which experiments would support the original question: add real image data, change the noise mechanism, and measure directly the rate at which the model fits incorrect labels. This adds evidence for the original scope of the claim while preserving the research question.

Only if new evidence refutes the claim, or the claim itself cannot be tested, do you say how to rewrite it. If the expression is hard to follow, go back to the outline and restructure the text. The claim check separates these kinds of comments, so the author knows whether the next step is to change the text or run an experiment.

Tie each review to a specific version

Write the path and SHA-256 of the reviewed PDF into the comments. When the draft moves to the next version, copy the old comments as historical input, and the new comments still give a verdict on the new file.

Read the SHA-256 of this version's PDF and write it into the review record.
When revising, keep the original version, produce versions/v2/, and write how each comment was handled.
Show the title and core claims before and after side by side; if their scope was reduced, state which evidence required it.

The editorial reviewer reads the final draft and the exemplar; when revising, the author reads all past user comments and editorial comments. The scientific review history is kept separately, so the editor does not turn the whole paper into a point-by-point defense against objections.

Revise in response to the review

First merge the unresolved problems by how they affect the narrative. The same opening problem may appear three times, in the abstract, introduction and conclusion, and one reordering of the main line handles them all. Then generate the full text from the new outline and check every factual result and verify that previously corrected problems have not returned.

When comments conflict, state in the response which approach to the narrative you adopted and why. When several rounds swing back and forth over taste, give both complete versions to a person to decide. The course uses three rounds as the point for human decision, to avoid endless editing.

Exercise

Pick three comments from a real review and rewrite them as actionable editorial comments. Have a classmate locate the problems from the comments alone, then have the author revise accordingly. If the classmate cannot find the place or does not know what to change, the comment is not yet specific enough.

Common mistakes and how to fix them

The author hands its own explanations to the reviewer as well. Have the reviewer read the draft alone first and record its first reaction, then let the author respond.

A comment asks to narrow the title without giving a reason. Return it for justification, and as in the example above, first list the experiments that would need to be added.

Declaring the review passed once the changes are done. The reviser reports how each comment was handled, the reviewer gives a verdict on the new version, and the two records are saved separately.

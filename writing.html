1 写作绘图

把一篇重点不清的四页论文，重写为围绕核心发现展开的稿子。完成重讲稿和两张重新生成的数据图，取得独立编辑审稿意见，并提炼下次可调用的 paper-retell Skill。

课前完成准备，课上 60 分钟，课后先复习再选做深入。

课前预备 · 课上一小时 · 课后复习与拔高

训练标签错了四成，网络却很早就找到了大部分正确答案。继续训练，测试表现反而掉下去。练习论文把这个现象埋在背景和方法清单之后，读完摘要还不知道为什么值得看。

这一课让 Agent 围绕这个发现重写论文。材料中的实验已在本机跑过，原数据和运行脚本都在包里。课堂使用现成数据，把时间留给论文表达与核查。

下载练习材料 · 做完再看参考答案

课前预备

预留 30 至 90 分钟，主要取决于 LaTeX 下载。首次安装可提前一天开始。

课前工具准备。 Python 项目环境，LaTeX 和 PDF 渲染器在这一步装好。课堂从已有论文开始，共同完成重讲与绘图，再做独立审稿。

在 lesson-1 工作，读 AGENTS.md，保留原稿和 data/。
检查 Python 项目环境，运行 code/plot_draft.py，编译 paper/main.tex，再把第一页渲染成图片。
缺工具时报告官方来源、安装位置与下载体积，安装到约定位置，实际运行后再记录为可用。
从官方入口取得 arXiv 1611.03530 的范文到 exemplar/，确认 PDF 能打开、标题与标识相符，先不分析讲法。
把实际运行命令、页数和错误信息写到 preflight.md；稳定调用方法写入 AGENTS.md。

带到课堂的四项结果：能读 CSV，能生成图，能编译原稿，能打开渲染页。另备好范文原件。CLAUDE.md 用一行 @AGENTS.md 导入同一份约定，两家 Agent 都从材料根目录启动。

安装卡住时，把错误码和系统信息提前交给老师。课堂可先用包内 preview/before.pdf 与两张成品对照图练讲法，记录尚未完成的编译检查，课后补做。不要在开课后重新下载整套 LaTeX。

课上一小时

先看同一份研究的两种讲法，5 分钟

打开课前的 preflight.md，确认编译和渲染已有结果；随后直接比较两种讲法。

初稿先铺深度学习的背景，读者要往后找才知道发现。重讲稿把网络先学会、后来退步的变化放到开头，接着回答三个问题：这个变化有多大，为什么不同损失会有差别，替代办法能否留下早期学到的东西。

图也按这个顺序读。第一张看训练过程，第二张看不同噪声比例下的比较。曲线和标注都围绕主要比较来安排，读者不用先辨认二十条线。

围绕核心发现组织论文，8 分钟

让 Agent 罗列工作，它很容易写成做了什么的清单。读者更关心研究改变了什么认识。先把那个发现写成一句能记住的话，再决定哪份证据先出现。

范文在这里提供的是叙事顺序。看它怎样引出具体问题，给出答案，再引导读者阅读下一项证据。用自己的材料重新搭这条顺序，句子也重新写。

数据核查与论文表达分别处理。重讲可以移动段落，却必须保留数据的版本与来源。数字和图均由脚本从数据生成；编辑审阅再判断读者是否能抓住发现。

练习一，找到开头并重讲，17 分钟

在写作 Agent 中发送：

读 paper/main.tex 与 data/，先理解全文。
读课前存到 exemplar/ 的 arXiv 1611.03530 范文，分析题目、摘要和开篇怎样引出下一问。
列出本练习最值得开篇的三个发现，各带数据出处。选一个作为叙事中心，给三个题目。
用其中最清楚的题目，先写一份每段一句话的提纲，再另起全文到 versions/v1/main.tex。
图先沿用原图。编译 PDF，把提纲和编辑说明一并保存。原稿保留。

读提纲时，试着只看段首复述论文。若复述出来的是作者依次做了哪些事，提纲还要重排；若每段都在回答上一段留下的问题，可以写全文。

课堂让 Agent 自选一个题目完成初稿，你再改最关键的一处。到本段结束仍未编译出 v1，就带提纲与已完成章节进入下一段，用包内 preview/after.pdf 练审稿；自己的完整 v1 课后补审，记录两份审阅对象。正式论文可以把题目和提纲单独拿出来讨论。

练习二，让图回答同一个问题，13 分钟

读 code/plot_draft.py 和 style_table.md，用 data/ 重写 code/plot_paper.py。
每张图先写一句它要回答的问题。按论文实际栏宽输出矢量 PDF，保留全部种子的数据来源。
方法与颜色固定对应，说明均值和误差带的含义，把方法名放在读者能看清的位置。
输出到 versions/v1/figures/，更新本版论文引用。编译并逐页查看渲染结果，修复重叠与出界。

看页面时，按实际阅读大小检查。最细的字能否读清，图注是否解释误差，主结论是否来自画出的量。画图脚本保留下来，换数据后继续生成。

练习三，独立审阅与方法留档，12 分钟

在另一家 Agent 的新会话里发送：

只读 versions/v1/main.pdf、style_table.md 与 exemplar/ 中的范文。
先读题目和摘要，判断你想继续追问什么；若抓不住中心，先指出卡住的具体位置。
再读全文，检查段落顺序和图文关系。每条意见定位到具体文本并给改进方向。
只写 versions/v1/review.md，注明审阅文件和判定，不改稿。
意见最后做主张检查：若要求缩小标题或核心主张，逐条说明必要证据；表达问题直接给重讲办法。

另一家提供不同视角，独立性还来自输入范围：它只看这一版及范文，自己作出判断。课堂先指出最该处理的一条意见，课后让原作者按意见生成 versions/v2/，保留逐条处理说明。

最后发送：

先把这次有效的改稿方法写成最小 paper-retell Skill。
内容涵盖范文分析与数据核查，以及整稿重讲和独立编辑审阅；调用已有脚本，去掉这次专用的文件名。
用新会话检查能否找到 Skill 和构建入口；完整迁移测试放在课后另一篇材料上。

检查与工作台小结，5 分钟

常见错误与处理方法

润色让每句更顺，论文仍缺少核心发现。 回到提纲，把读者要追问的问题排好，再从头重讲。

数字能在数据里找到，就判正确。 同一个数可能来自另一组。核查记录要同时写指标、配置与分母，详见 1.2。

只看图文件，漏看成稿。 图放进栏里会缩放。编译后查看整页，按最终尺寸判断可读性。

审过就接着用，稿件已经换版。 意见绑定审阅文件；新版本重新交审，审阅记录同时写明通过还是退修。

工作台小结

Python 从数据生成图，LaTeX 把源稿编译为 PDF，渲染器提供逐页检查所需的图片。AGENTS.md 留下入口，paper-retell 留下做法。下一次改稿时，先给材料和范文，Agent 就能按这些约定工作。

课后复习与拔高

先复盘，15 分钟

先不打开 Agent，用五句话复述自己的稿子。先讲发现，再给关键证据和比较，接着讲解释，最后留下下一问。再打开课堂保存的版本，抽一个数字追回数据行，说明它属于哪种设置。把复述与发现的缺口写到 review-after-class.md。

正反例辨析，15 分钟

下面是两种练习提纲。甲先铺背景，接着罗列模型和实验，最后总结。乙从训练先变好后退步开始，再给曲线、比较损失，最后解释差异。选出更能带出研究问题的一份，再指出它还缺哪项数据依据。另看两张图：一张只画最好种子，另一张按同一设置保留全部种子。各写一句读者可以从中作出的判断。

写完判断，再看对照思路

乙让后一段回答前一段的问题，但题目与曲线仍要对应同一实验。只画最好种子的图可展示那次运行的轨迹，不能据此估计典型表现；保留全部种子后还要说明汇总与误差的口径。

沿课堂往深处做

课堂交出一个明确版本的重讲稿和审阅记录，课后先按意见生成下一版，再选一条路径。换自己的材料重做时，保留整稿重讲的目标和数字核查，不只替换范例里的名词。

1 Writing and figures

Restructure a four-page paper with an unclear main point around a single finding. You will produce a revised draft and two regenerated figures, receive an independent editorial review, and create a reusable paper-retell Skill.

Prepare before class, spend 60 minutes in class, then review and choose an optional extension.

Before class · In class · After class: review and extension

Forty percent of the training labels are wrong, yet the network finds most of the right answers early. Keep training and test performance drops. The exercise paper buries this behind background and a list of methods, so after the abstract you still do not know why it is worth reading.

In this lesson, you use an agent to restructure the paper. The experiment in the materials has already been run locally, and the raw data and run scripts are in the package. The class uses the existing data and focuses on presentation and verification.

Download the exercise materials · Reference answers, for after you finish

Before class

Allow 30 to 90 minutes, mostly for the LaTeX download. You can start the first install a day early.

Before-class setup. The Python project environment, LaTeX and a PDF renderer are installed in this step. The class starts from an existing paper; restructuring, plotting and reviewing are all done together in class.

Work in lesson-1, read AGENTS.md, and keep the original draft and data/ unchanged.
Check the Python project environment, run code/plot_draft.py, compile paper/main.tex, then render the first page as an image.
If a tool is missing, report its official source, install location and download size, install it in the agreed location, and record it as usable only after it has actually run.
Get the arXiv 1611.03530 exemplar from the official source into exemplar/, confirm that the PDF opens and that its title and identifier match. Do not analyze its narrative structure yet.
Write the commands actually run, the page count and any error messages into preflight.md; write reusable tool commands into AGENTS.md.

Bring four results to class: CSV can be read, figures can be generated, the original draft compiles, and the rendered page opens. Also have the exemplar original ready. CLAUDE.md imports the same conventions with one line, @AGENTS.md, and both agents start from the root of the materials.

If installation gets stuck, send the error code and system information to the teacher in advance. In class you can practice structuring the paper with the packaged preview/before.pdf and the two before-and-after images, note the compilation check still to be done, and finish it after class. Do not re-download the whole of LaTeX after class has started.

In class

Two ways to present the same research, 5 minutes

Open the preflight.md from before class and confirm that compilation and rendering have results; then compare the two versions directly.

The draft opens with background on deep learning, and the reader has to search further on to learn the finding. The revised draft opens with the network learning early and declining later, and then answers three questions: how large the change is, why losses behave differently, and whether alternatives can keep what was learned early.

Read the figures in the same order. The first shows the training process, the second compares noise rates. Lines and labels each have a job, and the reader does not have to sort out twenty lines first.

Build the paper around one finding, 8 minutes

Ask an agent to describe the work, and it may simply list what was done. Readers care more about what the research changed in our understanding. First write that finding as one memorable sentence, then decide which evidence comes first.

Use the exemplar to study narrative structure. Look at how it establishes a specific research question, how it gives the answer, and how it leads the reader to the next piece of evidence. Rebuild that order with your own material, and write the sentences anew.

Check the numbers separately from the narrative. Restructuring may move paragraphs, but the underlying data and their provenance must stay the same. Numbers come from scripts and figures come from data; the editorial review then judges whether the reader can grasp the finding.

Exercise 1: choose an opening and restructure the draft, 17 minutes

In the writing agent, send:

Read paper/main.tex and data/, and understand the whole paper first.
Read the arXiv 1611.03530 exemplar saved to exemplar/ before class, and analyze how its title, abstract and opening lead into the next question.
List the three findings in this exercise most worth opening with, each with its data source. Choose one as the narrative center and give three titles.
Using the clearest title, first write an outline with one sentence per paragraph, then rewrite the complete paper in versions/v1/main.tex.
Keep the original figures for now. Compile the PDF and save the outline and editing notes with it. Keep the original draft.

When reading the outline, try summarizing the paper from its paragraph openings alone. If what comes out is the sequence of things the authors did, the outline needs reordering; if each paragraph answers the question left by the one before, you can write the full text.

In class, let the agent choose a title itself and finish the first draft, then revise the most important point yourself. If v1 has not compiled by the end of this block, take the outline and finished sections into the next block and practice reviewing with the packaged preview/after.pdf; have your own complete v1 reviewed after class, and record both review targets. For a real paper, the title and outline can be discussed on their own.

Exercise 2: make the figures answer the same question, 13 minutes

Read code/plot_draft.py and style_table.md, and rewrite code/plot_paper.py using data/.
For each figure, first write one sentence stating the question it answers. Output vector PDFs at the paper's actual column width, keeping the data source for all seeds.
Give each method a fixed color, state what the mean and the error band mean, and put method names where readers can see them.
Output to versions/v1/figures/ and update this version's figure references. Compile and look at the rendered result page by page, fixing overlaps and anything out of bounds.

When looking at the pages, check them at actual reading size. Can the smallest text be read, does the caption explain the error, and does the main conclusion come from the quantity plotted? Keep the plotting script, so the figures can be regenerated when the data change.

Exercise 3: get an independent review and save the method, 12 minutes

In a new session of the other vendor’s agent, send:

Read only versions/v1/main.pdf, style_table.md and the exemplar in exemplar/.
Read the title and abstract first and decide what you want to ask next; if the main finding is unclear, first point to the exact place where you got stuck.
Then read the full paper and check paragraph order and how figures relate to the text. Tie every comment to specific text and give a direction for improvement.
Write only versions/v1/review.md, naming the file reviewed and your verdict. Do not change the draft.
End your comments with a claim check: if you ask to narrow the title or a core claim, give the evidence that makes it necessary for each one; for problems of expression, suggest how to restructure the text.

The other vendor offers a different view, and independence also comes from the input scope: it sees only this version and the exemplar and forms its own judgment. In class, first point out the comment that most needs handling; after class, have the original author produce versions/v2/ from the comments, keeping a note on how each comment was handled.

Finally, send:

First write the revision method that worked this time into a minimal paper-retell Skill.
Cover exemplar analysis, number checking, restructuring the complete draft and independent editorial review; call the existing scripts and drop the file names specific to this run.
Use a new session to check that the Skill and the build command can be found; the full transfer test is done after class on another set of materials.

Check and workbench summary, 5 minutes

Common mistakes and how to fix them

Polishing makes every sentence smoother, but the paper still has no center. Go back to the outline, put the reader’s follow-up questions in order, and rewrite the full paper.

Judging a number correct because it can be found in the data. The same value may come from another group. The check record must state the metric, the configuration and the denominator together; see 1.2.

Looking only at the figure file and missing the finished page. A figure is scaled when placed in a column. Look at the whole page after compiling and judge readability at final size.

Using a review after the draft has moved on to a new version. Comments are tied to the file reviewed; a new version goes back for review, and the review record states whether it passed or was returned for revision.

Workbench summary

Python connects data to figures, LaTeX connects source to PDF, and the renderer produces page images for visual inspection. AGENTS.md keeps the entry points and paper-retell stores the method. The next time you revise a paper, give the agent the materials and an exemplar, and it can follow the saved method.

After class: review and extension

Review first, 15 minutes

Without opening the agent, summarize your draft in five sentences. Give the finding first, then the key evidence and comparison, then the explanation, and finally the next question. Then open the version saved in class, trace one number back to its data row, and say which setting it belongs to. Record omissions or errors in your summary in review-after-class.md.

Compare the examples, 15 minutes

Here are two exercise outlines. A first lays out background, then lists models and experiments, and finally sums up. B starts from training that first improves and then gets worse, then gives the curves, compares losses, and finally explains the difference. Choose the one that better brings out the research question, then identify any missing supporting data. Also look at two figures: one plots only the best seed, the other keeps all seeds under the same setting. For each, write one sentence on what a reader can judge from it.

Write your judgment first, then see the comparison notes

B lets each paragraph answer the question of the one before, but its title and curves must still correspond to the same experiment. A figure of only the best seed can show that run’s trajectory, but cannot be used to estimate typical performance; after keeping all seeds, you still have to state how results are aggregated and what the error means.

Further study

By the end of class, you should have a versioned draft and a review record. After class, first produce the next version from the comments, then choose one path. When you redo it with your own materials, keep the goal of restructuring the full draft and checking the numbers, rather than only swapping the nouns in the example.

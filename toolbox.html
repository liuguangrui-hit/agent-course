工具箱

这门课的暗线。每课一开始让 Agent 自己装上这一课的工具，装好后验证一遍，把用法写进项目的 AGENTS.md；之后每一课都接着用。这一页把全部工具按课列在一起，方便课后查。

装工具的任务卡都是一个样子，换掉工具名就能用：

这个项目要用 <工具>，用来 <让你能做的事>。检查这台电脑有没有，没有就装上。
装之前列出打算装什么，装在哪，要不要管理员权限，等我同意。
装完实际用一次证明它能用，再在 AGENTS.md 里补一两行：这个工具在本项目里怎么用。

第 0 课：两家 Agent

工具 Agent 因此能做的事 注意
Claude Code 读写你电脑上的文件，运行命令 一件事一个对话，一个文件夹
Codex 同上，另一家的模型 和 Claude 互相审，品味不同才看得出问题

第 1 课：能编译，能画图，能看页面

工具 Agent 因此能做的事 注意
Python 环境：uv 跑实验，从数据重画图，跑核对脚本 每个项目独立环境，不动系统 Python
LaTeX：TinyTeX 改完立刻编译，看到真实页数 轻量发行版够用，缺宏包时让它按需补
PDF 渲染：poppler 把编译后的页面转成图片，自己看排版 要求它看页面，不只看单独导出的图
AGENTS.md 每次开工自动读项目约定 只放稳定约定，加新条前先删重
Skill 一句话调出一整套做法 从一次真实的成功里提炼，不凭空写

第 2 课：出门找资料，回来存成知识库

工具 Agent 因此能做的事 注意
Ego 浏览器 用你已登录的图书馆账号打开出版社页面，下载订阅论文 你登录一次，它沿用；真人验证码留给你点
Obsidian 你和 Agent 共用一个文件夹形式的知识库，双链互相连接 知识库就是普通 Markdown 文件，Agent 直接读写
文献接口：OpenAlex，arXiv API 按关键词和引用关系批量查论文，不靠网页搜索 先查元数据定名单，再下载全文
Sub-agent 把几十篇论文分给多个干净上下文的助手并行读 每个只读自己那几篇，主对话只收结论

第 3 课：让实验在别的机器上跑

工具 Agent 因此能做的事 注意
Git 与 GitHub：gh 每次改代码留版本，结果对得上是哪一版代码跑出来的 数据和大文件不进仓库
SSH 与 Tailscale 从你的电脑登录实验室服务器，学校网络外也能连 每次 SSH 设超时，不在两台机器之间搬大文件
tmux 后台任务 实验在服务器上跑，断网关电脑也不停 启动后立刻返回，日志写进文件
监视器 Agent 盯着日志，跑完或出错时自己醒来接着干 隔几分钟看一次，不要每秒去问

第 4 课：夜里自己跑

工具 Agent 因此能做的事 注意
定时任务：Claude 桌面版，Codex 自动化 按时间表自己开工 每次开新对话，从文件里接上次的进度
无人值守调用：claude -p，codex exec 一个 Agent 用命令行把一件事交给另一家 限定可写的文件夹，产物落到文件
手机通知：ntfy 跑完或卡住时推到你手机上 只推结论和链接，不推长日志
经验榜 每轮把有效和无效的做法记下来，下一轮先读 每条带来源，旧条目会被新证据挤掉
GitHub Pages 把结果做成网页，手机上就能看 默认公开，未发表的结果放私有仓库或只放摘要

第 5 课选修：给工作台装上锁

工具 Agent 因此能做的事 注意
权限规则：settings.json 常用命令不再一次次问你，危险命令一律拒绝 先拒绝表，再允许表
沙箱 命令只能写项目文件夹，只能连你允许的网站 放手让它跑久一点之前先开
Hooks，gitleaks 改完文件自动跑检查，推送前自动查密钥，不靠它记得 检查要快，几秒内跑完
密钥管理 密码和 API Key 不进对话、不进仓库 放系统钥匙串或不提交的 .env

第 6 课选修：算账

工具 Agent 因此能做的事 注意
用量账本：ccusage 每件事花了多少 token，多少钱，多长时间，一目了然 按任务记，才比得出哪种编排划算

Toolbox

The hidden thread of this course. At the start of each session, have the agent install the tools it needs, test them, and write their use into the project’s AGENTS.md. Each later session keeps using them. This page lists all the tools by session so you can look them up afterwards.

The task cards for installing tools all follow the same pattern. Change the tool name and you can use it:

This project needs <tool> so you can <what it lets you do>. Check whether it is installed on this computer, and install it if it isn't.
Before installing, list what you plan to install, where, and whether it needs administrator permissions. Wait for my OK.
Use it once to show it works, then add a line or two to AGENTS.md explaining how to use it in this project.

Session 0: two vendors’ agents

Tool What it lets the agent do What to watch for
Claude Code Read and write files on your computer, run commands One task, one conversation, one folder
Codex The same, with another vendor’s model Have it and Claude review each other; different tastes reveal problems

Session 1: compile, draw figures, look at pages

Tool What it lets the agent do What to watch for
Python environment: uv Run experiments, redraw figures from data, run checking scripts A separate environment for each project; leave the system Python alone
LaTeX: TinyTeX Compile straight after an edit and see the actual page count A lightweight distribution is enough; have it add missing packages as needed
PDF rendering: poppler Turn compiled pages into images and check the layout itself Ask it to look at the pages, not just figures exported on their own
AGENTS.md Read project conventions automatically each time it starts Keep only stable conventions; remove duplicates before adding a rule
Skill Bring back a whole method with one line Extract it from a real success, rather than inventing it

Session 2: find material and bring it back as a knowledge base

Tool What it lets the agent do What to watch for
Ego browser Open publisher pages with your library login and download subscription papers You log in once; it reuses the session. Human verification is for you to click
Obsidian Share a folder-based knowledge base with you, with wikilinks connecting pages The knowledge base is plain Markdown; the agent reads and writes it directly
Literature APIs: OpenAlex, arXiv API Find papers in batches by keywords and citations, without web search Use metadata to settle the list first, then download the full texts
Sub-agent Split dozens of papers among assistants with fresh contexts to read in parallel Each reads only its own papers; the main conversation gets only the conclusions

Session 3: run experiments on another machine

Tool What it lets the agent do What to watch for
Git and GitHub: gh Keep a version for each code change and tie results to the code that produced them Keep data and large files out of the repository
SSH and Tailscale Log in to a lab server from your computer, even off campus Set a timeout for every SSH call; don’t move large files between machines
tmux background jobs Run experiments on the server through lost connections and shutdowns of your computer Return as soon as the job starts; write logs to files
Monitor Watch logs and wake the agent when a run finishes or fails Check every few minutes, not every second

Session 4: run overnight

Tool What it lets the agent do What to watch for
Scheduled tasks: Claude desktop, Codex automations Start work on a schedule Start a new conversation each time and pick up progress from files
Headless calls: claude -p, codex exec Hand a task from one agent to another vendor through the command line Limit the writable folder and save outputs as files
Phone notifications: ntfy Notify your phone when work finishes or gets stuck Send only the conclusion and a link, not long logs
Playbook Record what worked and what failed each round; read it before the next Give each entry a source; new evidence can displace old entries
GitHub Pages Make results into a web page you can read on your phone Public by default; put unpublished results in a private repository or publish only a summary

Session 5 elective: put locks on the workbench

Tool What it lets the agent do What to watch for
Permission rules: settings.json Run common commands without asking each time, and always reject dangerous ones Write the deny list before the allow list
Sandbox Write only inside the project folder and connect only to sites you allow Turn it on before leaving the agent to run for longer
Hooks, gitleaks Check files automatically after edits and scan for secrets before pushing, without relying on memory Keep checks fast, within a few seconds
Secret management Keep passwords and API keys out of conversations and repositories Use the system keychain or an uncommitted .env

Session 6 elective: count the cost

Tool What it lets the agent do What to watch for
Usage ledger: ccusage See each task’s tokens, cost and time at a glance Record by task so you can compare the cost of different arrangements

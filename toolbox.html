工具箱

学习目标

  1. 依据各课的研究任务确定所需的工具能力，区分课前可用性检查与课堂上的配置和实测。
  2. 以与研究任务相连的验收任务检验工具，不以安装成功或配置解析成功作为可用的依据。
  3. 维护最小化的项目工具约定，在新任务中删去无关部分。

工具安装完成后，须用实际任务检验一次。本页按课程和阶段列出所需的能力。安装、下载与登录安排在课前；复杂配置和边界判断在课堂上共同完成，并随即用于首次研究任务；课后再扩大使用范围。软件安装在本机，项目文件只保留本项目的调用方法。下一课复制约定时，先删去与新任务无关的部分。

不要提前设置长期调度、发布目标或复杂权限；课堂核对角色与完成判据后再配置。

第 0 课 课前准备

Claude Code 与 Codex 负责读取和修改文件并运行工具。桌面应用便于查看任务与产物，命令行适合脚本调用。按课前准备安装，先在同一个练习目录中完成纪要的整理与核查。

第 2 课 知识库

课前安装浏览器和 Obsidian，完成登录并取得原件；课堂上核对版本和证据，配置独立阅读的输入与输出范围。

工具 验收任务
已授权的浏览器，例如 Ego Lite 下载一篇有权限访问的全文，核对身份
Obsidian 从概念页跳回论文页，再找到原文页码

Sub-agent 在独立输入范围内写一份笔记，交回文件清单

接口用于批量查询元数据，浏览器处理需要登录的页面。接口当前的账号和频率要求以官方文档为准。浏览器能否沿用已有登录，须在自己的设备上实测。

第 3 课 实验分析

课前准备 Git、锁定依赖与可用的执行端；课堂上共同冻结预测、提交代码，并检查输出和后台任务身份。

工具 验收任务
Git 与 GitHub CLI 留下提交并从另一个目录取回同一版本
SSH 用主机别名连到目标机器，确认工作目录
Tailscale 或学校提供的网络入口 校外连接测试，沿用实验室已有方案即可
tmux 或集群调度器 断开终端以后任务继续，退出码和日志仍可读
监视器 区分运行中、成功和失败，任务结束后停止监视

第 4 课 自动化

课前检查已有入口与本地页面，完成一次零延迟的只读调用。课堂上共同设置单次唤醒并完成收工交接；课后再扩展为周期调度，通知和发布另行选择。

工具 验收任务
桌面调度或服务器调度 触发一次，确认执行机器与时区
无人值守调用 只读材料，意见存成文件，返回退出状态
经验榜 新增一条有条件、有来源的候选经验
结果页生成器 从结果文件重建页面，失败轮次也出现
通知渠道 收到一条测试通知，能定位到具体运行

GitHub Pages可以发布选定的网页，公开范围由研究者决定。未发表的问题和预测本身也可能需要保密，公开摘要应逐项选取字段。通知服务使用经过验证的认证与访问控制；频道名只用于寻址。

第 5 课 安全控制

课前下载扫描器与所需组件，并备份配置；课堂上定义角色、合并配置并实测系统边界；课后更换入口重测。

权限规则控制工具调用，沙箱限制实际进程，Hooks 在事件发生时执行检查。gitleaks用于辅助查找疑似密钥。分别做一次允许测试和拒绝测试，再换一个入口确认边界仍然成立。命令白名单不能替代进程隔离，配置解析成功也不能替代实测。

第 6 课 编排理论

课前确认标准库和数据文件可以读取；课堂上解释三组设计与分析结果；课后完成理论复算和真实任务检验。

本课新增三组评估器。它读取同一任务在无经验、匹配安慰剂和目标经验三种条件下的得分，按任务配对估计差值，再检查成本与原点版本。用量账本用于判断某项改进是否值得部署。相关公式和可运行练习见编排理论。

Toolbox

Learning outcomes

Using this page across the course, students should be able to:

  1. Distinguish setup that can be completed independently before class (installation, downloads, sign-in) from configuration and boundary judgments that depend on a defined research task.
  2. Verify each tool through a practical check on a research task rather than through installation alone.
  3. Maintain project-level tool conventions that carry forward only what the next task requires.

This page lists the capabilities required by session and by stage. Installation, downloads and sign-in take place before class. Complex configuration and boundary judgments are carried out in class and applied immediately to a first research task; their use is extended after class. A tool is considered ready only once it has been used on a real task. Software remains installed on the student’s computer, and project files record only the commands needed for that project. When conventions are carried into the next session, anything irrelevant to the new task is removed first.

Read the previous lesson's AGENTS.md and keep the tool conventions this lesson can use.
Check the capabilities listed below and report them in three groups: already usable, needs installing, needs me to log in.
State the source and install location of any new software, then carry out the installs I have agreed to.
Before class, only check that the tools work, and write actual calls and errors into preflight.md.
Do not set up long-term scheduling, publication targets or complex permissions in advance; configure them after the roles and completion criteria are checked in class.
Record reusable tool commands in this project's files, and in class use each tool on a real research task.

Lesson 0: Getting started

Claude Code and Codex read and modify files and run tools. The desktop app is suited to inspecting tasks and outputs; the command line is suited to scripted calls. Install them following Getting started, and complete the meeting-minutes task, with its independent check, in the same exercise directory.

Lesson 2: Research knowledge bases

Before class, install the browser and Obsidian, sign in and obtain the originals; in class, check versions and evidence, and configure the input and output scope for independent reading.

Tool Practical check
An authorized browser, such as Ego Lite Download one full text you have access to and check its identity
Obsidian Navigate from a concept page back to a paper page, then find the page number in the original
arXiv and OpenAlex Retrieve one record and save the query time and identifier
Sub-agent Write one note within an independent input scope and return the file list

APIs are used for bulk metadata queries; the browser handles pages that require sign-in. The APIs’ current account and rate requirements are those stated in the official documentation. Whether the browser can use existing sign-ins must be tested on the student’s own device.

Lesson 3: Experimental analysis

Before class, prepare Git, locked dependencies and an available execution environment; in class, freeze the prediction and commit code, and check the outputs and the details of background jobs.

Tool Practical check
Git and GitHub CLI Create a commit and fetch the same version from another directory
SSH Connect to the target machine with a host alias and confirm the working directory
Tailscale or the network access provided by the university Test a connection from off campus; the laboratory’s existing setup may be reused
tmux or a cluster scheduler The job continues after the terminal disconnects, and the exit code and log remain readable
Monitor Distinguishes running, success and failure, and stops monitoring when the job ends

Lesson 4: Research automation

Before class, check the existing entry points and the local page, and complete one zero-delay read-only call. In class, configure a single wake-up and hand the wrap-up to a new session; after class, extend this to periodic scheduling, and decide on notifications and publication separately.

Tool Practical check
Desktop scheduling or server scheduling Trigger once and confirm the executing machine and time zone
Unattended call Reads material only, saves comments as a file and returns an exit status
Playbook Add one candidate playbook entry with conditions and a source
Results page generator Rebuild the page from result files, with failed rounds also shown
Notification channel Receive one test notification that points to a specific run

GitHub Pages can publish selected web pages, with the public scope decided by the user. Unpublished questions and predictions may themselves need to remain confidential, so the public summary selects fields individually. Notification services use verified authentication and access control; the channel name only identifies the destination.

Lesson 5: Safety controls

Before class, download the scanner and required components and back up the configuration; in class, define roles, merge configuration and test the system boundaries; after class, retest through another entry point.

Permission rules control tool calls, the sandbox limits actual processes, and Hooks run checks when events occur. gitleaks helps to detect suspected secrets. Carry out one allowed test and one denied test, then confirm through another entry point that the boundary still holds. A command allowlist cannot replace process isolation, and a configuration that parses cannot replace actual testing.

Lesson 6: Orchestration theory

Before class, confirm that the standard library and data files can be read; in class, interpret the three groups and the analysis results; after class, check the theoretical calculations and test the method on real tasks.

This session adds a three-group evaluator. It reads the scores of the same task with no experience, a matched placebo and the target experience, estimates the differences paired by task, and then checks cost and the origin version. The usage ledger supports the decision on whether an improvement is worth deploying. The formulas and runnable exercises are in Orchestration theory.

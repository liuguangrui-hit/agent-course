第 0 课 课前准备

Claude Code 与 Codex 负责读文件、改文件并运行工具。桌面应用适合看任务与产物，命令行适合脚本调用。按课前准备安装，先在同一个练习目录完成写纪要和查纪要。

第 1 课 写作绘图

工具 课前检查 课上共同做

LaTeX 发行版与构建器 原稿能编译 检查重讲稿的图文与引用

第 2 课 知识库

课前装浏览器和 Obsidian、登录并取得原件；课上核对版本和证据，配置独立阅读的输入输出范围。

工具 验收任务
已授权的浏览器，例如 Ego Lite 下载一篇有权限访问的全文，核对身份
Obsidian 从概念页跳回论文页，再找到原文页码
arXiv 与 OpenAlex 查到一条记录，保存查询时间与标识
Sub-agent 在独立输入范围内写一份笔记，交回文件清单

接口用来批量查元数据，浏览器处理需要登录的页面。接口当前的账号和频率要求以官方文档为准。浏览器能否使用已有登录，要在自己的设备上实测。

第 3 课 实验分析

课前准备 Git、锁定依赖与可用执行端；课上一起冻结预测与提交代码，检查输出和后台身份。

工具 验收任务
Git 与 GitHub CLI 留下提交并从另一个目录取回同一版本
SSH 用主机别名连到目标机器，确认工作目录
Tailscale 或学校提供的网络入口 校外连接测试，沿用实验室已有方案即可
tmux 或集群调度器 断开终端以后任务继续，退出码和日志仍可读
监视器 区分运行中、成功和失败，任务结束后停止监视

第 4 课 自动化

课前检查已有入口与本地页，完成一次零延迟只读调用。课上共同设置单次唤醒并完成收工交接；课后再扩成周期调度，另选通知和发布。

工具 验收任务
桌面调度或服务器调度 触发一次，确认执行机器与时区
无人值守调用 只读材料，意见存成文件，返回退出状态
经验榜 新增一条有条件、有来源的候选经验
结果页生成器 从结果文件重建页面，失败轮次也出现
通知渠道 收到一条测试通知，能定位到具体运行

GitHub Pages可发布选定网页，公开范围由你决定。未发表的问题和预测本身也可能需要保密，公开摘要逐项选取字段。通知服务用已验证的认证与访问控制；频道名只负责寻址。

第 5 课 安全控制

课前下载扫描器与所需组件并备份配置；课上定义角色并合并配置，实测系统边界；课后换入口重测。

权限规则控制工具调用，沙箱限制实际进程，Hooks 在事件发生时执行检查。gitleaks用于辅助查找疑似密钥。分别做一次允许测试和拒绝测试，再换一个入口确认边界仍在。命令白名单无法替代进程隔离，配置被解析也无法替代实测。

第 6 课 编排理论

课前确认标准库和数据文件可读；课上解释三组与分析结果；课后做理论复算和真实任务检验。

本课新增三组评估器。它读取同一任务在无经验、匹配安慰剂和目标经验下的得分，按任务配对估计差值，再检查成本与原点版本。用量账本帮助判断某种改进是否值得部署。相关公式和可运行练习见编排理论。

Toolbox

After installing a tool, try it on a real task. This page lists the capabilities needed by lesson and stage. Installs, downloads and logins happen before class. Complex configuration and boundary judgments are done together in class and used straight away on a first research task; you extend their use after class. The software stays on your computer, and the project files record only the commands needed for this project. When you copy the conventions into the next lesson, first delete what is irrelevant to the new task.

Read the previous lesson's AGENTS.md and keep the tool conventions this lesson can use.
Check the capabilities listed below and report them in three groups: already usable, needs installing, needs me to log in.
State the source and install location of any new software, then carry out the installs I have agreed to.
Before class, only check that the tools work, and write actual calls and errors into preflight.md.
Do not set up long-term scheduling, publication targets or complex permissions in advance; configure them after the roles and completion criteria are checked in class.
Record reusable tool commands in this project's files, and in class use each tool on a real research task.

Lesson 0: Getting started

Claude Code and Codex read files, change files and run tools. The desktop app is good for viewing tasks and outputs; the command line is good for scripted calls. Install them following Getting started, and first write and check meeting minutes in the same exercise directory.

Lesson 2: Research knowledge bases

Before class, install the browser and Obsidian, log in and get the originals; in class, check versions and evidence, and configure the input and output scope for independent reading.

Tool Practical check
An authorized browser, such as Ego Lite Download one full text you have access to and check its identity
Obsidian Jump from a concept page back to a paper page, then find the page number in the original
arXiv and OpenAlex Find one record and save the query time and identifier
Sub-agent Write one note within an independent input scope and hand back the file list

APIs are for querying metadata in bulk; the browser handles pages that need login. The APIs’ current account and rate requirements are as stated in the official docs. Whether the browser can use existing logins must be tested on your own device.

Lesson 3: Experimental analysis

Before class, prepare Git, locked dependencies and an available execution environment; in class, freeze the prediction and commit code together, and check the outputs and background job details.

Tool Practical check
Git and GitHub CLI Create a commit and fetch the same version from another directory
SSH Connect to the target machine with a host alias and confirm the working directory
Tailscale or the network entry your university provides Test a connection from off campus; reusing your lab’s existing setup is fine
tmux or a cluster scheduler The job continues after the terminal disconnects, and the exit code and log can still be read
Monitor Tells running, success and failure apart, and stops monitoring when the job ends

Lesson 4: Research automation

Before class, check the existing entry points and local page, and complete one zero-delay read-only call. In class, set up a single wake-up together and hand the wrap-up to a new session; after class, extend it to periodic scheduling, and choose notifications and publishing separately.

Tool Practical check
Desktop scheduling or server scheduling Trigger once and confirm the executing machine and time zone
Unattended call Reads material only, saves comments as a file, returns an exit status
Playbook Add one candidate playbook entry with conditions and a source
Results page generator Rebuild the page from result files, with failed rounds shown too
Notification channel Receive one test notification that points to a specific run

GitHub Pages can publish selected web pages, and you decide the public scope. Unpublished questions and predictions may themselves need to stay confidential, so the public summary selects fields one by one. Notification services use verified authentication and access control; the channel name only identifies the destination.

Lesson 5: Safety controls

Before class, download the scanner and needed components and back up your configuration; in class, define roles, merge configuration and test the system boundaries; after class, retest through another entry point.

Permission rules control tool calls, the sandbox limits actual processes, and Hooks run checks when events happen. gitleaks helps find suspected secrets. Do one allowed test and one denied test, then confirm through another entry point that the boundary still holds. A command allowlist cannot replace process isolation, and a configuration that parses cannot replace actual testing.

Lesson 6: Orchestration theory

Before class, confirm that the standard library and data files can be read; in class, interpret the three groups and the analysis results; after class, check the theoretical calculations and test the method on real tasks.

This lesson adds a three-group evaluator. It reads the scores of the same task with no experience, a matched placebo and the target experience, estimates the differences paired by task, then checks cost and the origin version. The usage ledger helps you decide whether an improvement is worth deploying. The formulas and runnable exercises are in Orchestration theory.

1.6 引用与投稿

课后深入，约 30 分钟。

论文写好以后，还有一段很容易被轻视的路：引用是否真实，格式是否合规，匿名是否干净，PDF 能否被投稿系统接受。这些检查枯燥，正适合交给 Agent，前提是让它用工具查，而不是凭记忆答。

每一条引用都要核实

Agent 写论文时会补引用，补出来的引用看起来非常像真的：作者是这个领域的人，题目像他会写的，年份和会议也合理，但这篇论文不存在。也有半真半假的：论文存在，年份或者会议写错，或者引的是 arXiv 版而正式版早已发表。

规则只有一条：参考文献里的每一条，都要用外部数据源对上。

写 code/verify_refs.py：读取论文的参考文献，对每一条用题目到 Crossref 和 arXiv 的公开接口查询，
比对作者，年份和发表处。输出一张表，分完全对上，部分不符和查不到三类，部分不符的指出是哪一项。
查不到的不要删，列出来给我看。

BibTeX 条目也不要让 Agent 凭记忆写。从 DBLP 或出版社页面导出，或者让 Agent 按 DOI 去取。练习论文的七条引用都是真实的，可以先拿它试一遍脚本。

模板和篇幅

用刊会官方的最新模板，不要拿去年的版本或者别人改过的版本。页数超了，删内容，不压格式：调小字号，改页边距，大量使用负的 \vspace，都可能直接被拒稿。

删什么，回到 1.1 的原则：主次分明，敢于取舍。次要的实验移到附录或者直接不写，重复的限定只留一处，附录里不再复述正文已经讲过的设计。

论文超出页数限制 0.6 页。不要改格式和字号。
列出可以删减的内容，按对主要结论的重要性从低到高排，每项估计能省多少行。先给我看，不要动手。

匿名

双盲投稿要检查的不只是作者栏：

  • 致谢和基金号；
  • 正文里的 our previous work，以及第一人称引用自己的论文；
  • 代码和数据的链接，GitHub 用户名会暴露身份；
  • PDF 的元数据，作者字段常常带着你的名字；
  • 图里的水印和文件路径。
按双盲要求检查 versions/v2/main.pdf：正文，脚注，图中文字，链接和 PDF 元数据里有没有能识别作者的信息。
用工具读取 PDF 元数据，不要只看正文。列出发现的每一处。

编译和 PDF 检查

投稿前让 Agent 把这些都跑一遍：

  • 编译日志里的警告：未定义的引用，未定义的标签，超出版心的行。
  • PDF 里的字体是否全部嵌入，有没有 Type 3 字体。
  • 每一页渲染成图片，逐页看一遍：图和图注是否在同一页，表格有没有出界，第一页的版式是否合乎这个刊会的惯例。
完整编译 versions/v2/main.tex，汇总日志里的所有警告并逐条修复。
用 pdffonts 一类工具检查字体嵌入，确认没有 Type 3 字体。
把每一页渲染成图片逐页检查版面，列出问题。修复超出版心的行时不要缩小字号。

关于第一页：多数会议论文第一页没有图。要放的话照刊会的惯例来，双栏的刊会通常放在右栏，用单栏宽的图，不在标题下放通栏大图。拿不准时，翻几篇这个刊会去年的论文看。

练习

用 verify_refs.py 的思路检查练习论文的参考文献。然后故意把其中一条的年份改错，再加一条编造的引用，看脚本能否把两处都找出来。

参考结果

年份改错的那条会显示为部分不符，指出年份；编造的那条查不到。注意 Crossref 按题目检索会返回最相近的结果，相近不等于相同，脚本要比对题目的相似度，低于阈值就算查不到，否则编造的引用会被一篇题目相近的真论文顶替。

最容易出错的地方

编造的引用。 作者，题目，会议都像真的，论文不存在。每一条都用外部数据源核实，查不到的交给人看。

引了 arXiv 版。 论文早已正式发表，参考文献还写着 arXiv 预印本。核实时同时查正式发表版本。

用缩格式凑篇幅。 Agent 修复超页的第一反应往往是缩字号和间距。明确禁止，要求删内容。

元数据泄露身份。 正文全部匿名了，PDF 属性里作者一栏还是你的名字。用工具检查元数据。

延伸阅读

  • Crossref REST API：按题目或 DOI 查询文献元数据。
  • arXiv API：查询预印本。
  • DBLP：计算机领域论文的权威书目，可导出 BibTeX。

1.6 References and submission

Self-study, about 30 minutes.

Once the paper is written, there is still a stretch of road that is easy to underrate: are the references real, does the format comply, is the anonymization clean, will the submission system accept the PDF. These checks are tedious, which makes them a good fit for an agent, as long as it checks with tools and never answers from memory.

Verify every reference

Agents add references while writing a paper, and the references they add look very real: the authors work in the field, the title sounds like something they would write, the year and venue are plausible, and the paper does not exist. Some are half true: the paper exists, but the year or venue is wrong, or the citation points to the arXiv version long after the published version came out.

There is one rule: match every entry in the bibliography against an external data source.

Write code/verify_refs.py: read the paper's references and look up each one by title through the public Crossref and arXiv APIs,
comparing authors, year and venue. Output a table sorted into three groups: full match, partial mismatch and not found. For partial mismatches, name the field that differs.
Don't delete the ones not found. List them for me to see.

Don’t let the agent write BibTeX entries from memory either. Export them from DBLP or the publisher’s page, or have the agent fetch them by DOI. All seven references in the exercise paper are real, so you can try the script on it first.

Template and length

Use the venue’s latest official template, never last year’s or a copy someone else has modified. If you are over the page limit, cut content and leave the format alone: a smaller font, changed margins or heavy use of negative \vspace can each get the paper rejected outright.

For what to cut, go back to the principle from 1.1: make the main point stand out, and be willing to let things go. Move minor experiments to the appendix or drop them, keep a repeated caveat in one place only, and don’t restate in the appendix a design the main text already explained.

The paper is 0.6 pages over the page limit. Don't change the format or font size.
List what could be cut, ordered from least to most important to the main conclusion, with an estimate of how many lines each saves. Show me first and don't change anything.

Anonymization

A double-blind submission needs checks well beyond the author block:

  • acknowledgments and grant numbers;
  • “our previous work” in the text, and citing your own papers in the first person;
  • links to code and data, where a GitHub username reveals who you are;
  • PDF metadata, whose author field often carries your name;
  • watermarks and file paths in figures.
Check versions/v2/main.pdf against double-blind rules: is there anything in the text, footnotes, figure text, links or PDF metadata that could identify the authors?
Read the PDF metadata with a tool; don't look only at the text. List every instance you find.

Compilation and PDF checks

Before submitting, have the agent run through all of these:

  • Warnings in the compile log: undefined citations, undefined labels, lines running past the text block.
  • Whether every font in the PDF is embedded, and whether any are Type 3.
  • Every page rendered as an image and looked at one by one: is each figure on the same page as its caption, does any table overflow, does the first page follow the venue’s conventions.
Do a full compile of versions/v2/main.tex, collect every warning in the log, and fix them one by one.
Check font embedding with a tool such as pdffonts and confirm there are no Type 3 fonts.
Render every page as an image, check the layout page by page, and list the problems. When fixing lines that run past the text block, don't shrink the font.

On the first page: most conference papers have no figure on page one. If you want one, follow the venue’s convention. Two-column venues usually put it in the right column at single-column width, with no full-width figure under the title. When unsure, look through a few of the venue’s papers from last year.

Exercise

Check the exercise paper’s references using the approach of verify_refs.py. Then deliberately change the year in one entry and add a made-up reference, and see whether the script catches both.

Expected result

The entry with the wrong year shows up as a partial mismatch, with the year named; the made-up one comes back as not found. Note that a Crossref title search returns the closest match, and close is different from identical. The script has to compare title similarity and count anything below a threshold as not found. Otherwise a real paper with a similar title stands in for the made-up reference.

Where agents go wrong most

Made-up references. The authors, title and venue all look real, and the paper does not exist. Verify every entry against an external data source, and hand the ones not found to a person.

Citing the arXiv version. The paper was formally published long ago, and the bibliography still lists the arXiv preprint. When verifying, look up the published version as well.

Shrinking the format to fit the page limit. An agent’s first move when a paper runs over is usually to shrink the font and spacing. Forbid it explicitly and require cuts to the content.

Metadata gives you away. The text is fully anonymized, yet the author field in the PDF properties still holds your name. Check the metadata with a tool.

Further reading

  • Crossref REST API: look up bibliographic metadata by title or DOI.
  • arXiv API: look up preprints.
  • DBLP: the authoritative bibliography for computer science papers, with BibTeX export.

1.6 文献引用与刊会投稿

课后深入，约 30 分钟。

引用能查到，还要查它是否支持正文。投稿 PDF 编译成功，还要查它是否符合目标刊会的交付要求。这一节介绍成稿后的两类检查。

文献引用

对每条参考文献保存 DOI 或 arXiv 标识，核对标题、作者与发表信息，再确认正文使用的是哪个版本。正式版与预印本的图表可能不同，笔记页码要跟着版本走。

读取参考文献，逐条到出版社或书目接口核对。
输出 exact，mismatch，unresolved 三类，保留查询 URL 和时间。
题目检索返回的近似结果只作候选，进一步用作者和标识确认。
为正文实际引用的版本保留记录。

Crossref、DBLP 和 arXiv各有覆盖范围。某个接口没有记录时，继续核对出版方与作者公开页面，结论仍未确定就保留为待核。

再查引用关系

从正文抽出依赖引用的主张，写成主张与出处表。按原文找到支持段落，记录证据是实验结果、理论推导还是作者讨论。综述转引的发现，追到原研究再判断。

对正文每个带引用的结论，给出原文支持位置和证据类型。
检查是否把作者的推测写成已证实结果，是否把一种设置的结果换成另一种设置。
缺支撑时先找直接证据，找不到就列出需要补的原文证据或实验。

身份核查用结构化元数据，含义核查用全文。两者的通过状态分开保存。

刊会投稿

确定目标届次，保存官方作者指南和模板入口，按当前要求检查页数、匿名与附件。需要删篇幅时，按叙事作用决定去留：删重复解释，移次要实验，保留核心证据。

图在第一页的位置、字体要求和附录安排，都以目标模板及同类正式论文为准。把别处的惯例搬过来，容易让 Agent 修错方向。

检查实际 PDF

完整构建本版 PDF，汇总未定义引用和超出版心等日志。
读取字体与元数据，按目标刊会要求检查。
逐页看渲染结果，检查图注位置、表格边界和链接。
如需双盲，检查作者栏和致谢，再查链接、图内路径与 PDF 元数据。

代码仓库和补充材料也有身份信息。需要匿名发布时，先把拟公开文件打包，在本地核查完整内容，再由用户确认提交。

练习

复制练习稿，在其中一条引用里改错年份，另把一条真实引用挪到它无法支持的句子后。分别运行身份与含义核查，看看两处问题各由哪道检查发现。

参考判断

错误年份应在元数据核对时出现。第二处文献身份仍然真实，要通过原文支持位置发现。两道检查分开，才能解释为什么一条引用通过了其中一道却仍不能使用。

常见错误与处理方法

题目相似就判为同一篇。 进一步对作者、标识和版本，保留候选与最终匹配的区别。

为满足页数限制调小模板。 把删减建议按叙事作用排序，修正文内容，保持模板要求。

匿名只查正文。 同时检查 PDF 属性、图内文字与附件链接，按目标要求交付。

1.6 Citations and submission

After-class deep dive, about 30 minutes.

Finding a reference does not establish that it supports the text. A PDF that compiles may still fail to meet the target venue’s submission requirements. This section covers both checks once the draft is complete.

Verify reference details

For every reference, keep its DOI or arXiv identifier, check title, authors and publication details, then confirm which version the text uses. Figures and tables may differ between the published version and the preprint, and page numbers in notes follow the version.

Read the references and check each one against the publisher or a bibliographic API.
Output three classes: exact, mismatch, unresolved, keeping the query URL and time.
Approximate matches from a title search are only candidates; confirm further with authors and identifiers.
Keep a record of the version actually cited in the text.

Crossref, DBLP and arXiv each cover different ground. When one API has no record, keep checking the publisher’s and authors’ public pages; if the result is still uncertain, keep it as pending.

Then check what each citation supports

Pull out the claims in the text that rely on citations and make a table of claims and sources. Find the supporting passage in the original and record whether the evidence is an experimental result, a theoretical derivation or the authors’ discussion. For findings cited through a review, trace them to the original study before judging.

For every cited conclusion in the text, give the supporting location in the original and the type of evidence.
Check whether an author's speculation has been written as an established result, and whether a result from one setting has been swapped for another setting.
Where support is missing, first look for direct evidence; if none is found, list the evidence from the original or the experiment that needs to be added.

Use structured metadata to check reference details and full text to check what a citation supports. Record the two outcomes separately.

Check the venue’s submission requirements

Identify the target conference year or journal issue and save the official author guidelines and template links. Check page count, anonymity and supplementary files against the current requirements. When cutting length, consider each passage’s role in the argument: cut repeated explanations, move secondary experiments, keep the core evidence.

The position of figures on the first page, font requirements and appendix arrangements all follow the target template and published papers of the same type. Carrying over conventions from elsewhere easily leads the agent to fix things in the wrong direction.

Check the actual PDF

Build this version's PDF in full and collect log entries such as undefined references and content outside the text block.
Read the fonts and metadata and check them against the target venue's requirements.
Look at the rendered result page by page, checking caption placement, table borders and links.
If double-blind review is required, check the author block, acknowledgments, links, paths inside figures and PDF metadata.

Code repositories and supplementary materials also carry identity information. When anonymous release is needed, first package the files to be made public, check their full content locally, and then have the user confirm the submission.

Exercise

Copy the exercise draft, change the year in one citation to a wrong one, and move another real citation to a sentence it cannot support. Run the identity check and the meaning check separately and see which check finds each problem.

Suggested analysis

The wrong year should show up in the metadata check. In the second case the reference is still genuine, so detecting the error requires checking the purported supporting passage in the source. Only with the two checks separate can you explain why a citation passed one of them and still cannot be used.

Common mistakes and how to fix them

Judging two papers the same because their titles are similar. Go further and match authors, identifiers and versions, keeping candidates distinct from the final match.

Shrinking the template to get under the page limit. Rank cuts by their role in the argument, revise the content, and keep the template’s requirements.

Checking anonymity only in the body text. Also check PDF properties, text inside figures and attachment links, and deliver as the target requires.

3 实验分析

把一个文献问题改写成能区分两种解释的实验。先保存预测和分析计划，再让 Agent 执行，最后用配对结果更新判断。每份结果都能找到执行代码与数据版本信息。

课前完成准备，课上 60 分钟，课后先复习再选做深入。

课前预备 · 课上一小时 · 课后复习与拔高

验证集也带噪声，早停是不是就失灵了？配套实验原先预测它会让 CE 晚停、准确率下降，结果四条预测错了三条。错误留下了一个更好的问题：验证标签中的哪些信息足以帮助选模型？

这一课从预览结果出发，先判断哪项实验能进一步检验解释。课堂只跑一条短路径，完整种子和扩展对照课后完成。

确认 data/ 和 preview/ 能读取，创建 logs/，只检查预览代码的 --help，不启动正式训练。
课堂默认用本机；已有服务器的，另核对 SSH 别名，实际机器，工作目录和后台任务入口。

把可用命令、执行端与未解决项写到 preflight.md，把稳定入口写入 AGENTS.md。

课上一小时

先看一次猜错的预测，5 分钟

先核对 preflight.md 的执行端与环境状态，随后看一次已经完成的预测检验。

预览中，四成标签噪声下 CE 的带噪验证早停准确率是 93.25%，干净验证早停是 92.26%，不早停是 68.37%。五个种子配对后的带噪减干净差为 0.99 个百分点，95% 区间为负 0.34 到 2.32 个百分点。

这些数回答了当前比较。它们还留下两种解释：带噪标签仍保留有用的排序信息，或只要提前停止就已经能保住大部分表现。增加随机停止时点和随机验证标签等对照，才能往下判断。

明确判别标准与实验单位，10 分钟

一个问题配两种解释，各自给出可测预测。选主要比较后，固定数据切分和分析方式。写清哪项结果支持哪种解释，无法区分时补什么。

同一个种子应尽量共享数据划分、标签翻转和初始化，让比较关注干预。实验单位是一次独立训练，重复记录同一条训练曲线的多个轮次，不能当成增加种子数。

代码写完以后先做冒烟测试，检查输出结构和数值，再提交正式版本。预测、代码和结果分别留下版本，先后关系才完整。

练习一，写判别计划，10 分钟

读 questions.md 和 preview/ 中的真实结果。
围绕带噪验证集为什么有效，写两个竞争解释。
先选一个最小对照，固定主要指标与比较方向，写出有实际意义的效应大小。
把种子，数据划分，早停规则和分析方法写入 prediction.md，再提交。
说明什么结果能区分两种解释，什么结果仍需继续实验。

练习二，先查执行，再扩大运行，20 分钟

先核查预览的提交字段与审查记录，再为本次运行建立真实提交和独立审查记录。
根据计划改实验代码，加入 --seeds、--epochs 和输出目录参数。
每次运行保存代码提交和数据哈希，同时记录参数、环境与随机种子。
先做单种子短运行，核对预期行数和有限值，并确认验证集与测试集分离，结果写 smoke/。
通过后提交正式代码，把完整任务的后台命令和停止方法准备好。课堂用短任务检验后台入口，正式任务课后提交。返回任务标识、日志与完成检查入口。

正式训练中的早停使用验证交叉熵，耐心值 8，并恢复最好一轮权重。沿用预览时先核对这一规则；第 2 课问题页还展示了按验证准确率选择的另一种设计，两者应分别登记。

课堂可以在现有实现上做短运行，再用完整预览练分析。完整运行和新对照都放进课后计划，短运行的数字不能填进正式结论。

练习三，读区间，核管线，再交审，10 分钟

分析演练用 preview/ 的五个种子，重算带噪减干净的配对差、均值与区间，写到 smoke/analysis-rehearsal.md。
注明演练沿用的旧比较，只回答带噪与干净验证的差异，不拿它回答本次新增对照。
核对新对照两臂已有的同种子短运行，检查配对键与输出字段，只验证分析管线。
本轮 prediction.md 保持冻结；正式 result.md 等课后完整运行再写。
另一家 Agent 只读演练文件、冒烟记录和 prediction.md，检查数据归属与计划是否可检验，意见及主张检查写到 smoke/review.md。

预测命中只是一次检验结果。研究理解是否变好，还要看它能否继续预测新条件。猜错以后，回写知识库中的解释与下一问，保留当时的预测原件。

检查与工作台小结，5 分钟

常见错误与处理方法

预测对了，就说机制得证。 写出竞争解释，补能让两种解释产生不同预测的对照。

测试集参与选轮次。 选择规则只读取验证信息。测试指标用于最终报告，相关代码入口分开核查。

任务消失就算跑完。 同时检查退出码、预期产物和内容完整性，失败也留下状态。

不显著就写一样好。 报配对差及区间。要主张等价，先定等价界，再设计相应检验。

工作台小结

结果现在有完整的执行记录：提交与数据对应，后台任务有日志与退出状态，结论有事前计划和独立核查。无论在哪台机器上跑，下一位接手者都能找到同一项比较。

课后复习与拔高

先复盘，15 分钟

不看课堂记录，写出两种竞争解释，各写出一个会让自己改判的结果。再核对 prediction.md 和运行身份，说明主要指标、实验单位与停止规则。把计划和实际执行的偏差写到 review-after-class.md，预测原件保留。

正反例辨析，20 分钟

以下数字仅供辨析。甲报告配对差为 0.3 个百分点，95% 区间为负 1.2 到 1.8，因此两种做法等价。乙报告同一组数，指出区间仍含有预先关心的差异，提出按事前等价界增加有判别力的实验。判断哪一句得到了当前结果支持，再写出要支持等价所需的界和设计。另找出把同一种子的五个轮次当作五次独立实验会改变哪一个分母。

先写判据，再看对照思路

当前区间只说明这批数据对差值的约束，尚不能推出等价。等价要先给有实际含义的界，再看相应检验与区间是否满足它。轮次共享同一次训练，不能替代独立种子。把它们当作独立重复会虚增区间公式的 n 和自由度，使标准误被人为缩小；需要更多支持时增加独立重复和有效对照。

沿课堂往深处做

先补完课堂冒烟与计划审阅，再按冻结计划完成种子和对照。完整结果到齐后，按相同种子配对，写正式 result.md 回答主要问题，再交另一家核查到 review.md。完整训练提交后台后，先做推导与分析练习，任务结束再汇总，不把训练等待算作学习操作。

3 Experimental analysis

Turn a question from the literature into an experiment that can distinguish two explanations. Save the prediction and analysis plan first, then let the agent run it, and finally update your judgment with paired results. Every result can be traced to the exact code and data used.

Prepare before class, spend 60 minutes in class, then review and choose an optional extension.

Before class · In class · After class: review and extension

If the validation set is noisy too, does early stopping stop working? The companion experiment originally predicted that it would make CE stop later and lose accuracy, and three of the four predictions were wrong. The failed predictions raised a better question: which information in the validation labels is enough to help choose a model?

This lesson starts from the preview results and asks which experiment would help distinguish the explanations. In class you carry out a short run; the full set of seeds and the extended controls are done after class.

In class

A prediction that turned out wrong, 5 minutes

First check the executor and environment status in preflight.md, then look at a prediction test that has already been completed.

In the preview, with 40% label noise, CE’s accuracy with early stopping on noisy validation is 93.25%, with early stopping on clean validation 92.26%, and without early stopping 68.37%. Paired over five seeds, noisy minus clean is 0.99 percentage points, with a 95% interval from minus 0.34 to 2.32 percentage points.

These numbers answer the current comparison. They still leave two explanations: noisy labels keep useful ranking information, or simply stopping early is already enough to keep most of the performance. Only adding controls such as a random stopping point and random validation labels lets you judge further.

Define the decision criteria before running the experiment, 10 minutes

One question comes with two explanations, each giving a measurable prediction. Once you choose the main comparison, fix the data split and the analysis. State which result supports which explanation, and what to add if they cannot be told apart.

Runs with the same seed should share data splits, label flips and initialization wherever possible, so the comparison focuses on the intervention. The experimental unit is one independent training run; recording many epochs of the same training curve does not count as adding seeds.

After writing the code, run a smoke test first, check the output structure and values, then commit the version for full execution. The prediction, the code and the results each keep their own version, so you can show what came first.

Exercise 1: plan an experiment to distinguish explanations, 10 minutes

Read questions.md and the real results in preview/.
Write two competing explanations for why a noisy validation set works.
First choose one minimal control, fix the main metric and the direction of comparison, and write down an effect size that matters in practice.
Write the seeds, data split, early-stopping rule and analysis method into prediction.md, then commit it.
State which result would separate the two explanations, and which result would still need further experiments.

Exercise 2: check the execution first, then scale up the run, 20 minutes

First check the commit fields and review record of the preview, then create a real commit and an independent review record for this run.
Change the experiment code according to the plan, adding the --seeds and --epochs parameters and an output directory parameter.
Each run saves the code commit, data hash, parameters, environment and random seed.
First do a short single-seed run and check the expected number of rows, finite values, and that validation and test are separate. Write results to smoke/.
Once it passes, commit the code for the full run and prepare the background command for the full job and the way to stop it. In class, use a short job to test the background entry; the full job is submitted after class. Return the job identifier, the log and the entry for checking completion.

Early stopping in full training uses validation cross-entropy, with patience 8, and restores the weights of the best epoch. When reusing the preview, check this rule first; the Lesson 2 question page also shows another design that selects by validation accuracy, and the two should be registered separately.

In class you can do short runs on the existing implementation, then practice the analysis with the full preview. The full run and the new controls both go into the after-class plan, and numbers from short runs do not belong in the final conclusions.

Exercise 3: read the interval, check the pipeline, then hand over for review, 10 minutes

For the analysis rehearsal, use the five seeds in preview/ to recompute the paired noisy-minus-clean difference, its mean and interval, and write them to smoke/analysis-rehearsal.md.
Note that the rehearsal reuses the old comparison and answers only the difference between noisy and clean validation; it is not used to answer this round's new control.
Check the pairing keys and output fields in the existing matched-seed short runs of both arms of the new control. This verifies only the analysis pipeline.
Keep this round's prediction.md frozen; the final result.md is written after the full after-class run.
The other vendor's agent reads only the rehearsal file, the smoke record and prediction.md, checks where the data belong and whether the plan can be tested, and writes its comments and a claim check to smoke/review.md.

A correct prediction is only one test result. An improved explanation should also make useful predictions under new conditions. After a wrong prediction, write the explanation and the next question back into the knowledge base, and keep the original prediction.

Check and workbench summary, 5 minutes

Common mistakes and how to fix them

Saying the mechanism is proven because the prediction was right. Write out the competing explanation and add the control under which the two explanations predict different things.

The test set takes part in choosing the epoch. The selection rule reads only validation information. Test metrics are for the final report, and the code paths involved are checked separately.

The job disappeared, so it must have finished. Check the exit code, the expected products and their completeness together, and leave a status for failures too.

Writing “equally good” because a difference is not significant. Report the paired difference and its interval. To claim equivalence, first set an equivalence margin, then design the matching test.

Workbench summary

Results now have traceable run records: each identifies the code commit and data, background jobs have logs and exit statuses, and conclusions refer to a plan recorded in advance and an independent check. Whichever machine it runs on, the next person to take over can find the same comparison.

After class: review and extension

Review first, 15 minutes

Without looking at the class record, write the two competing explanations, and for each sketch one result that would make you change your judgment. Then check prediction.md and the run identity, and state the main metric, the experimental unit and the stopping rule. Write the deviations between the plan and what was actually run into review-after-class.md, keeping the original prediction.

Compare the examples, 20 minutes

The numbers below are for discussion only. A reports a paired difference of 0.3 percentage points with a 95% interval from minus 1.2 to 1.8, and so concludes that the two approaches are equivalent. B reports the same numbers, points out that the interval still contains the difference of interest set in advance, and proposes adding a more discriminating experiment based on an equivalence margin set in advance. Judge which statement the current result supports, then write the margin and design needed to support equivalence. Also find which denominator changes if the five epochs of one seed are treated as five independent experiments.

Write your criteria first, then see the comparison notes

The current interval only shows how this batch of data constrains the difference; it cannot yet establish equivalence. Equivalence first needs a margin with practical meaning, then a check of whether the matching test and interval satisfy it. Epochs share one training run and cannot replace independent seeds. Treating them as independent replications inflates the n and degrees of freedom in the interval formula, shrinking the standard error artificially; when you need more support, add independent replications and effective controls.

Further study

First finish the class smoke test and plan review, then complete the seeds and controls according to the frozen plan. Once the full results are in, pair them by seed, write the final result.md to answer the main question, then have the other vendor check it in review.md. After submitting full training to the background, do the derivation and analysis exercises first, and aggregate once the job finishes; training wait time is separate from time spent on the exercise.

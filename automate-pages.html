4.3 结果页

课后深入，约 25 分钟。

循环每晚都在产出，你不可能每天早上打开文件夹一个个文件看。结果页把它们汇成一张网页，手机上就能看；通知只推一句结论和这个网页的链接。

从结果文件生成，不手写

结果页由一个脚本从结果文件生成，每轮收工时重新生成一次：

写 code/make_page.py：读 runs/ 下每一轮的 prediction.md，results/，result.md 和 review.md，生成两份网页。
site/ 是公开摘要：顶上一行汇总轮数和预测命中率；下面每轮一行，列出问题，预测，对错，以及审查是否通过；页尾是经验榜的前五条。
internal/ 是内部版：在摘要之外，点进每一轮能看到完整数字，图和结果说明。
只用 HTML 和一个 CSS 文件，不用外部框架。

为什么不让 Agent 每轮手动改网页：手动改会漏，会把上一轮的数字改错，几轮之后网页和结果文件对不上。脚本生成，网页上的每个数字都来自文件，和第 1 课数字从数据来是同一个道理。

发布到 GitHub Pages

GitHub Pages 把一个仓库里的网页免费发布成网站。收工的最后一步：

运行 code/make_page.py，只把 site/ 复制到 lab-results 仓库，提交并推送。用 gh 查这个仓库的 Pages 部署状态，成功后再打开网址确认更新了。

免费账号只能从公开仓库发布网页，发布出来的网站也是公开的。所以公开摘要放在一个单独的公开仓库里，内部版和代码，数据一起留在私有仓库，在本机打开。

放什么，不放什么

公开的网页任何人都能看到，搜索引擎也可能收录。

放 不放
问题，预测，对错 还没发表的完整数字和图
汇总的命中率 代码和数据
经验榜 服务器地址，账号，任何密钥

还没发表的工作，公开页只放到对错这一层，具体数字只在内部版里。

通知里写什么

一条好的通知：

第 7 轮完成：带噪验证集早停的预测对了两条错了一条；审查通过。https://你的名字.github.io/lab-results/

一句结论，对错，审查，链接。ntfy 的频道名谁知道谁就能收到，它相当于一个密码，不写进仓库和网页；通知里也不放未发表的数字。不推长日志，不推每一步的进度；只在三种时候推：一轮完成，出错停下，反思检查叫停。推得太多，你很快就不看了。

练习

给结果页加一张折线图：横轴轮次，纵轴累计的预测命中率。图也由脚本从结果文件生成。

最容易出错的地方

让 Agent 手动改网页。 几轮之后网页上的数字和结果文件对不上。网页由脚本从文件生成。

未发表的结果上了公开网页。 免费 Pages 只能公开发布，完整数字一推上去就被人看到。公开页只放到对错这一层。

通知太多。 每一步都推，一天几十条，真出事时那条被淹没。只在完成，出错，叫停时推。

4.3 Results page

Self-study, about 25 minutes.

The loop produces work every night. You cannot open a folder and read every file each morning. A results page brings them together on a web page you can read on your phone. Notifications send only a one-sentence conclusion and the link.

Generate from result files

A script generates the results page from files, rebuilding it at the end of each round:

Write code/make_page.py: read prediction.md, results/, result.md and review.md for each round under runs/ and generate two sets of pages.
site/ is the public summary: a top line with round count and prediction accuracy; one row per round with the question, prediction, right or wrong, and whether review passed; the playbook's top five entries at the bottom.
internal/ is the internal version: beyond the summary, clicking through to a round shows all numbers, figures and the result report.
Use only HTML and one CSS file, no external frameworks.

Why not have the agent edit the page each round? Manual edits miss things or change last round’s numbers. After a few rounds, the page no longer matches the files. With a script, every number comes from a file: the same principle as Session 1’s numbers coming from data.

Publish to GitHub Pages

GitHub Pages publishes a repository’s web pages as a free website. The last step of wrapping up:

Run code/make_page.py. Copy only site/ to the lab-results repository, commit and push. Use gh to check its Pages deployment status. Once it succeeds, open the URL and confirm the update.

Free accounts can publish only from public repositories, and the website is public too. Keep the public summary in a separate public repository. Keep the internal version with code and data in the private repository, and open it locally.

What to publish

Anyone can see a public page, and search engines may index it.

Publish Keep out
Questions, predictions, right or wrong Full unpublished numbers and figures
Overall prediction accuracy Code and data
Playbook Server addresses, accounts, any secrets

For unpublished work, the public page goes only as far as right or wrong. Detailed numbers stay in the internal version.

What a notification says

A good notification:

Round 7 complete: two predictions about noisy-validation early stopping were right and one was wrong; review passed. https://your-name.github.io/lab-results/

One conclusion, right or wrong, review, link. Anyone who knows an ntfy channel name can receive its messages. Treat it as a password and keep it out of repositories and pages. Keep unpublished numbers out of notifications too. Don’t send long logs or step-by-step progress. Notify only when a round finishes, an error stops it, or a reflection check halts it. Too many notifications and you soon stop reading them.

Exercise

Add a line chart to the results page: round on the horizontal axis, cumulative prediction accuracy on the vertical. Generate it from result files with the script too.

Where agents go wrong most

The agent edits pages manually. After a few rounds, the numbers on the page no longer match result files. Generate pages from files with a script.

Unpublished results on a public page. Free Pages publishes publicly; people can see the full numbers as soon as you push. Public pages go only as far as right or wrong.

Too many notifications. Dozens of updates each day bury the one that matters. Notify only on completion, error or a halt.

2.3 并行复筛与选题

课后深入，约 50 分钟。

把三百条文献分给六个助手，很快就能得到六张表。真正难的是六张表里的收与不收是否是同一个意思。

先用共同样本校准

从检索结果中抽一小组，放入明确相关、明确不相关和边界案例。由不同助手按同一标准判断，比较分歧。把标准修成对研究问题有意义的条件，再冻结本轮版本。

复筛首先控制漏读。边界案例进入待定，后续全文复筛；明确排除的也保留一句理由。若任务要求系统性覆盖，另外对排除集抽样回读，估计漏掉相关文献的风险。

用同一份 criteria.md 独立判断校准集，输出 include，exclude，uncertain 和理由。
比较分歧，找出标准中含糊的地方。修订后用另一小组校准，再开始批量任务。
保留标准版本与各轮判断。

每个助手只写自己的分片

任务说明要自成一体，写清输入文件与标准版本，指定可写目录和输出列。共享概念页留给一个合并者。文献标识去重后分配，避免同一篇在不同分片重复计数。

只读分配给你的论文与 criteria.md，不读其他助手的结论。
写 screening/part-01.csv，逐条保留文献标识与判断，并说明理由和阅读范围。
只写自己的分片。返回文件清单、无法判断项和实际使用的工具名称。

合并时检查编号集合，重复项和缺行。质量抽查按明确排除，边界与纳入分层抽样，发现某一类持续出错，再决定重做范围。

新会话的输入范围

新会话可以减少既有讨论的影响，仍可能继承项目文件和默认知识。任务卡写明问题生成允许读取哪些材料，并记录实际输入。

让它提出问题时，同时生成最近先例与竞争解释。三个问题若都只是在原方法上改一个参数，回到分歧表检查遗漏了哪种机制。

查新要形成同一张比较表

维度 自己的问题 最近先例
要解释的现象 具体到可观察变化 原工作解释了什么
关键干预 这次改变什么 已做过哪些变化
预测与反例 哪种结果会否定解释 原证据能否区分它
新增信息 实验成功或失败各多知道什么 已经知道的部分

关键词搜索先找线索，再查原文和引用关系。某次检索没有找到，记录查询范围和日期。保留原问题的尺度，针对差异补充证据或换一项真正有信息的干预。

并行阅读的质量评估

用同一批材料做一个小对照：串行阅读与分工阅读使用相同模板，比较遗漏关键条件的比例、证据抽查通过率和实际耗时。token 成本另记。

即使分工更快，合并阶段也可能丢掉限定条件。把合并后的核心结论再抽回原文，才能知道瓶颈转移到了哪里。

练习

取二十条自己方向的文献，四条用于校准，余下分两组。合并后抽查明确排除与边界各几条，再让一个只读知识库的新会话提出研究问题。交付标准版本、分片与查新表。

常见错误与处理方法

分工前没有校准。 先比较共同样本，修清标准再分配。

多个助手直接改共享综述。 各写分片，一个合并者更新总表和概念页。

并行速度当成研究覆盖。 检查文献标识集合，分层抽查排除项和关键证据。

2.3 Parallel screening and research questions

After-class deep dive, about 50 minutes.

Split three hundred papers among six helpers and you quickly get six tables. The hard part is whether include and exclude mean the same thing in all six.

Calibrate on a shared sample first

Draw a small set from the search results, containing clearly relevant, clearly irrelevant and borderline cases. Have different helpers judge them by the same criteria and compare disagreements. Revise the criteria into conditions that mean something for the research question, then freeze this round’s version.

The first priority in rescreening is to avoid missing relevant papers. Borderline cases go to pending for later full-text rescreening; clear exclusions also keep a one-sentence reason. If the task requires systematic coverage, also sample and reread the excluded set to estimate the risk of having missed relevant work.

Judge the calibration set independently using the same criteria.md, outputting include, exclude or uncertain with a reason.
Compare disagreements and find where the criteria are vague. After revising, calibrate on another small set before starting the batch.
Keep the criteria version and each round's judgments.

Give each helper a separate output file

The task description must stand on its own, stating the input files, criteria version, writable directory and output columns. The shared concept page is left to one editor. Deduplicate by paper identifier before assigning, so the same paper is not counted twice in different shards.

Read only the papers assigned to you and criteria.md; do not read other helpers' conclusions.
Write screening/part-01.csv, keeping for each item the paper identifier, judgment, reason and reading scope.
Write only your own shard. Return the file list, the items you could not judge and the actual names of the tools you used.

When merging, check the set of identifiers, duplicates and missing rows. Spot-check quality with stratified samples from clear exclusions, borderline cases and inclusions; if one class keeps going wrong, then decide how much to redo.

Check what a new session can read

A new session can reduce the influence of earlier discussion, but may still inherit project files and background knowledge. The task card states which materials question generation may read, and the actual inputs are recorded.

When it proposes questions, have it also produce the nearest precedent and competing explanations. If all three questions only change one parameter of the original method, go back to the disagreement table and check which mechanism was left out.

A novelty search should produce one comparison table

Dimension Your question Nearest precedent
Phenomenon to explain Specific down to an observable change What the original work explained
Key intervention What this one changes Which changes have already been made
Prediction and counterexample Which result would refute the explanation Whether the original evidence can tell it apart
New information What more you would know if the experiment succeeds or fails What is already known

Keyword searches find leads first; then check the originals and citation relations. If a search found nothing, record the query scope and date. Keep the scale of the original question, and address the gap by adding evidence or choosing a more informative intervention.

Evaluate the quality of parallel reading

Run a small comparison on the same materials: serial and parallel reading use the same template, and you compare the share of key conditions missed, the pass rate of evidence spot-checks and wall-clock time. Record token cost separately.

Even if splitting is faster, the merge stage may drop qualifying conditions. Only by taking the merged core conclusions back to the originals do you learn where the bottleneck moved.

Exercise

Take twenty papers from your own field: four for calibration, the rest split into two groups. After merging, spot-check a few clear exclusions and a few borderline cases, then have a new session that reads only the knowledge base propose a research question. Deliver the criteria version, the shards and the novelty table.

Common mistakes and how to fix them

Splitting the work without calibrating. Compare on a shared sample first, clarify the criteria, then assign.

Several helpers editing the shared review directly. Each writes a shard, and one editor updates the master table and concept page.

Mistaking faster parallel reading for complete coverage. Check the set of paper identifiers, and spot-check exclusions and key evidence by stratum.

The discussion of framework choice in the Hugging Face Agents Course helps judge when a simple script is already enough. Berkeley LLM Agents covers task allocation and evaluation in multi-stage systems.

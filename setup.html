0 课前准备

让两个 Agent 在同一个练习文件夹里工作：一家整理会议记录，另一家拿原记录核查。结束时，你能找到它们写出的文件，也知道自己登录的是哪一种服务。

自学 45 至 90 分钟。按自己的系统选一条路径。安装说明核对于 2026 年 10 月 15 日。

本页是第一次课以前的共同准备，不占六堂课各自的一小时。先完成安装与登录，再做第一次读写；每堂课还各有一张预备卡，提前装那一课新增的工具，下载材料。暂时只有一家 Agent，也先把第一次读写做通。

第一次安装提前一天开始，留出下载与报错处理的时间。会话怎么交接、怎样判断输出可靠，课堂会接着练，不要求在课前自行完成复杂配置。

网页、桌面应用与命令行

Claude 和 ChatGPT 的网页聊天适合提问。Claude Code 与 Codex 的本地入口还能读写项目文件，并调用电脑上的程序。本课同时介绍桌面应用和命令行：桌面应用便于看产物；命令行在第 4 课用于自动执行。

使用前确认账号有相应访问资格。订阅登录与 API 密钥登录使用不同的计费渠道；本课走官方账号登录，不需要先买 API 额度。登录界面显示的套餐与组织是最后的检查位置。

桌面安装从 Claude Code Desktop 和 Codex 快速入门进入，选择官网提供的系统安装包。macOS 把应用拖到 Applications，Windows 按官方安装界面完成。装好后选择本地项目，找到能显示工作目录的任务入口。Linux 读者可直接走下面的命令行路线。

Windows：在 PowerShell 里装

第一步，打开正确的终端

在开始菜单搜索 PowerShell，打开普通用户窗口。提示符通常以 PS C:\ 开头。下面这组安装命令要在 PowerShell 里运行。

如果平时使用 Git Bash 或 WSL，先选定一套环境，安装和启动都在同一套里完成。Windows 与 WSL 各有自己的程序、PATH 和用户目录。

第二步，安装 Claude Code

按 Anthropic 官方安装说明，粘贴：

irm https://claude.ai/install.ps1 | iex

下载阶段可能一时没有输出。等它回到提示符，关掉这个窗口，再开一个 PowerShell，检查：

claude --version
Get-Command claude

第一条应当显示版本号，第二条显示实际执行文件的位置。Claude Code 原生安装放在用户目录。需要 Bash 工具时，按 Git for Windows 官网安装 Git，再确认：

git --version

当前 Claude Code 在未安装 Git for Windows 时也可使用 PowerShell 作为 shell 工具。后续课程涉及 Bash 脚本时，再检查运行环境，见官方说明。

第三步，安装 Codex

在同一套 PowerShell 环境运行官方安装器：

irm https://chatgpt.com/codex/install.ps1 | iex

重新打开 PowerShell，检查：

codex --version
Get-Command codex

官方独立安装器可以直接安装 Codex，不需要先装 Node.js。已有 npm 工作环境的读者也可用官方文档列出的 npm install -g @openai/codex。一台机器选一种安装方式，避免 PATH 先找到另一份旧程序。安装入口见 Codex CLI。

第四步，找不到命令时修 PATH

PATH 是终端查找程序的一串目录。先确认文件是否存在：

Test-Path "$env:USERPROFILE\.local\bin\claude.exe"
Test-Path "$env:LOCALAPPDATA\Programs\OpenAI\Codex\bin\codex.exe"

若文件存在，把对应目录加入当前窗口再试。下面分别是 Claude 与 Codex 独立安装器的默认目录：

$env:Path = "$env:USERPROFILE\.local\bin;$env:LOCALAPPDATA\Programs\OpenAI\Codex\bin;$env:Path"
claude --version
codex --version

如果这样成功，问题就在持久 PATH。开始菜单搜索环境变量，进入环境变量窗口，在上半部分的用户变量里编辑 Path。点新建，分别填入 Claude 的 C:\Users\用户名\.local\bin 和 Codex 的 %LOCALAPPDATA%\Programs\OpenAI\Codex\bin，保留已有项目，确认保存。重新打开终端再检查。

若 Test-Path 为 False，回到安装日志查实际安装位置和下载结果。使用 npm 安装的 Codex，运行 npm config get prefix，检查它报告的全局目录是否在用户 Path 中。不要把 PATH 整列替换成一个新目录。

第五步，进入练习目录

下载第 0 课材料

把压缩包解到自己的 agent-course 文件夹，找到含 notes.md 的那一层。资源管理器在这一层打开终端，或者在 PowerShell 输入实际路径：

Set-Location "$env:USERPROFILE\Documents\agent-course\lesson-0"
Get-Location
Get-ChildItem
claude

路径含空格时保留双引号。若目录放在桌面或 OneDrive，改成资源管理器地址栏里看到的实际位置。

Windows 原生 Codex 有自己的沙箱配置。若出现组织策略或系统组件错误，按 Windows 官方排障页核对系统版本与错误码。需要 Linux 工具链时，可由你启用 WSL，再按 Linux 路线安装；已有 Windows 安装不会自动成为 WSL 安装。

macOS：在 Terminal 里装

第一步，打开终端并查看系统

按 Command 与空格，搜索 Terminal，回车。先运行：

sw_vers
uname -m
echo "$SHELL"

arm64 对应 Apple 芯片，x86_64 对应 Intel。安装器会选择适合的程序；桌面应用的芯片与系统要求以下载页为准。

第二步，安装两家命令行

已有 Homebrew 的读者可沿用它安装，两条命令分开运行：

brew install --cask claude-code
brew install --cask codex

未使用 Homebrew 时，官方独立安装器更直接：

curl -fsSL https://claude.ai/install.sh | bash
curl -fsSL https://chatgpt.com/codex/install.sh | sh

两种路线选一种。分别见 Claude Code 安装和 Codex CLI 安装。安装结束后新开一个终端窗口：

claude --version
codex --version
command -v claude
command -v codex

第三步，处理 PATH

独立安装器通常把入口放在 ~/.local/bin。如果程序存在却提示找不到命令，先只修当前窗口：

export PATH="$HOME/.local/bin:$PATH"
claude --version
codex --version

成功后，用文本编辑器打开 ~/.zshrc，把同一行加到末尾一次，再运行：

source ~/.zshrc

使用 Bash 的读者改对应的 ~/.bashrc；登录 shell 还要检查自己的 ~/.bash_profile 是否加载它。用 Homebrew 安装时，按 brew --prefix 找实际前缀，再按 Homebrew 安装后的提示配置 shell，避免把 Apple 芯片和 Intel 的目录写反。

第四步，进入目录

下载并解压第 0 课材料，找到 notes.md 所在文件夹。在终端输入 cd，把文件夹从 Finder 拖进终端，再按回车。也可以写实际路径：

cd "$HOME/Documents/agent-course/lesson-0"
pwd
ls
claude

Linux：先把用户环境做通

以下示例使用 Ubuntu 或 Debian。其他发行版先通过自己的包管理器安装 curl 和 Git。共享服务器沿用管理员提供的基础环境。

sudo apt update
sudo apt install curl git ca-certificates

这两步会修改系统软件，由你本人授权。接下来的 Agent 安装在自己的用户目录里完成：

curl -fsSL https://claude.ai/install.sh | bash
curl -fsSL https://chatgpt.com/codex/install.sh | sh
export PATH="$HOME/.local/bin:$PATH"
claude --version
codex --version

把 PATH 那一行加入自己的 ~/.bashrc 一次，重新打开终端检查。若使用 Zsh，改 ~/.zshrc。安装失败时先看官方页面的发行版和 CPU 要求；Alpine 等环境的依赖不同，不能直接套用 Ubuntu 的包名。

解压练习材料，进入含 notes.md 的目录：

cd "$HOME/agent-course/lesson-0"
pwd
ls
claude

远程无桌面的机器可能打不开登录浏览器。Claude Code 启动时按终端提示在本机浏览器完成登录；Codex 可按官方认证说明使用设备码登录。先在真实界面确认支持的方式，登录结果以终端回报为准。

首次登录，两家分别确认

启动 claude 后，按提示选择官方 Claude 账号登录。浏览器里完成账号和组织选择，回到终端确认已经进入对话。启动 codex 时选择 Sign in with ChatGPT，再回到终端检查。两家分别登录，各自使用自己的账号状态。

如果机器以前配过 API，只检查相关变量是否存在：

检查这台机器是否配置过影响当前 Agent 认证的环境变量，只报告变量名和是否存在。
不要输出值。告诉我当前实际使用订阅登录还是 API 登录。

以 Claude 的 ANTHROPIC_API_KEY 和 Codex 的 OPENAI_API_KEY 为例，先查是否设置了这些环境变量；最终渠道还要结合当前设置和登录状态确认。需要调整时保留原配置，明确改哪一项。密钥由你在本地管理。

第一次进入项目，会看到目录信任和权限选择。核对当前路径是练习目录，使用能逐步看到读写与命令的默认权限。先完成一次小任务，后面再按工作需要配置。

第一次任务：整理并核查会议纪要

在 Claude Code 中发送：

读 notes.md，把这次组会整理成 minutes.md。
分别写已作出的决定、每个人的待办和截止日期。记录里没有的日期写待定。
写完告诉我产物位置，列出你发现的一处原记录歧义。

在文件夹里打开 minutes.md。核对人物、日期和决定是否来自原记录。接着开 Codex，选择同一个项目，发送：

对照 notes.md 核查 minutes.md，查漏项和凭空补出的决定。
只把核查意见写到 check.md，不改纪要。注明审阅的文件和问题位置。

现在你已经做完后面各课都会用到的交接：原件留在文件里，产物另存，审阅者拿明确版本核查。换一个任务时，让当前 Agent 把下一步写进文件，再开新会话。

常见报错，按现象查

现象 先检查 处理
irm 无法识别 是否在 CMD 或 Bash 改在 PowerShell 执行对应安装命令
command not found 或未识别命令 文件是否已下载，当前 PATH 指向哪里 先用完整路径验证，再修用户 PATH
codex.ps1 被执行策略拦下 是否来自 npm 安装 可先用 codex.cmd 启动，或改用官方独立安装器；组织策略交管理员处理
下载超时、403 或证书错误 官方地址能否在浏览器正常访问，机器时间是否正确 查学校网络和代理设置，保留错误码；不要换成来路不明的安装脚本
Permission denied 或 EACCES 是否在写系统目录，旧安装属于谁 改用用户目录安装或修复明确的目录权限，保留配置备份
登录完成后终端仍未登录 浏览器是否登录了正确账号，回调是否返回这台机器 按官方提示重试一次；远端机器检查设备码等受支持的方式
401 或 403 出现在模型调用时 登录渠道、组织权限和账号资格 按认证文档核查，区分安装成功与服务可用
同一命令显示不同版本 PATH 中是否有多份安装 Windows 用 Get-Command codex -All，macOS 与 Linux 用 type -a codex；选定一种安装来源

Claude Code 的诊断可从 claude doctor 开始，更多现象见官方排障。Codex 从 /status 检查会话设置，再按 CLI 文档定位。保留错误文本和版本号，发给 Agent 时删去凭据。

常见错误与处理方法

安装成功就宣布能用了。 版本号只证明程序能启动。再做一次登录后的读写任务，文件落到预定目录才完成验收。

修 PATH 时覆盖旧配置。 要加入一个目录，却把原来的 Path 清空。编辑前保留原值，新增目录后在新终端验证。

两家同时改同一份纪要。 核查任务只写核查文件，修改交回原作者处理。一个产物在同一时刻由一个会话写。

工作台小结

现在的工作台只有两家 Agent 和一个项目文件夹。notes.md 是原件，minutes.md 是产物，check.md 是独立核查。安装位置和启动命令写进自己的简短准备记录，后续课堂无需重新安装。

准备好第 1 课材料。下一课让 Agent 把 Python、编译和页面检查接上，完成一篇论文的重讲。

第一次课前交什么

在练习目录留下 preflight.md，写明系统与两家 Agent 的版本，标出实际工作目录及 minutes.md 与 check.md 的位置，以及尚未解决的错误。确认文件能在自己的电脑上打开，然后进入第 1 课预备卡，完成编译环境、渲染和范文下载。

以后每课在自己的材料目录更新同名准备记录。带着错误记录提前求助，比开课后重新尝试整套安装更容易定位问题。

0 Getting started

Get two agents working in the same exercise folder: one turns meeting notes into minutes, the other checks them against the original notes. At the end you can find the files they wrote, and you know which service and billing method you are using.

Self-study, 45 to 90 minutes. Choose the path for your system. Installation instructions checked on 15 October 2026.

This page is the shared preparation before the first class and is separate from the six one-hour classes. Work through installation, login and your first file task; each lesson also has its own preparation card for installing that lesson’s new tools and downloading materials. If you have only one agent for now, still get your first file task working.

Start the first installation a day early to leave time for downloads and errors. You will practice session handoffs and assess output reliability in class; you are not expected to set up complex configuration on your own beforehand.

Web chat, desktop apps and command-line tools

The Claude and ChatGPT web chats are good for asking questions. The local versions of Claude Code and Codex can also read and write project files and run programs on your computer. This lesson covers both the desktop apps and the command line: the desktop app makes outputs easy to view; the command line is used for automatic execution in Lesson 4.

Before you start, confirm that your account has the right access. Subscription login and API key login are billed through different channels; this course uses official account login and does not require buying API credit first. The plan and organization shown on the login screen provide the final confirmation.

For the desktop apps, start from Claude Code Desktop and the Codex quickstart, and choose the installer the official site offers for your system. On macOS, drag the app into Applications; on Windows, follow the official installer. Once installed, choose a local project and find the task view that shows the working directory. Linux readers can go straight to the command-line route below.

Windows: install in PowerShell

Step 1: open the right terminal

Search for PowerShell in the Start menu and open a normal user window. The prompt usually starts with PS C:\. Run the following installation commands in PowerShell.

If you normally use Git Bash or WSL, choose one environment and do both installation and startup in it. Windows and WSL each have their own programs, PATH and user directory.

Step 2: install Claude Code

Following Anthropic’s official installation guide, paste:

irm https://claude.ai/install.ps1 | iex

The download may show no output for a while. Wait until it returns to the prompt, close this window, open a new PowerShell and check:

claude --version
Get-Command claude

The first should show a version number, the second the location of the actual executable. The native Claude Code install goes in your user directory. If you need the Bash tool, install Git from the Git for Windows site, then confirm:

git --version

Current Claude Code can also use PowerShell as its shell tool when Git for Windows is not installed. When later lessons involve Bash scripts, check the runtime environment then; see the official guide.

Step 3: install Codex

In the same PowerShell environment, run the official installer:

irm https://chatgpt.com/codex/install.ps1 | iex

Reopen PowerShell and check:

codex --version
Get-Command codex

The official standalone installer installs Codex directly; you do not need Node.js first. Readers who already have a working npm setup can also use npm install -g @openai/codex, as listed in the official docs. Choose one installation method per machine, so that PATH does not find another, older copy first. See the installation instructions in Codex CLI.

Step 4: fix PATH when the command is not found

PATH is the list of directories the terminal searches for programs. First check whether the files exist:

Test-Path "$env:USERPROFILE\.local\bin\claude.exe"
Test-Path "$env:LOCALAPPDATA\Programs\OpenAI\Codex\bin\codex.exe"

If they exist, add their directories to the current window and try again. These are the default directories of the Claude and Codex standalone installers:

$env:Path = "$env:USERPROFILE\.local\bin;$env:LOCALAPPDATA\Programs\OpenAI\Codex\bin;$env:Path"
claude --version
codex --version

If this works, the problem is the persistent PATH. Search for environment variables in the Start menu, open the Environment Variables window, and edit Path under the user variables in the upper half. Click New and add Claude’s C:\Users\YourName\.local\bin (with your own user name) and Codex’s %LOCALAPPDATA%\Programs\OpenAI\Codex\bin as separate entries, keep the existing entries, and save. Reopen the terminal and check again.

If Test-Path returns False, go back to the installation log to find the actual install location and download result. For Codex installed with npm, run npm config get prefix and check whether the global directory it reports is in your user Path. Do not replace the whole PATH with a single new directory.

Step 5: go to the exercise directory

Download the Lesson 0 materials

Unzip the archive into your own agent-course folder and find the level that contains notes.md. Open a terminal at that level from File Explorer, or type the actual path in PowerShell:

Set-Location "$env:USERPROFILE\Documents\agent-course\lesson-0"
Get-Location
Get-ChildItem
claude

Keep the double quotes when the path contains spaces. If the folder is on the Desktop or in OneDrive, use the actual location shown in File Explorer’s address bar.

Native Codex on Windows has its own sandbox configuration. If you see an organization policy or system component error, check your system version and the error code against the official Windows troubleshooting page. If you need a Linux toolchain, you can enable WSL yourself and follow the Linux route; an existing Windows install does not automatically become a WSL install.

macOS: install in Terminal

Step 1: open a terminal and check the system

Press Command and Space, search for Terminal, and press Return. First run:

sw_vers
uname -m
echo "$SHELL"

arm64 means Apple silicon and x86_64 means Intel. The installers choose the right program; for the desktop apps, the chip and system requirements on the download page are authoritative.

Step 2: install both command-line tools

If you already use Homebrew, you can install with it, running the two commands separately:

brew install --cask claude-code
brew install --cask codex

Without Homebrew, the official standalone installers are more direct:

curl -fsSL https://claude.ai/install.sh | bash
curl -fsSL https://chatgpt.com/codex/install.sh | sh

Choose one of the two routes. See Claude Code installation and Codex CLI installation. When installation finishes, open a new terminal window:

claude --version
codex --version
command -v claude
command -v codex

Step 3: configure PATH

The standalone installers usually put their entry points in ~/.local/bin. If the program exists but the command is not found, first fix only the current window:

export PATH="$HOME/.local/bin:$PATH"
claude --version
codex --version

Once that works, open ~/.zshrc in a text editor, add the same line once at the end, then run:

source ~/.zshrc

Bash users edit ~/.bashrc instead; for login shells, also check whether your ~/.bash_profile loads it. If you installed with Homebrew, find the actual prefix with brew --prefix and configure the shell as Homebrew suggests after installation, so you do not mix up the Apple silicon and Intel directories.

Step 4: go to the directory

Download and unzip the Lesson 0 materials and find the folder that contains notes.md. Type cd in the terminal, drag the folder from Finder into the terminal, and press Return. You can also type the actual path:

cd "$HOME/Documents/agent-course/lesson-0"
pwd
ls
claude

Linux: get the user environment working first

The examples below use Ubuntu or Debian. On other distributions, first install curl and Git with your own package manager. On shared servers, use the base environment the administrator provides.

sudo apt update
sudo apt install curl git ca-certificates

These two steps change system software, and you authorize them yourself. The agents are then installed in your own user directory:

curl -fsSL https://claude.ai/install.sh | bash
curl -fsSL https://chatgpt.com/codex/install.sh | sh
export PATH="$HOME/.local/bin:$PATH"
claude --version
codex --version

Add the PATH line to your ~/.bashrc once, reopen the terminal and check. If you use Zsh, edit ~/.zshrc. If installation fails, first check the distribution and CPU requirements on the official pages; environments such as Alpine have different dependencies, and Ubuntu package names do not carry over.

Unzip the exercise materials and go to the directory that contains notes.md:

cd "$HOME/agent-course/lesson-0"
pwd
ls
claude

A remote machine without a desktop may not be able to open the login browser. When Claude Code starts, follow the terminal prompts and finish login in a browser on your local machine; Codex can use device-code login as described in the official authentication guide. First confirm in the actual interface which methods are supported; the terminal’s report is what counts as the login result.

Log in to each agent separately

After starting claude, follow the prompts and choose official Claude account login. Finish choosing the account and organization in the browser, then go back to the terminal and confirm that you are in a conversation. When starting codex, choose Sign in with ChatGPT, then check back in the terminal. Log in to each separately; each keeps its own account state.

If this machine was configured for APIs before, only check whether the relevant variables exist:

Common errors, by symptom

Symptom Check first What to do
irm not recognized Are you in CMD or Bash Run the installation command in PowerShell
command not found or command not recognized Was the file downloaded, and where does the current PATH point Verify with the full path first, then fix the user PATH
codex.ps1 blocked by execution policy Was it installed with npm Start it with codex.cmd for now, or switch to the official standalone installer; organization policy goes to the administrator
Download timeout, 403 or certificate error Does the official address open normally in a browser, is the machine’s clock correct Check the university network and proxy settings and keep the error code; do not switch to an installation script of unknown origin
Permission denied or EACCES Are you writing to a system directory, and who owns the old install Install in the user directory or fix the specific directory permission, keeping a backup of the configuration
Terminal still not logged in after login Did the browser log in to the right account, did the callback return to this machine Retry once as the official prompt says; on remote machines, check supported methods such as device code
401 or 403 on model calls Login channel, organization permissions and account eligibility Check against the authentication docs, and keep installation success distinct from service availability
The same command shows different versions Is there more than one install on PATH On Windows use Get-Command codex -All, on macOS and Linux type -a codex; settle on one installation source

Diagnosis for Claude Code can start with claude doctor; more symptoms are in the official troubleshooting guide. For Codex, check session settings with /status, then use the CLI docs. Keep the error text and version numbers, and remove credentials before sending them to an agent.

Common mistakes and how to fix them

Declaring it usable because installation succeeded. A version number only proves that the program starts. Do one read-and-write task after login; the check passes only when the file lands in the intended directory.

Overwriting the old configuration while fixing PATH. You meant to add one directory but emptied the original Path. Keep the original value before editing, and verify in a new terminal after adding the directory.

Both agents editing the same minutes at once. The checking task writes only the check file; changes go back to the original author. Only one session writes to a given output at a time.

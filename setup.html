0 课前准备

学习目标

  1. 区分网页聊天、桌面应用与命令行 Agent 的能力范围，以及订阅登录与 API 密钥登录的计费渠道，确认本机实际使用的认证方式。
  2. 依据版本号、实际执行路径和 PATH 诊断安装问题，并以一次登录后的文件读写任务作为环境验收标准。
  3. 在原件、产物与独立核查之间建立文件交接，使审阅者针对明确的文件给出意见。

自学 45 至 90 分钟。按自己的操作系统选择一条路径。安装说明核对于 2026 年 10 月 15 日。

本页是首次课前的共同准备，不占用六次课堂各自的 60 分钟。先完成安装与登录，再完成首次文件读写。此后每课另有一份课前准备说明，用于提前安装该课新增的工具并下载材料。暂时只能使用一家 Agent 的，也应先完成首次读写。

首次安装建议提前一天开始，为下载与报错处理留出时间。会话交接和输出可靠性的判断在课堂中继续训练，课前不要求自行完成复杂配置。

网页、桌面应用与命令行

Claude 和 ChatGPT 的网页聊天适合提问。Claude Code 与 Codex 的本地入口还能读写项目文件，并调用本机程序。本课同时介绍桌面应用和命令行：桌面应用便于查看产物，命令行在第 4 课用于自动执行。

使用前应确认账号具有相应的访问资格。订阅登录与 API 密钥登录属于不同的计费渠道；本课使用官方账号登录，无需购买 API 额度。登录界面显示的套餐与组织是最终的核对依据。

桌面应用从 Claude Code Desktop 和 Codex 快速入门进入，选择官网提供的系统安装包。macOS 把应用拖入 Applications，Windows 按官方安装界面完成。安装后选择本地项目，找到能够显示工作目录的任务入口。Linux 用户可直接采用下文的命令行路线。

Windows：在 PowerShell 中安装

第一步：打开 PowerShell

在开始菜单中搜索 PowerShell，打开普通用户窗口，提示符通常以 PS C:\ 开头。以下安装命令均在 PowerShell 中运行。

平时使用 Git Bash 或 WSL 的用户，应先选定一套环境，安装和启动都在同一环境中完成。Windows 与 WSL 各有独立的程序、PATH 和用户目录。

第二步：安装 Claude Code

按 Anthropic 官方安装说明运行：

irm https://claude.ai/install.ps1 | iex

下载阶段可能暂时没有输出。回到提示符后关闭该窗口，新开一个 PowerShell 检查：

claude --version
Get-Command claude

第一条命令应显示版本号，第二条显示实际执行文件的位置。Claude Code 的原生安装位于用户目录。需要 Bash 工具时，按 Git for Windows 官网安装 Git，再确认：

git --version

当前版本的 Claude Code 在未安装 Git for Windows 时，也可以使用 PowerShell 作为 shell 工具。后续课程涉及 Bash 脚本时再检查运行环境，见官方说明。

第三步：安装 Codex

在同一 PowerShell 环境中运行官方安装器：

irm https://chatgpt.com/codex/install.ps1 | iex

重新打开 PowerShell 检查：

codex --version
Get-Command codex

官方独立安装器可以直接安装 Codex，无需先安装 Node.js。已有 npm 工作环境的用户也可以使用官方文档列出的 npm install -g @openai/codex。同一台机器只选一种安装方式，以免 PATH 先找到另一份旧程序。安装入口见 Codex CLI。

第四步：找不到命令时修复 PATH

PATH 是终端查找程序时依次搜索的目录列表。先确认文件是否存在：

Test-Path "$env:USERPROFILE\.local\bin\claude.exe"
Test-Path "$env:LOCALAPPDATA\Programs\OpenAI\Codex\bin\codex.exe"

若文件存在，先把对应目录加入当前窗口的 PATH 再试。以下分别是 Claude 与 Codex 独立安装器的默认目录：

$env:Path = "$env:USERPROFILE\.local\bin;$env:LOCALAPPDATA\Programs\OpenAI\Codex\bin;$env:Path"
claude --version
codex --version

若这样能够运行，问题在于持久 PATH。在开始菜单中搜索环境变量，打开环境变量窗口，在上半部分的用户变量中编辑 Path。点击新建，分别填入 Claude 的 C:\Users\用户名\.local\bin 和 Codex 的 %LOCALAPPDATA%\Programs\OpenAI\Codex\bin，保留已有条目，确认保存。重新打开终端后再检查。

若 Test-Path 返回 False，应回到安装日志查找实际安装位置和下载结果。使用 npm 安装的 Codex，运行 npm config get prefix，检查其报告的全局目录是否在用户 Path 中。不要用一个新目录替换整个 PATH。

第五步：进入练习目录

下载第 0 课材料

把压缩包解压到自己的 agent-course 文件夹，找到包含 notes.md 的那一层目录。可以在资源管理器中从该目录打开终端，也可以在 PowerShell 中输入实际路径：

Set-Location "$env:USERPROFILE\Documents\agent-course\lesson-0"
Get-Location
Get-ChildItem
claude

路径含空格时保留引号。目录位于桌面或 OneDrive 时，改为资源管理器地址栏中显示的实际位置。

Windows 原生 Codex 有独立的沙箱配置。若出现组织策略或系统组件错误，按 Windows 官方排障页核对系统版本与错误码。需要 Linux 工具链时，可由用户本人启用 WSL，再按 Linux 路线安装；已有的 Windows 安装不会自动成为 WSL 中的安装。

macOS：在 Terminal 中安装

第一步：打开终端并查看系统

按 Command 与空格键，搜索 Terminal 并打开，先运行：

sw_vers
uname -m
echo "$SHELL"

arm64 对应 Apple 芯片，x86_64 对应 Intel 芯片。安装器会自动选择适配的程序；桌面应用的芯片与系统要求以下载页为准。

第二步：安装两家命令行工具

已使用 Homebrew 的用户可以沿用它安装，两条命令分别运行：

brew install --cask claude-code
brew install --cask codex

未使用 Homebrew 时，官方独立安装器更为直接：

curl -fsSL https://claude.ai/install.sh | bash
curl -fsSL https://chatgpt.com/codex/install.sh | sh

两种路线任选其一，分别见 Claude Code 安装和 Codex CLI 安装。安装结束后新开一个终端窗口：

claude --version
codex --version
command -v claude
command -v codex

第三步：配置 PATH

独立安装器通常把入口放在 ~/.local/bin。若程序存在却提示找不到命令，先只修复当前窗口：

export PATH="$HOME/.local/bin:$PATH"
claude --version
codex --version

确认有效后，用文本编辑器打开 ~/.zshrc，在末尾加入同一行，只加一次，再运行：

source ~/.zshrc

使用 Bash 的用户修改对应的 ~/.bashrc；登录 shell 还需检查 ~/.bash_profile 是否加载了它。使用 Homebrew 安装时，通过 brew --prefix 查找实际前缀，再按 Homebrew 安装后的提示配置 shell，避免混淆 Apple 芯片与 Intel 芯片的目录。

第四步：进入练习目录

下载并解压第 0 课材料，找到 notes.md 所在的文件夹。在终端输入 cd，把文件夹从 Finder 拖入终端，再按回车；也可以直接输入实际路径：

cd "$HOME/Documents/agent-course/lesson-0"
pwd
ls
claude

Linux：用户环境的准备

以下示例使用 Ubuntu 或 Debian。其他发行版先通过各自的包管理器安装 curl 和 Git。共享服务器沿用管理员提供的基础环境。

sudo apt update
sudo apt install curl git ca-certificates

这两步会修改系统软件，须由用户本人授权。随后的 Agent 安装在自己的用户目录中完成：

curl -fsSL https://claude.ai/install.sh | bash
curl -fsSL https://chatgpt.com/codex/install.sh | sh
export PATH="$HOME/.local/bin:$PATH"
claude --version
codex --version

把设置 PATH 的那一行加入 ~/.bashrc，只加一次，重新打开终端检查。使用 Zsh 时改为 ~/.zshrc。安装失败时，先查看官方页面对发行版和 CPU 的要求；Alpine 等环境的依赖不同，不能直接套用 Ubuntu 的包名。

解压练习材料，进入包含 notes.md 的目录：

cd "$HOME/agent-course/lesson-0"
pwd
ls
claude

没有桌面环境的远程机器可能无法打开登录浏览器。Claude Code 启动时按终端提示在本机浏览器中完成登录；Codex 可按官方认证说明使用设备码登录。先在实际界面中确认支持的方式，登录结果以终端的反馈为准。

首次登录与认证方式确认

启动 claude 后，按提示选择以官方 Claude 账号登录。在浏览器中完成账号和组织选择，回到终端确认已经进入对话。启动 codex 时选择 Sign in with ChatGPT，再回到终端检查。两家分别登录，各自维护账号状态。

若本机以前配置过 API，只检查相关变量是否存在：

检查这台机器是否配置过影响当前 Agent 认证的环境变量，只报告变量名和是否存在。
不要输出值。告诉我当前实际使用订阅登录还是 API 登录。

以 Claude 的 ANTHROPIC_API_KEY 和 Codex 的 OPENAI_API_KEY 为例，先检查是否设置了这些环境变量；实际使用的渠道还须结合当前设置和登录状态确认。需要调整时保留原配置，并明确修改哪一项。密钥由用户本人在本地管理。

首次进入项目时，会出现目录信任和权限选择。确认当前路径是练习目录，使用能够逐步显示读写与命令的默认权限。先完成一次小任务，之后再按工作需要配置。

首次任务：会议纪要的整理与核查

在 Claude Code 中发送：

读 notes.md，把这次组会整理成 minutes.md。
分别写已作出的决定、每个人的待办和截止日期。记录里没有的日期写待定。
写完告诉我产物位置，列出你发现的一处原记录歧义。

在文件夹中打开 minutes.md，核对人物、日期和决定是否来自原记录。接着打开 Codex，选择同一项目，发送：

对照 notes.md 核查 minutes.md，查漏项和凭空补出的决定。
只把核查意见写到 check.md，不改纪要。注明审阅的文件和问题位置。

这一任务包含后续各课都会使用的交接方式：原件保留在文件中，产物另行保存，审阅者针对明确的文件进行核查。切换任务时，由当前 Agent 把下一步写入文件，再开启新会话。

常见报错的诊断

现象 先检查 处理
irm 无法识别 是否在 CMD 或 Bash 改在 PowerShell 执行对应安装命令
command not found 或未识别命令 文件是否已下载，当前 PATH 指向哪里 先用完整路径验证，再修用户 PATH
codex.ps1 被执行策略拦下 是否来自 npm 安装 可先用 codex.cmd 启动，或改用官方独立安装器；组织策略交管理员处理
下载超时、403 或证书错误 官方地址能否在浏览器正常访问，机器时间是否正确 查学校网络和代理设置，保留错误码；不要换成来路不明的安装脚本
Permission denied 或 EACCES 是否在写系统目录，旧安装属于谁 改用用户目录安装或修复明确的目录权限，保留配置备份
登录完成后终端仍未登录 浏览器是否登录了正确账号，回调是否返回这台机器 按官方提示重试一次；远端机器检查设备码等受支持的方式
401 或 403 出现在模型调用时 登录渠道、组织权限和账号资格 按认证文档核查，区分安装成功与服务可用
同一命令显示不同版本 PATH 中是否有多份安装 Windows 用 Get-Command codex -All，macOS 与 Linux 用 type -a codex；选定一种安装来源

Claude Code 的诊断可从 claude doctor 开始，更多现象见官方排障。Codex 先用 /status 检查会话设置，再按 CLI 文档定位问题。保留错误文本和版本号，提交给 Agent 时删去凭据。

常见错误与处理方法

安装成功即认为环境可用。 版本号只证明程序能够启动。还须完成一次登录后的读写任务，文件写入预定目录才算通过验收。

修复 PATH 时覆盖了原有配置。 本意是加入一个目录，却清空了原来的 Path。编辑前保留原值，新增目录后在新终端中验证。

两家 Agent 同时修改同一份纪要。 核查任务只写核查文件，修改交回原作者处理。同一产物在同一时刻只由一个会话写入。

本节小结

目前的工作环境由两家 Agent 和一个项目文件夹构成。notes.md 是原件，minutes.md 是产物，check.md 是独立核查。安装位置和启动命令写入自己的准备记录，后续课堂无需重新安装。

请准备好第 1 课材料。下一课将接入 Python、LaTeX 编译和页面检查，完成一篇论文的重写。

首次课前提交的准备记录

在练习目录中保存 preflight.md，写明操作系统与两家 Agent 的版本，注明实际工作目录、minutes.md 与 check.md 的位置，以及尚未解决的错误。确认文件能在自己的电脑上打开，然后进入第 1 课课前准备，完成编译环境、渲染和范文下载。

此后每课都在相应材料目录中更新同名的准备记录。带着错误记录提前求助，比开课后重新尝试整套安装更容易定位问题。

0 Getting started

Learning outcomes

After completing this unit, students should be able to:

  1. Verify that an agent environment is usable by distinguishing program installation, authenticated service access and correct file access in the intended working directory.
  2. Identify the authentication and billing channel an agent is using, and diagnose common installation failures from their symptoms without discarding existing configuration.
  3. Organize a two-agent task so that the source material, the product and an independent check are kept in separate files with identifiable versions.

Self-study, 45 to 90 minutes. Choose the path for your operating system. Installation instructions checked on 15 October 2026.

This unit is the common preparation for the course and is separate from the six 60-minute sessions. It covers installation, sign-in and a first file task. Each session also has its own preparation requirements for additional tools and materials. Students who currently have access to only one agent should still complete the first file task with that agent.

The first installation should begin a day in advance to allow for downloads and errors. Session handovers and the assessment of output reliability are taught in class; no complex configuration is expected beforehand.

Web chat, desktop apps and command-line tools

The Claude and ChatGPT web interfaces are suited to answering questions. The local versions, Claude Code and Codex, can also read and write project files and run programs on the user’s computer. This unit covers both the desktop apps and the command line. The desktop app makes outputs easy to inspect; the command line is used for automated execution in Session 4.

Confirm before starting that the account has the required access. Subscription sign-in and API-key sign-in are billed through different channels. The course uses official account sign-in and does not require the purchase of API credit. The plan and organization shown on the sign-in screen are the definitive confirmation.

For the desktop apps, start from Claude Code Desktop and the Codex quickstart, and choose the installer offered for your system. On macOS, drag the app into Applications; on Windows, follow the official installer. After installation, choose a local project and locate the task view that shows the working directory. Linux users can proceed directly to the command-line route below.

Windows: install in PowerShell

Step 1: open the correct terminal

Search for PowerShell in the Start menu and open a normal user window. The prompt usually begins with PS C:\. Run the following installation commands in PowerShell.

Users who normally work in Git Bash or WSL should choose one environment and carry out both installation and startup in it. Windows and WSL each have their own programs, PATH and user directory.

Step 2: install Claude Code

Following Anthropic’s official installation guide, paste:

irm https://claude.ai/install.ps1 | iex

The download may produce no output for some time. Wait for the prompt to return, close the window, open a new PowerShell window and check:

claude --version
Get-Command claude

The first command should report a version number and the second the location of the executable. The native Claude Code installation is placed in the user directory. If the Bash tool is needed, install Git from the Git for Windows site, then confirm:

git --version

Current versions of Claude Code can use PowerShell as the shell tool when Git for Windows is not installed. When later sessions involve Bash scripts, check the runtime environment at that point; see the official guide.

Step 3: install Codex

In the same PowerShell environment, run the official installer:

irm https://chatgpt.com/codex/install.ps1 | iex

Reopen PowerShell and check:

codex --version
Get-Command codex

The official standalone installer installs Codex directly, without a prior Node.js installation. Users with a working npm setup may instead use npm install -g @openai/codex, as listed in the official documentation. Use only one installation method per machine, so that PATH does not find an older copy first. See the installation instructions in Codex CLI.

Step 4: correct PATH when a command is not found

PATH is the list of directories in which the terminal searches for programs. First check whether the files exist:

Test-Path "$env:USERPROFILE\.local\bin\claude.exe"
Test-Path "$env:LOCALAPPDATA\Programs\OpenAI\Codex\bin\codex.exe"

If they exist, add their directories to the current window and try again. These are the default directories of the Claude and Codex standalone installers:

$env:Path = "$env:USERPROFILE\.local\bin;$env:LOCALAPPDATA\Programs\OpenAI\Codex\bin;$env:Path"
claude --version
codex --version

If the commands now work, the problem lies in the persistent PATH. Search for environment variables in the Start menu, open the Environment Variables window and edit Path under the user variables in the upper half. Click New and add Claude’s C:\Users\YourName\.local\bin (with your own user name) and Codex’s %LOCALAPPDATA%\Programs\OpenAI\Codex\bin as separate entries, keep the existing entries and save. Reopen the terminal and check again.

If Test-Path returns False, return to the installation log to establish the actual installation location and download result. For Codex installed with npm, run npm config get prefix and check whether the global directory it reports is in the user Path. Do not replace the whole PATH with a single new directory.

Step 5: open the exercise directory

Download the Lesson 0 materials

Unzip the archive into an agent-course folder and locate the level that contains notes.md. Open a terminal at that level from File Explorer, or type the actual path in PowerShell:

Set-Location "$env:USERPROFILE\Documents\agent-course\lesson-0"
Get-Location
Get-ChildItem
claude

Keep the double quotes when the path contains spaces. If the folder is on the Desktop or in OneDrive, use the location shown in File Explorer’s address bar.

Native Codex on Windows has its own sandbox configuration. If an organization policy or system component error appears, check the system version and error code against the official Windows troubleshooting page. Users who need a Linux toolchain can enable WSL and follow the Linux route; an existing Windows installation does not become a WSL installation automatically.

macOS: install in Terminal

Step 1: open a terminal and check the system

Press Command and Space, search for Terminal and press Return. First run:

sw_vers
uname -m
echo "$SHELL"

arm64 indicates Apple silicon and x86_64 indicates Intel. The installers select the appropriate program; for the desktop apps, the chip and system requirements on the download page are authoritative.

Step 2: install both command-line tools

Users who already use Homebrew can install with it, running the two commands separately:

brew install --cask claude-code
brew install --cask codex

Without Homebrew, the official standalone installers are more direct:

curl -fsSL https://claude.ai/install.sh | bash
curl -fsSL https://chatgpt.com/codex/install.sh | sh

Choose one of the two routes. See Claude Code installation and Codex CLI installation. When installation finishes, open a new terminal window:

claude --version
codex --version
command -v claude
command -v codex

Step 3: configure PATH

The standalone installers usually place their entry points in ~/.local/bin. If the program exists but the command is not found, first correct only the current window:

export PATH="$HOME/.local/bin:$PATH"
claude --version
codex --version

Once this works, open ~/.zshrc in a text editor, add the same line once at the end, then run:

source ~/.zshrc

Bash users edit ~/.bashrc instead; for login shells, also check whether ~/.bash_profile loads it. After a Homebrew installation, find the actual prefix with brew --prefix and configure the shell as Homebrew recommends, so that the Apple silicon and Intel directories are not confused.

Step 4: open the exercise directory

Download and unzip the Lesson 0 materials and locate the folder that contains notes.md. Type cd in the terminal, drag the folder from Finder into the terminal and press Return, or type the actual path:

cd "$HOME/Documents/agent-course/lesson-0"
pwd
ls
claude

Linux: prepare the user environment first

The examples below use Ubuntu or Debian. On other distributions, install curl and Git with the distribution’s package manager. On shared servers, use the base environment provided by the administrator.

sudo apt update
sudo apt install curl git ca-certificates

These two commands change system software and must be authorized by the user. The agents are then installed in the user directory:

curl -fsSL https://claude.ai/install.sh | bash
curl -fsSL https://chatgpt.com/codex/install.sh | sh
export PATH="$HOME/.local/bin:$PATH"
claude --version
codex --version

Add the PATH line to ~/.bashrc once, reopen the terminal and check. Zsh users edit ~/.zshrc. If installation fails, check the distribution and CPU requirements on the official pages first; environments such as Alpine have different dependencies, and Ubuntu package names do not carry over.

Unzip the exercise materials and open the directory that contains notes.md:

cd "$HOME/agent-course/lesson-0"
pwd
ls

First task: producing and checking meeting minutes

This task introduces the division of labor used throughout the course: one agent produces an output from a source file, and a second agent checks that output against the source without modifying it. In Claude Code, send:

Read notes.md and turn these group meeting notes into minutes.md.
Write the decisions made, each person's to-dos and their deadlines as separate parts. Where the notes give no date, write TBD.
When done, tell me where the output is and list one ambiguity you found in the original notes.

Open minutes.md and check that the people, dates and decisions all come from the original notes. Then open Codex, select the same project and send:

Check minutes.md against notes.md for omissions and decisions that were invented.
Write your review only to check.md; do not change the minutes. Name the files you reviewed and where each problem is.

This is the handover pattern used in every later session: the original remains in its own file, the product is saved separately, and the reviewer checks an explicitly identified version. When a task changes, the current agent writes the next step into a file before a new session is opened.

Common errors, by symptom

Symptom Check first Action
irm not recognized Whether the terminal is CMD or Bash Run the installation command in PowerShell
command not found or command not recognized Whether the file was downloaded, and where the current PATH points Verify with the full path first, then correct the user PATH
codex.ps1 blocked by execution policy Whether it was installed with npm Start it with codex.cmd for now, or switch to the official standalone installer; refer organization policy to the administrator
Download timeout, 403 or certificate error Whether the official address opens in a browser and whether the system clock is correct Check the university network and proxy settings and keep the error code; do not switch to an installation script of unknown origin
Permission denied or EACCES Whether a system directory is being written, and who owns the old installation Install in the user directory or correct the permission of the specific directory, keeping a backup of the configuration
Terminal still not signed in after sign-in Whether the browser used the correct account, and whether the callback returned to this machine Retry once as the official prompt instructs; on remote machines, check supported methods such as device code
401 or 403 on model calls Sign-in channel, organization permissions and account eligibility Check against the authentication documentation, and keep installation success distinct from service availability
The same command reports different versions Whether more than one installation is on PATH On Windows use Get-Command codex -All, on macOS and Linux type -a codex; settle on one installation source

Diagnosis for Claude Code can begin with claude doctor; further symptoms are covered in the official troubleshooting guide. For Codex, check session settings with /status, then consult the CLI docs. Keep the error text and version numbers, and remove credentials before passing them to an agent.

Common errors and corrections

Treating a successful installation as a usable environment. A version number shows only that the program starts. Complete one read-and-write task after sign-in; the check passes only when the file is written to the intended directory.

Overwriting existing configuration while correcting PATH. An attempt to add one directory can empty the original Path. Keep the original value before editing, and verify in a new terminal after adding the directory.

Two agents editing the same minutes concurrently. The checking task writes only the check file; corrections return to the original author. Only one session writes to a given output at a time.

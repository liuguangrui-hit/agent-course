5.2 Hooks 与密钥

课后深入，约 30 分钟。

AGENTS.md 里的约定，Agent 多数时候照做，偶尔会忘。对必须每次都做的检查，靠它记得不够。Hook 是在特定时刻一定会运行的脚本，把检查从约定变成机制。这一节也讲密钥：Agent 要用到很多账号，密钥放哪里，泄露了怎么办。

Hook 的几个时刻

时刻 典型用法
运行一个工具之前 推送前查密钥；拦下某类命令
运行一个工具之后 改完文件跑格式化或核对脚本
你发出一句话时 自动附上当天的状态
Agent 每答完一次，或整个会话结束时 检查有没有留下未提交的改动

运行之前的 Hook 可以阻止这次操作，并把理由告诉 Agent；运行之后的 Hook 可以把检查结果交给 Agent，要求它修正。

写一个 Hook

改完论文自动核对数字。Hook 挂在编辑文件之后，只在改的是 .tex 时才运行：

{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [{ "type": "command", "command": "python3 hooks/check_tex.py" }]
      }
    ]
  }
}

check_tex.py 从标准输入读到这次改的是哪个文件，不是 .tex 就直接退出；是的话运行第 1 课的 check_numbers.py，有对不上的数字就把原因写到错误输出，以退出码 2 退出。退出码 2 是约定好的信号：Agent 会看到这段原因并去修正。其他非零退出码只算 Hook 自己出错，Agent 看不到原因。

写 Hook 交给 Agent 就行：

写一个 Hook：每次编辑 paper/ 下的 .tex 文件之后运行 code/check_numbers.py，对不上时把结果告诉你并要求修正。
按当前官方文档的格式挂进 .claude/settings.json，写完故意改错一个数字测试它。

Codex 也支持 Hook，配置写法不同，同样让它按自己的文档写。

这个 Hook 只盯 Agent 用编辑工具改的文件，Agent 用命令改的文件它看不到。所以它是随手提醒，最终那一道核对放在提交或收工时再跑一次全量的 check_numbers.py。

Hook 要快

Hook 在每次对应事件时都运行。一个要跑两分钟的检查挂在每次编辑之后，Agent 的每一步都会被拖住。几秒内跑完的检查才挂 Hook；慢的检查，比如重跑整个实验，放进收工流程。

密钥放在哪

Agent 会用到 GitHub 的令牌，各种 API Key，服务器的登录。原则只有一条：值不出现在对话里，也不进仓库。

放在哪 怎么用
系统钥匙串 由命令行工具自己读取，比如 gh 登录后的令牌
项目里的 .env，列入 .gitignore 脚本启动时自己加载 .env，拒绝表禁止 Agent 读这个文件
SSH 密钥 留在 ~/.ssh/，拒绝表禁止 Agent 读这个目录

让 Agent 帮你配置时，告诉它变量名，值由你自己填进文件，不要贴进对话。

登录网站也是同样的道理。第 2 课让 Agent 用浏览器下载论文，你自己在浏览器里登录一次，Agent 沿用登录状态，它从头到尾不需要知道密码。

推送前查密钥

写一个 Hook：每次运行 git push 之前，用 gitleaks 扫描这次要推送的提交，发现疑似密钥就阻止推送，并告诉你是哪个文件哪一行。

gitleaks 偶尔会误报，比如一串像密钥的测试数据。误报时把那一行加进它的忽略清单，不要关掉整个检查。

泄露了怎么办

密钥一旦推到 GitHub，即使下一次提交就删掉，历史里也还在，公开仓库几分钟内就可能被自动扫描到。顺序是：

  1. 立刻到对应的网站作废这个密钥，生成新的；
  2. 新密钥放进 .env 或钥匙串；
  3. 再考虑清理历史。

第一步最重要。清理历史很麻烦，而且不能保证没人已经拿到；作废了的密钥，拿到也没用。

练习

给你的工作台加第三道检查：每次 Agent 答完，如果有未提交的改动，提醒 Agent 提交或者说明为什么不提交。

最容易出错的地方

关键检查写在 AGENTS.md 里。 多数时候照做，偶尔会忘，忘的那次就出事。每次都必须做的检查交给 Hook。

误报一次就关掉检查。 一次误报后整个 Hook 被删掉，下次真的有密钥就没人拦了。误报的那一行加进忽略清单。

泄露后先删提交。 花半小时清理历史，密钥这期间一直有效。先作废，再清理。

5.2 Hooks and secrets

Self-study, about 30 minutes.

The agent usually follows AGENTS.md conventions, but sometimes forgets. Memory is not enough for checks that must run every time. A Hook is a script that always runs at a specific moment, turning a convention into a mechanism. This section also covers secrets: the agent uses many accounts, so where do keys live, and what if one leaks?

Hook events

Event Typical use
Before a tool runs Scan for secrets before pushing; block a kind of command
After a tool runs Format files or run a checking script after edits
When you send a message Attach today’s state automatically
After each agent response, or when the session ends Check for uncommitted changes

A pre-run Hook can block the action and tell the agent why. A post-run Hook can return check results and require a fix.

Writing a Hook

Check numbers automatically after paper edits. Attach the Hook after file editing and run it only for .tex files:

{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [{ "type": "command", "command": "python3 hooks/check_tex.py" }]
      }
    ]
  }
}

check_tex.py reads the edited filename from standard input. If it is not .tex, it exits. Otherwise it runs Session 1’s check_numbers.py. If numbers do not match, it writes the reason to standard error and exits with code 2. Exit code 2 is the agreed signal: the agent sees the reason and fixes it. Other nonzero codes count only as a Hook failure, and the agent does not see the reason.

Let the agent write the Hook:

Write a Hook that runs code/check_numbers.py after every edit to a .tex file under paper/. If numbers don't match, return the results to you and require a fix.
Connect it in .claude/settings.json using the current official documentation's format. Then deliberately change a number to an incorrect one to test it.

Codex also supports Hooks with different configuration syntax. Have it follow its own documentation too.

This Hook watches only files changed with the agent’s editing tools, not changes made through commands. Treat it as a quick reminder. Run a full check_numbers.py again at commit or wrap-up for the final check.

Keep Hooks fast

A Hook runs on every matching event. A two-minute check after each edit holds up every step. Attach only checks that finish in a few seconds. Slow checks, such as rerunning the whole experiment, belong in wrapping up.

Where secrets live

The agent uses GitHub tokens, API keys and server logins. One rule: values stay out of conversations and repositories.

Location How to use it
System keychain Command-line tools read it themselves, such as gh’s token after login
A project .env listed in .gitignore Scripts load .env at startup; deny rules stop the agent reading it
SSH keys Keep in ~/.ssh/; deny rules stop the agent reading the directory

When the agent helps configure this, tell it variable names. Fill values into the file yourself; do not paste them into the conversation.

Website login follows the same principle. In Session 2 you sign in once in the browser, and the agent reuses that state to download papers. It never needs to know the password.

Scan for secrets before pushing

Write a Hook: before each git push, use gitleaks to scan the commits being pushed. Block the push if it finds a suspected secret, and tell you the file and line.

gitleaks sometimes flags a false positive, such as test data that looks like a key. Add that line to its ignore list rather than disabling the check.

When a secret leaks

Once a key reaches GitHub, deleting it in the next commit leaves it in history. Automated scanners may find it in a public repository within minutes. In order:

  1. Revoke the key on the relevant site at once and generate a new one;
  2. Put the new key in .env or the keychain;
  3. Then consider cleaning the history.

The first step matters most. Cleaning history is difficult and cannot guarantee nobody already got the key. A revoked key is useless even if someone has it.

Exercise

Add a third check to your workbench: after each agent response, if there are uncommitted changes, remind it to commit or explain why it is not committing.

Where agents go wrong most

Critical checks only in AGENTS.md. Usually followed, sometimes forgotten, and the missed check is when things go wrong. Give checks that must run every time to Hooks.

Disabling a check over one false positive. Delete the whole Hook and the next real secret has nothing to stop it. Add the false-positive line to the ignore list.

Deleting commits before revoking a leaked key. Half an hour cleaning history leaves the key active the whole time. Revoke first, clean later.

课程大纲

课程目标

面向研究生和带研究生的老师。让有科研经验但近年少写代码的人，能指挥 Claude Code 与 Codex 这类 Agent 写稿、读文献和做实验，并把这些步骤接成能自己运行的流程。

完成课程后，你能够：

  1. 为一个科研任务建项目文件夹，用文件把材料、约定和产物交代给 Agent。
  2. 用 Agent 把一篇论文从题目到结论整体重讲，把实验数据画成能投稿的图，让另一家的 Agent 审稿，并把这套做法做成 Skill。
  3. 用 Agent 把一批论文整理成可追溯的知识库，从中提出能检验的问题。
  4. 指挥 Agent 在本机或远程服务器上完成一次能重跑的实验，读懂结果能说明什么。
  5. 把以上步骤接成定时运行的流程，认出 Agent 最常见的几类失败，并为每类加上检查。

每堂课分两部分。课堂核心 60 分钟，讲这一课最重要的一件事并当堂做出来；课后深入是几节自学内容，每节 25 到 45 分钟，讲清原理，给出更多任务卡，练习和参考答案。时长可按现场微调。四堂必修按顺序上，后一堂会用到前一堂做出的东西；两堂选修在第四堂之后任选。

每堂课怎么上

时间 做什么
开课第 1 分钟 发出装工具任务卡：Agent 在后台装这一课的工具
0 至 5 分钟 看成品：先看这堂课最后要做出来的东西
5 至 15 分钟 讲：这一课的做法，以及新装的工具让 Agent 多了什么本事
15 至 50 分钟 做：三段练习，每段先演示，再各自动手
50 至 55 分钟 最容易出错的地方
55 至 60 分钟 回顾要点，看一眼工作台多了什么，布置用自己的材料再做一遍

讲的部分不超过十分钟，其余时间都在动手。装工具和讲课同时进行：任务卡开课就发，Agent 装的时候你在听讲，装完它会自己验证一遍，并把用法写进项目的 AGENTS.md。需要你本人登录或授权的几步，GitHub，图书馆，服务器，最好课前先确认账号能用。每段练习给一张任务卡，复制给 Agent 就能开始。任务卡都写清四件事：读什么，做什么，存到哪，做到哪里停。

考核

每堂课带走的成果就是作业，课后换成自己的材料再做一遍。结课作品是用自己的课题搭一个小工作台：包含前四堂的产物，在一次无人值守的运行之后交出一个结果页面。

需要准备

  • 一台 Mac 或 Windows 电脑。
  • Claude 的 Pro 或以上订阅，和含 Codex 的 ChatGPT 套餐。第 1 课起一家写，另一家审；只有一家的，审稿那一步用同一家开一个只读稿件的新对话代替，效果差一些。
  • 第 2 课：学校图书馆的机构登录账号，用来让浏览器替 Agent 拿订阅论文的全文。
  • 第 3 课：一个 GitHub 账号；最好有一台能 SSH 登录的服务器，没有的话用本机也能完成。
  • 第 4 课：手机上装好 Claude 应用或者一个能收推送的通知应用。
  • 其余工具都是免费软件，课上由 Agent 自己装。

Syllabus

Aim

For graduate students and the people who supervise them. Researchers who know their field but have not written much code lately learn to direct agents such as Claude Code and Codex through writing, reading the literature and running experiments, and to join these steps into a workflow that runs on its own.

By the end of the course you will be able to:

  1. Set up a project folder for a research task and use files to hand an agent its material, conventions and outputs.
  2. Use agents to retell a paper from title to conclusion, redraw its experimental data as submission-ready figures, have another vendor’s agent review it, and package the method as a Skill.
  3. Use agents to turn a set of papers into a traceable knowledge base and draw testable questions from it.
  4. Direct an agent through a rerunnable experiment, locally or on a remote server, and read what the result does and does not show.
  5. Join these steps into a scheduled workflow, recognise the most common ways agents fail, and add a check for each.

Each session has two parts. The 60-minute core class covers the one thing that matters most and builds it in the room. Self-study sections follow, 25 to 45 minutes each, with the reasoning, more task cards, exercises and answers. Timings can shift a little on the day. The four core sessions run in order, since each uses what the previous one built. The electives can follow session four in either order.

How a session runs

Time What happens
First minute Send the tool installation task card: the agent installs this session’s tools in the background
0 to 5 min See the finished product the session builds toward
5 to 15 min Talk: the method, and what the new tools let the agent do
15 to 50 min Do: three exercises, each a short demo then hands-on
50 to 55 min Where agents go wrong most
55 to 60 min Key points, what the workbench gained, and redoing it on your own material

Talking takes at most ten minutes; the rest is hands-on. Tool installation happens alongside the talk: send the card at the start, listen while the agent installs, and let it test the tools and write their use into the project’s AGENTS.md. For steps that need your login or authorization, such as GitHub, the library and the server, check your accounts work before class. Each exercise comes with a task card you paste to the agent. Every card says four things: what to read, what to do, where to save it, and where to stop.

Assessment

What you build in each session is the assignment; afterwards, redo it with your own material. The final piece is a small workbench for your own research topic. It holds the outputs of the four core sessions and, after one unattended run, produces a results page.

What you need

  • A Mac or Windows computer.
  • Claude Pro or above, and a ChatGPT plan that includes Codex. From Session 1, one vendor writes and the other reviews. If you have only one, use a new conversation with the same vendor that reads only the draft for the review; it works less well.
  • For Session 2: your university library’s institutional login, so the browser can get subscription full texts for the agent.
  • For Session 3: a GitHub account, and ideally a server you can SSH into. Without one, you can complete the work locally.
  • For Session 4: Claude on your phone or a notification app that can receive pushes.
  • All other tools are free software, installed by the agent during class.

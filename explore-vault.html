2.2 知识库怎么搭

课后深入，约 30 分钟。

知识库的用处是让下一次提问站在这一次的阅读上。它要同时满足两个读者：你，在 Obsidian 里翻；Agent，在文件夹里读写。两边读的是同一批 Markdown 文件，所以结构要简单到两边都不会走错。

文件夹结构

vault/
├── sources/        PDF 原件和 manifest.csv，只增不改
├── papers/         一篇论文一页笔记
├── concepts/       概念页，把论文连起来
├── templates/      笔记模板
├── conflicts.md    论文之间的分歧
└── questions.md    从知识库里提出的问题

在 AGENTS.md 里写清这几条：原件只增不改；论文页一篇一页，文件名和 PDF 对应；结论必须带页码；概念页只引用论文页，不直接引用 PDF。

论文页模板

---
title: A Closer Look at Memorization in Deep Networks
authors: Arpit et al.
year: 2017
source: sources/arpit2017.pdf   # 相对 vault/ 根目录
---
## 问题
## 设定
## 主要结果
- 结论一句话，数字。p. 页码
## 和本课题的关系

模板固定，Sub-agent 写出来的笔记格式就统一，后面合并和检索都省事。页码那一项最重要：没有页码的结论，过后很难复核。

概念页

论文页回答这篇论文说了什么，概念页回答关于这件事，现在知道什么。一页概念页的样子：

# 早停

一段综述：带噪标签下，网络在前几轮先拟合干净样本，之后才开始记住错误标签，所以按验证准确率选停止点，有望停在记住错误标签之前。
分歧在于验证集本身也带噪声时这个办法还灵不灵。

- [[arpit2017]]：先学规律后记噪声。
- [[liu2020]]：早期学习正则化，不靠停止点也能挡住记忆。
- ...

概念页的数量要少。三五个概念把十几篇论文连起来，比三十个概念各挂一篇论文有用。在 Obsidian 的关系图里，孤立的论文就是还没想清它和谁有关的论文。

分歧表

分歧是知识库里最值钱的部分，好问题大多从这里来。单独存一张表：

论文 A 论文 B 在什么设定下 A 说 B 说 可能的原因

可能的原因一栏让 Agent 填它的猜测，并标明是猜测。第 3 课挑问题时，先看这张表。

新论文进来

知识库会长大。每加一篇论文：

读 vault/papers/新论文.md。它和哪几个概念页有关？把它的结论合并进去：
如果它说的和已有内容一致，在已有条目后补一个链接，不重复写；如果是新内容，加一条；如果冲突，写进 conflicts.md。
不要在概念页末尾追加一段关于这篇论文的总结。

最后一句针对一个常见毛病：Agent 喜欢在末尾追加，几十篇之后概念页变成论文摘要的流水账。合并的要求是改写已有的综述，让它同时覆盖旧的和新的，并且不比原来长多少。

用 Obsidian 读

Obsidian 是免费的桌面应用，打开一个文件夹就是一个库。课上用到的只有三样：

  • 双链：[[文件名]] 跳到另一页，打开反向链接面板能看到谁链接了这一页。
  • 关系图：看哪些论文和概念连在一起，哪些孤立。
  • 搜索：全文搜一个词，比如一个数据集名，看哪些论文用过。

插件很多，课上不需要。Agent 不依赖 Obsidian 本身，它只读写文件；关掉 Obsidian 也照样工作。

练习

往练习 2 的知识库里加两篇你自己挑的论文，按上面的合并任务卡更新概念页。比较更新前后的概念页，看它是改写了综述还是在末尾追加。

如果它还是在末尾追加

在任务卡里给一个长度上限，比如综述段不超过一百五十字，并要求它先说明这篇论文改变了综述的哪一句。改不动综述的论文，只补链接。

最容易出错的地方

概念页变成流水账。 每篇论文在末尾追加一段，几十篇后没人读得下去。合并就是改写综述，不是追加。

概念太多。 每篇论文造两三个新概念，关系图里全是孤点。先用已有概念，实在装不下再新建。

直接改原件。 Agent 在 PDF 旁边写了一个同名笔记，或者为了提取文字把 PDF 转换覆盖了。原件只增不改，写进 AGENTS.md。

2.2 Building the knowledge base

Self-study, about 30 minutes.

A knowledge base lets your next question build on what you read this time. It serves two readers: you, browsing in Obsidian, and the agent, reading and writing in the folder. Both read the same Markdown files, so the structure needs to be simple enough for neither to get lost.

Folder structure

vault/
├── sources/        Original PDFs and manifest.csv; add, never change
├── papers/         One page of notes per paper
├── concepts/       Concept pages connecting papers
├── templates/      Note templates
├── conflicts.md    Disagreements between papers
└── questions.md    Questions drawn from the knowledge base

Put these rules in AGENTS.md: add originals, never change them; one page per paper, with a filename matching the PDF; every claim needs a page number; concept pages cite paper pages, not PDFs directly.

Paper page template

---
title: A Closer Look at Memorization in Deep Networks
authors: Arpit et al.
year: 2017
source: sources/arpit2017.pdf   # Relative to the vault/ root
---
## Question
## Setting
## Main results
- One-sentence conclusion, number. p. page number
## Relation to this topic

A fixed template keeps Sub-agents’ notes consistent and makes merging and searching easier. Page numbers matter most: a claim without one is hard to check later.

Concept pages

A paper page answers what this paper says. A concept page answers what we now know about this subject. An example:

# Early stopping

Overview: with noisy labels, networks fit clean samples in the first few epochs, then start memorizing wrong labels. Choosing a stopping point by validation accuracy may stop them before that memorization.
The disagreement is whether this still works when the validation set is noisy too.

- [[arpit2017]]: learns patterns before memorizing noise.
- [[liu2020]]: early-learning regularization can block memorization without a stopping point.
- ...

Keep concept pages few. Three to five concepts connecting a dozen papers are more useful than thirty concepts with one paper each. In Obsidian’s graph view, an isolated paper is one whose connections you have yet to work out.

Conflict table

Disagreements are the most valuable part of the knowledge base. Most good questions come from them. Keep a separate table:

Paper A Paper B Setting A says B says Possible reason

Have the agent put its guesses in the possible reason column and mark them as guesses. Start with this table when choosing a question in Session 3.

When a new paper arrives

The knowledge base grows. Each time you add a paper:

Read vault/papers/new-paper.md. Which concept pages does it relate to? Merge its conclusions into them:
If it agrees with existing content, add a link to the existing entry without repeating it. If it adds something new, add an entry. If it conflicts, record that in conflicts.md.
Don't append a summary of this paper to the end of a concept page.

The last line addresses a common habit: agents like appending, and after dozens of papers a concept page becomes a list of abstracts. Merging means rewriting the existing overview to cover both old and new work without making it much longer.

Reading with Obsidian

Obsidian is a free desktop app. Open a folder and it becomes a vault. The class uses only three features:

  • Wikilinks: [[filename]] jumps to another page. The backlinks panel shows who links to this page.
  • Graph view: see which papers and concepts connect, and which are isolated.
  • Search: search all text for a term, such as a dataset name, to see which papers used it.

There are many plugins, but you do not need them for class. The agent does not depend on Obsidian itself; it just reads and writes files. It works with Obsidian closed too.

Exercise

Add two papers you choose to the knowledge base from Exercise 2. Update the concept pages with the merge task card above. Compare the pages before and after: did it rewrite the overview or append to the end?

If it still appends to the end

Give a length limit in the task card, such as an overview paragraph of at most 150 characters, and ask it to say first which sentence the new paper changes. If a paper does not change the overview, add only a link.

Where agents go wrong most

Concept pages become a running list. A paragraph appended for every paper becomes unreadable after dozens. Merging means rewriting the overview, not appending.

Too many concepts. Two or three new concepts per paper leave the graph full of isolated points. Use existing concepts first; create a new one only when they do not fit.

Changing originals. The agent writes a note with the same name beside a PDF, or overwrites the PDF while converting it to extract text. Add originals, never change them. Put this in AGENTS.md.

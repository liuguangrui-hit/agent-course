1.2 数字从数据来

课后深入，约 30 分钟。用到第 1 课练习材料和参考答案。

Agent 改写论文时，最危险的不是文风，是数字。它会把 96.0 写成约 96.2，把 28.6 个点写成超过 30 个点；重跑实验以后，表格更新了，正文还停在旧数字上。这些错误语气通顺，读起来毫无破绽，靠读是读不出来的。

这一节给三道防线：数字从数据生成，脚本核对剩下的数字，同一个数各处同一种说法。

为什么读不出来

试一下：

读 paper/main.tex 和 data/results.csv，检查正文里的数字和数据是否一致。

Agent 多半会认真地读一遍，然后告诉你基本一致，也许顺手指出一两处。它可能漏掉摘要里的 96.2，因为 96.0 和 96.2 太接近，在一段通顺的文字里不扎眼。人读也一样。数字一致性是机械问题，应该交给机械的办法。

第一道防线：数字宏

让正文根本不手写结果数字。一个脚本从数据算出每个要报告的数，写成 LaTeX 宏：

% paper/numbers.tex，由 code/make_numbers.py 生成，不要手改
\newcommand{\ceFinalForty}{67.4}
\newcommand{\gceFinalForty}{96.0}
\newcommand{\gapGceCeForty}{28.6}

正文写 GCE ends at \gceFinalForty\%，编译出来就是 96.0%。表格也一样，由同一个脚本生成 table_main.tex，正文用 \input{table_main.tex} 引入。

这样一来，重跑实验后只要重新运行脚本再编译，正文，表格和图同时更新，不可能有一处还停在旧数字上。任务卡：

写 code/make_numbers.py：从 data/results.csv 和 data/curves.csv 计算论文里要报告的每个数，
写成 paper/numbers.tex 里的 \newcommand 宏，宏名能看出含义；再生成 paper/table_main.tex。
然后把 versions/v1/main.tex 正文里手写的结果数字全部换成宏，表格换成 \input，编译确认 PDF 里的数字不变。

参考答案里的 code/make_numbers.py 是一种写法，六十行左右。

第二道防线：核对脚本

有些数字不适合做成宏，比如摘要里四舍五入到整数的 16 个点，或者 Agent 重讲时临时算出的差值。对这些，用脚本把正文里每一个百分数和点数找出来，到数据里找对应：

写 code/check_numbers.py：从一个 .tex 文件里找出所有百分数和点数，
逐个到 data/ 的汇总值里找对应，对不上的列出来，标明行号。
先在 paper/main.tex 上运行，再在 versions/v1/main.tex 上运行。

在初稿上，参考答案的脚本输出：

line 16: 96.2\% not found in the data
line 28: 30 percentage points not found in the data
2 unsupported number(s)

候选集要小。 这个脚本的思路是：从数据算出一组候选值，正文里的数要能在候选值里找到。我们第一版把每条平均曲线第 1 轮的准确率也放进了候选，结果漏掉了 96.2：交叉熵在 20% 噪声下第 1 轮的平均准确率恰好是 96.24，而这个数论文里从未报告。候选越多，错误的数碰巧对上的机会越大。只放论文实际报告的那几类量。

第三道防线：同一个数，同一种说法

脚本只能查数值，查不了意思。重讲时，a quarter of ideas on other subjects 变成 a quarter of all ideas study another topic，数字都是 25%，分母已经换了。规则很简单：一个数第一次出现时怎么说，摘要，引言，图注和正文就都怎么说。让审稿的 Agent 专门查这一项：

列出 versions/v1/main.tex 里每个出现两次以上的数字，把每次出现的整句并排列出，指出主语或分母不一致的地方。

一条命令重建整篇论文

数字宏的好处要靠流程兑现。把实验，生成数字，画图和编译串成一条命令：

写一个 Makefile，make paper 依次运行 make_numbers.py，plot_paper.py 和 latexmk，
make check 运行 check_numbers.py。告诉我每个目标依赖哪些文件。

以后任何人拿到这个文件夹，一条 make paper 就能从数据得到同一份 PDF。第 3 课在服务器上重跑实验时，你会用到它。

练习

把 data/ 里 GCE 的一个种子的结果故意改掉一点，重新运行 make paper，看看 PDF 里哪些数字变了，再运行 make check。然后把数据改回来。

会发生什么

用了数字宏的地方，正文和表格会一起变；check_numbers.py 不报错，因为数字就是从新数据来的。没有改成宏，仍然手写的地方，make check 会把它列出来。这正是两道防线的分工：宏保证一致，脚本抓住漏网的。

最容易出错的地方

重跑实验后正文没跟上。 表格是新的，摘要还是旧数字。只要有一个数是手写的，这种事迟早发生。结果数字一律走宏。

差值先四舍五入还是后四舍五入。 表里 GCE 83.8，CE 47.2，读者心算差值是 36.6；用原始均值算是 36.7。两种都对，但论文里只能有一种。约定差值由表中的数相减，参考答案的脚本就是这样生成 \gapGceCeSixty 的。

百分数和百分点混用。 从 67.4% 到 96.0% 是提高 28.6 个百分点，不是 28.6%。Agent 经常混写，核对脚本要把两种说法都抓出来。

Agent 自己补数字。 摘要要求每个发现带一个数，手头没有现成的，它会算一个，甚至编一个看起来合理的。每个新出现的数字都要能追到 data/ 里。

延伸阅读

  • Ten Simple Rules for Reproducible Computational Research：Sandve 等人，PLoS Computational Biology，2013。
  • latexmk：自动处理多次编译和引用的 LaTeX 构建工具。

1.2 Numbers come from data

Self-study, about 30 minutes. Uses the Session 1 materials and answers.

When an agent rewrites a paper, style is the smaller risk. The real danger is the numbers. It turns 96.0 into about 96.2 and 28.6 points into over 30 points; after you rerun the experiments, the table gets updated and the text stays on the old numbers. These errors read smoothly and leave no trace on the page, so no amount of reading finds them.

This section gives three lines of defense: generate numbers from the data, check the remaining numbers with a script, and phrase the same number the same way everywhere.

Why reading doesn’t catch them

Try it:

Read paper/main.tex and data/results.csv and check whether the numbers in the text match the data.

The agent will most likely read it all carefully and tell you it broadly matches, perhaps pointing out one or two things along the way. It can easily miss the 96.2 in the abstract, because 96.0 and 96.2 are so close that the difference doesn’t stand out in fluent text. People reading are no different. Number consistency is a mechanical problem, and it belongs to a mechanical method.

First line of defense: number macros

Keep hand-typed result numbers out of the text entirely. A script computes every number to be reported from the data and writes it as a LaTeX macro:

% paper/numbers.tex, generated by code/make_numbers.py. Do not edit by hand.
\newcommand{\ceFinalForty}{67.4}
\newcommand{\gceFinalForty}{96.0}
\newcommand{\gapGceCeForty}{28.6}

The text says GCE ends at \gceFinalForty\%, which compiles to 96.0%. Tables work the same way: the same script generates table_main.tex, and the text pulls it in with \input{table_main.tex}.

Now when you rerun the experiments, you rerun the script and recompile, and the text, the tables and the figures all update together. No place can be left behind on an old number. The task card:

Write code/make_numbers.py: compute every number the paper reports from data/results.csv and data/curves.csv,
and write them as \newcommand macros in paper/numbers.tex, with macro names that show what each one means; also generate paper/table_main.tex.
Then replace every hand-typed result number in the text of versions/v1/main.tex with a macro and the table with \input, and compile to confirm the numbers in the PDF are unchanged.

The code/make_numbers.py in the answers is one way to write it, about sixty lines.

Second line of defense: a checking script

Some numbers don’t suit a macro, such as the 16 points rounded to a whole number in the abstract, or a difference the agent works out on the spot while retelling. For these, use a script to find every percentage and point difference in the text and look for its match in the data:

Write code/check_numbers.py: find every percentage and point difference in a .tex file,
look each one up among the summary values from data/, and list the ones that don't match, with line numbers.
Run it on paper/main.tex first, then on versions/v1/main.tex.

On the draft, the script in the answers prints:

line 16: 96.2\% not found in the data
line 28: 30 percentage points not found in the data
2 unsupported number(s)

Keep the candidate set small. The script works like this: it computes a set of candidate values from the data, and every number in the text has to be found among them. Our first version also put the epoch-1 accuracy of every mean curve into the candidates, and it missed the 96.2: the mean epoch-1 accuracy of cross-entropy at 20% noise happens to be 96.24, a number the paper never reports. The more candidates, the better the odds that a wrong number matches one by chance. Include only the kinds of quantities the paper actually reports.

Third line of defense: same number, same wording

A script can check values. It cannot check meaning. In a retell, a quarter of ideas on other subjects becomes a quarter of all ideas study another topic; both are 25%, and the denominator has changed. The rule is simple: however a number is phrased the first time it appears, the abstract, the introduction, the captions and the body all phrase it the same way. Have the reviewing agent check exactly this:

List every number that appears two or more times in versions/v1/main.tex, show the full sentence for each occurrence side by side, and point out where the subject or the denominator differs.

Rebuild the whole paper with one command

Number macros pay off only through the workflow. Chain the experiment, number generation, plotting and compilation into one command:

Write a Makefile where make paper runs make_numbers.py, plot_paper.py and latexmk in that order,
and make check runs check_numbers.py. Tell me which files each target depends on.

From then on, anyone who gets this folder can run one make paper and get the same PDF from the data. You will use it in Session 3 when you rerun experiments on a server.

Exercise

Deliberately change the result of one GCE seed in data/ a little, rerun make paper, see which numbers in the PDF change, then run make check. Afterwards, change the data back.

What happens

Wherever macros are used, the text and the table change together; check_numbers.py reports nothing, because the numbers come straight from the new data. Any place still typed by hand, with no macro, gets listed by make check. That is exactly how the two lines of defense divide the work: macros keep numbers consistent, and the script catches whatever slips through.

Where agents go wrong most

The text falls behind after a rerun. The table is new and the abstract still has the old number. As long as even one number is typed by hand, this happens sooner or later. Every result number goes through a macro.

Rounding a difference before or after. The table has GCE at 83.8 and CE at 47.2, so a reader works out a gap of 36.6; from the raw means it is 36.7. Both are correct, and the paper gets to use only one. Agree that differences are computed from the numbers in the table; that is how the script in the answers generates \gapGceCeSixty.

Mixing percent and percentage points. Going from 67.4% to 96.0% is a gain of 28.6 percentage points. It is not a 28.6% gain. Agents often mix the two, so the checking script has to catch both phrasings.

The agent supplies its own numbers. Asked for one number per finding in the abstract, with none ready to hand, it computes one, or even invents one that looks plausible. Every new number has to trace back to data/.

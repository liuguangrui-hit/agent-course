6 编排理论

把闭源 Agent 作为不可改动的原点，定义它之外的可学习对象。写清策略、回报和更新规则，再设计能区分经验收益与提示效应的实验，给出下一批任务上的可检验预测。

选修课。课前完成准备，课上 60 分钟，课后先复习再选做深入。

课前预备 · 课上一小时 · 课后复习与拔高

第 4 课留下了一张经验榜。把它交给新会话，Agent 可能改变做法；换一家 Agent，同一条经验又可能没有用。权重没有动，改变究竟发生在哪里？

本课从这里讨论学习。Claude Code 和 Codex 这类完整 Agent 由厂商提供，包含模型、工具接口与执行循环。研究者能控制的部分在它外面：给什么经验，怎样选择任务，怎样依据结果更新。

下载第 6 课材料

课上一小时

从一条冒烟测试经验开始，10 分钟

先确认材料能读，把课前带来的经验放到白板上，再一起定义学习过程。

回到第 4 课那条经验：实验输出格式变了，短运行后检查每列和行数，再提交正式任务。

让同一个 Agent 接到一项新实验。它先读当前经验榜，写出测试程序，运行器检查结果文件。若漏掉了必需列，回报记零；结构检查全部通过，回报记一。更新器读这次失败，把经验改得更具体，例如要求同时核对列名与每列的有限值。

下一项任务换了数据和输出格式，Agent 再读修改后的榜。我们要测的是，这份经验能否让它在新任务上少犯同类错误。做事的 Agent 保持不动，行为依据和更新规则保存在它外面。

学习过程的形式化，5 分钟

把固定版本的闭源 Agent 记作 𝒜v\mathcal A_v，刚才那张经验榜记作 BB。新实验的材料是 xx，Agent 给出的测试程序是 yy：

y∼𝒜v(⋅∣x,B).y\sim\mathcal A_v(\cdot\mid x,B).

运行器给出回报 rr，更新器 UϕU_\phi 把榜改为下一版：

Bt+1=Uϕ(Bt,xt,yt,rt).B_{t+1}=U_\phi(B_t,x_t,y_t,r_t).

不同的 BB 让同一原点形成不同策略。经验独立保存，就能交给另一家 Agent 再测。原点在两个地方都作参照：它是系统不修改的执行单元，无经验时的表现又是测量学习增量的零点。

内环与外环，5 分钟

内环根据回报改这条经验，目标是减少以后任务的漏检。策略参数是一份离散文本，更新器在文本空间搜索。这个问题可以表述为强化学习，回报怎样影响更新是检验的重点。

外环改的是合并与淘汰经验的规则。例如原先每次失败都加一条，现在改成先合并相近条目，再用验证任务决定保留。这一层在改变学习算法，对应自进化。评价器继续使用同一套检查和最终确认任务，改进才有共同参照。

刚才每项格式检查只给一次回报，下一项任务由外部给定，最小结构接近情境老虎机。真正研究里，选实验会改变已知证据，后续动作也随之改变，这时进入序贯决策与延迟回报。深入页会把两种目标分别写出来。

三组比较与效应分解，10 分钟

每个未见任务分别运行目标经验，匹配安慰剂和无经验三组。记平均回报为 J(B)J(B)，J(P)J(P) 与 J(⌀)J(\varnothing)：

J(B)−J(⌀)=[J(B)−J(P)]+[J(P)−J(⌀)].J(B)-J(\varnothing) =[J(B)-J(P)]+[J(P)-J(\varnothing)].

总效应回答带这张榜比原点自身高多少。第一项比较内容，第二项呈现匹配安慰剂带来的变化。等式总成立；第一项能否解释为学到的知识，取决于安慰剂是否配平了格式、篇幅和其他非特异作用。

还要检查学习信号。另学一张榜，训练时打乱任务与回报的对应，其他预算相同。两张榜都在正常未见任务上评估，才能判断改进是否依赖正确反馈。

练习一，写出自己的学习对象，10 分钟

选一个科研行为，例如根据实验设置提出可区分的假设。
定义任务输入，原点版本，可改经验与不可改评价规则。
写一次输出、一次回报和一次经验更新的例子，只引用文件与指标。
判断任务属于单步还是序贯，并说明回报怎样指向前面的选择。

练习二，实际分析一份三组数据，10 分钟

运行 analyze_experience.py，逐项解释三组均值、配对内容差和总效应。
指出哪项比较支持什么判断，再检查原点版本改变后方向是否一致。
按 protocol.md 设计自己的小规模试验，固定任务、预算和失败处理。
把内容收益、回报依赖和迁移分别写成预测，各列一个能推翻它的结果。

检查与小结，5 分钟

常见错误与处理方法

写了更新公式，就认为收益必然上升。 给出更新器的选择依据，在未见任务上比较，收敛另需假设。

把使用声明当作条目贡献。 声明用于提出候选，贡献用消融或随机化干预检验。

同一张榜换版本，成绩直接并到一条曲线。 新版本另起统计段，保留桥接任务测漂移。

正反例辨析，20 分钟

先看一组假设数字：目标经验 0.64，匹配安慰剂 0.62，无经验 0.50。甲把全部 0.14 增量称为学到的知识。乙同时报告内容差 0.02 和安慰剂差 0.12，再检查配平、区间和正确反馈的作用。判断两种解读各需要哪些证据。再打开课堂 analyze_experience.py 的输出，用同一分解解释 design 行为在 origin-v2 下的结果，说明目标经验低于安慰剂时，甲的解释哪里不成立。若换原点后三组都提高，写出怎样比较旧经验是否仍有增量。

自己拆完三组，再看对照思路

0.14 是总效应，恒等分解给出 0.02 与 0.12。内容差要解释为知识收益，还要检查安慰剂是否配平，并估计不确定性与反馈依赖。课堂演算中 design 在 origin-v2 下的目标经验低于安慰剂，提示总效应不能代替内容差。跨原点分别用各自无经验和安慰剂组作参照，不能只比较目标经验的绝对分数。

6 Orchestration theory

How a system learns while the weights stay fixed

Treat a closed-source agent as a fixed origin, and define what the surrounding system can learn. Write out the policy, the reward and the update rule, then design an experiment that separates the gain from experience from prompt effects, and give a testable prediction on the next batch of tasks.

Elective. Prepare before class, spend 60 minutes in class, then review and choose an optional extension.

Before class · In class · After class: review and extension

Lesson 4 left you a playbook. Give it to a new session and the agent may change how it works; switch to another vendor’s agent and the same entry may be of no use. The weights did not move, so where did the change happen?

This is the starting point for the lesson’s account of learning. Complete agents such as Claude Code and Codex are provided by vendors and include the model, the tool interfaces and the execution loop. The part researchers can control lies outside: which experience to provide, how to choose tasks, and how to update from results.

Download the Lesson 6 materials

The exercise package has three groups of scores, a learning protocol and a usage ledger. The scores and the ledger are both synthetic worked-example data for practicing the analysis; real effects are measured by you, calling your own agent under the frozen protocol.

In class

Start with a playbook entry from a smoke test, 10 minutes

First confirm that the materials can be read, put the entry you brought on the whiteboard, then define the learning process together.

Go back to the entry from Lesson 4: when the experiment output format changes, check every column and the number of rows after a short run, then submit the real job.

Give the same agent a new experiment. It first reads the current playbook and writes a test program, and the runner checks the result file. If a required column is missing, the reward is zero; if the structure check passes entirely, the reward is one. The updater reads this failure and makes the entry more specific, for example by requiring both the column names and the finite values in each column to be checked.

The next task changes the data and output format, and the agent reads the revised playbook again. What we want to measure is whether this entry makes it commit fewer errors of the same kind on new tasks. The agent doing the work stays fixed; the basis for its behavior and the update rule are kept outside it.

Formalize the learning process, 5 minutes

Write the fixed-version closed-source agent as 𝒜v\mathcal A_v, and the playbook as BB. The material of the new experiment is xx, and the test program the agent gives is yy:

y∼𝒜v(⋅∣x,B).y\sim\mathcal A_v(\cdot\mid x,B).

The runner gives a reward rr, and the updater UϕU_\phi changes the playbook into the next version:

Bt+1=Uϕ(Bt,xt,yt,rt).B_{t+1}=U_\phi(B_t,x_t,y_t,r_t).

Different choices of BB induce different policies from the same origin. Because experience is kept separately, it can be handed to another vendor’s agent and tested again. The origin serves as the reference in two places: it is the execution unit the system does not modify, and its performance without experience is the baseline for measuring learning gains.

The inner and outer loops, 5 minutes

The inner loop changes this entry according to the reward, aiming to reduce misses on later tasks. The policy parameter is a discrete piece of text, and the updater searches in text space. This problem can be stated as reinforcement learning, and how the reward affects the update is the focus of testing.

The outer loop changes the rules for merging and retiring entries. For example, instead of adding an entry for every failure, first merge similar entries, then let validation tasks decide what to keep. This layer changes the learning algorithm, which is what self-evolution means here. The evaluator keeps using the same checks and final confirmation tasks, so improvements have a common reference.

Just now, each format check gave a single reward and the next task was given from outside, so the minimal structure is close to a contextual bandit. In real research, choosing an experiment changes the known evidence and the later actions change with it; this is where sequential decision-making and delayed reward come in. The deeper pages write out the two objectives separately.

Decompose the effects with three groups, 10 minutes

Each unseen task is run in three groups: target playbook, matched placebo and no playbook. Write their average rewards as J(B)J(B), J(P)J(P) and J(⌀)J(\varnothing):

J(B)−J(⌀)=[J(B)−J(P)]+[J(P)−J(⌀)].J(B)-J(\varnothing) =[J(B)-J(P)]+[J(P)-J(\varnothing)].

The total effect answers how much higher it scores with this playbook than the origin on its own. The first term compares content; the second shows the change brought by the matched placebo. The identity always holds; whether the first term can be interpreted as learned knowledge depends on whether the placebo balances format, length and other non-specific effects.

The learning signal also needs checking. Train another playbook with shuffled task–reward pairings during training, keeping the rest of the budget unchanged. Only when both playbooks are evaluated on normal unseen tasks can you judge whether the improvement depends on correct feedback.

Check and summary, 5 minutes

Common mistakes and how to fix them

Assuming the gain must rise because an update formula has been written. Give the updater’s basis for selection and compare on unseen tasks; convergence needs further assumptions.

Taking a usage claim as an entry’s contribution. Claims are for proposing candidates; contribution is tested with ablations or randomized interventions.

Merging scores of different versions of the same playbook into one curve. Start a new statistical segment for each new version, and keep bridging tasks to measure drift.

Workbench summary

The learnable object, updater and evaluator are now explicitly defined. The workbench can propose a way of learning, and can also state how it could be refuted. The final ledger exercise measures the resources required to obtain these gains.

Break down the three groups yourself, then see the comparison notes

Across origins, use each origin’s own no-playbook and placebo groups as references, rather than comparing only the absolute scores of the target playbook.

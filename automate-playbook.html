4.2 经验管理与评估

学习目标

  1. 把经验写成带适用条件、动作、来源与检验方式的条目，区分使用声明与因果贡献。
  2. 设计目标经验、匹配安慰剂与无经验三组对照，在未见任务上估计经验的总效应与内容差。
  3. 区分内环与外环更新，识别留出集复用和任务难度变化造成的虚假进步。

课后深入专题，约 70 分钟。

一次冒烟测试发现了缺失的数据列。Agent 把相应做法写入经验榜，下一轮也按此执行。这只说明经验被使用了；它是否减少了错误，还需要由下一批任务证明。

经验条目的构成

适用条件：实验输出格式发生变化
动作：短运行后检查所有预期列、行数与有限值，再提交正式执行版本
来源：哪轮任务出现何种失败，哪轮通过检查发现同类问题
测试：在之后未见任务上比较漏检率与新增耗时
状态：候选

有效的条目应明确下一次要检查什么。来源以链接形式记录，并保留当时的数据和失败记录。触发条件应能根据任务开始时可见的信息识别。

从回报到更新

把每次任务看作一次尝试。Agent 读取当前经验榜并选择做法，环境或检查器给出回报，更新器据此新增、合并或删除条目。

这里有两种不同的信号：作者声称使用了某条经验，以及带有这条经验时的实际表现。前者是使用声明，后者需要对照才能判断。使用声明可以用来提出消融候选，不能单独作为因果贡献的证据。

新增条目先进入候选集，经验证任务比较后保留，再在未参与选择的任务上评估。容量有限时删除冗余条目，并保留每条经验的具体适用条件。

三组对照评估

对同一批未见任务，三组分别带有目标经验、格式与长度匹配的安慰剂，或不带经验。三组的执行预算和评分规则相同，输出匿名并打乱顺序后交给冻结的评审。

目标经验减无经验得到总效应，目标经验减安慰剂得到匹配安慰剂条件下的内容差。安慰剂本身也可能有帮助或造成干扰，因此三组结果都要报告。6.2 节将进一步推导该设计能够识别什么。

留出一批从未用于写榜或挑榜的任务，冻结输入和评分。
每个任务独立跑三组，随机化执行顺序，记录原点版本、预算与失败。
按任务配对分析，报告三个均值、内容差与总效应及其区间。

规则变更与版本管理

更新经验内容属于内环，改变合并规则、容量或评分属于外环。外环有自己的训练与验证记录。若外环持续观察同一留出集的成绩，留出集也就参与了选择，最终还需要新的确认集。

反思检查可以提出新版本，但不能改写过去的评分。固定评估点，保留全部尝试，并把当前经验榜版本与学习规则版本一起记录。

研究问题与任务难度的核查

有些经验会使任务变得容易：只选择自己擅长的问题，把预测写得很宽泛，或在结果说明中回避主要比较。表面命中率因此升高。

复盘时应同时检查任务难度与问题尺度。比较每轮的问题与最初的问题，解释变化来自哪项证据。缺乏支撑的方向先列出补证实验，避免以更简单的问题替代真正的进步。

练习

选择一条自认为有效的经验，先写明它会改善哪类任务，再做一个小规模的三组试验。小样本只用于检查设计与波动，正式主张须按预期效应大小规划样本量。同时记录移除该条目后的差值，检验使用声明是否确实对应贡献。

常见错误与处理方法

每次成功都写成通则。 保存具体条件，预留新任务加以验证。

作者自评有帮助即给条目加分。 使用声明与客观结果分开记录，贡献用随机化对照或消融检验。

反复查看留出集来挑选经验榜。 记录每次选择，最终使用从未反馈给更新器的确认集。

4.2 Managing and evaluating playbooks

Learning outcomes

After this section, students should be able to:

  1. Write playbook entries with recognizable conditions of use, a concrete action, a traceable source and a defined test.
  2. Design a three-group evaluation on unseen tasks that separates the total effect of a playbook from the difference attributable to its content, and distinguish usage claims from measured contributions.
  3. Evaluate whether changes to the playbook or its update rules introduce selection bias or shift the difficulty of the research questions.

Extension reading and exercises, about 70 minutes.

A playbook records methods intended to improve future tasks. Its value is a matter of evidence. Suppose a smoke test found a missing column, the agent added the corresponding check to the playbook as an entry, and the next round followed it. This shows that the entry was used; whether it reduced errors must still be shown on the next batch of tasks.

Writing actionable playbook entries

Conditions of use: the format of experiment output has changed
Action: after a short run, check all expected columns, the number of rows and that values are finite, then commit the version for full execution
Source: which round showed which failure, and which round caught the same kind of problem through the check
Test: compare the miss rate and added time on later unseen tasks
Status: candidate

A good entry specifies what to check in the next task. The source is written as a link, and the data and failure records of the time are retained. The trigger condition should be recognizable from information available when the task starts.

From reward to update

Each task is treated as one attempt. The agent reads the current playbook and chooses a method, the environment or checker returns a reward, and the updater adds, merges or deletes entries accordingly.

Two different signals are involved: the agent’s statement that it used a particular entry, and its measured performance with that entry. The first is a usage claim; the second requires a control. Usage claims can be used to propose ablation candidates but cannot by themselves be taken as a causal contribution.

New entries enter a candidate set first. They are retained after comparison on validation tasks and then evaluated on tasks that played no part in selection. When capacity is limited, redundant entries are removed, and each entry’s specific conditions of use are kept.

Separating gains with three groups

On the same batch of unseen tasks, the three groups receive the target playbook, a placebo matched in format and length, or no playbook. Execution budget and scoring rules are identical, and outputs are anonymized and shuffled before scoring with a fixed reviewer and rubric.

Target playbook minus no playbook gives the total effect; target playbook minus placebo gives the content difference under a matched placebo. The placebo may itself help or interfere, so all three groups are reported. Section 6.2 examines which effects these comparisons can identify.

Set aside a batch of tasks never used for writing or choosing the playbook, and freeze their inputs and scoring.
Run the three groups independently on each task, randomize the execution order, and record the origin version, budget and failures.
Analyze paired differences by task, reporting the three means, the content difference and the total effect with their intervals.

Every rule change produces a new version

Updating the content of entries belongs to the inner loop; changing the merge rule, capacity or scoring belongs to the outer loop. The outer loop has its own training and validation records. If it repeatedly sees the same held-out scores, the held-out set has also been used for selection, and a new confirmation set is eventually required.

A reflection check can propose a new version but cannot silently rewrite past scores. Fix the evaluation points, keep all attempts, and record the current playbook version together with the version of the learning rule.

Checking whether entries shift the research questions

Some entries make tasks easier rather than better: selecting only questions the system handles well, making vague predictions, or explaining results while avoiding the main comparison. The apparent hit rate then rises.

Task difficulty and the scope of the question are therefore included in the review. Compare each round’s question with the original one and state which evidence prompted any change. For directions that lack support, first list the experiments that would add evidence, so that a simpler question is not mistaken for progress.

Exercise

Choose a playbook entry believed to be effective, state which kind of task it should improve, and run a small three-group trial. A small sample serves only to check the design and the variation; a substantive claim requires sample-size planning based on the effect size. Also record the difference after the entry is removed, and assess whether the usage claim corresponds to an actual contribution.

Common errors and corrections

Turning every success into a general rule. Record the specific conditions and reserve new tasks for verification.

Crediting an entry because the agent judged that it helped. Keep usage claims separate from objective results, and test contribution with randomized controls or ablations.

Selecting the playbook by consulting the held-out set repeatedly. Keep a record of every selection, and finally use a confirmation set that was never fed back to the updater.

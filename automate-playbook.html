4.2 经验管理与评估

课后深入，约 70 分钟。

一次冒烟测试发现了缺失列。Agent 把做法写进经验榜，下一轮也照做了。这说明经验被使用，还需要下一批任务证明它减少了错误。

经验条目的构成

适用条件：实验输出格式发生变化
动作：短运行后检查所有预期列、行数与有限值，再提交正式执行版本
来源：哪轮任务出现何种失败，哪轮通过检查发现同类问题
测试：在之后未见任务上比较漏检率与新增耗时
状态：候选

有效条目应明确下一次要检查什么。把来源写成链接，保留当时的数据和失败记录。触发条件应当由任务开始时可见的信息识别。

从回报到更新

把每次任务看作一次尝试。Agent 读取当前榜，选择做法，环境或检查器给出回报，更新器据此新增、合并或删除条目。

这里有两种不同信号：作者说用了某条经验，以及带这条经验后实际表现怎样。前者是使用声明，后者需要对照。声明可用来提出消融候选，不能单独当成因果贡献。

新增条目先进入候选集。用验证任务比较后保留，再到未参与选择的任务上评估。容量有限时，删掉冗余条目，把每条经验的具体适用条件留下。

三组对照评估

对同一批未见任务，三组分别带目标经验、格式与长度匹配的安慰剂，或不带经验。执行预算和评分规则相同，输出匿名打乱后交给冻结评审。

目标经验减无经验给总效应，目标经验减安慰剂给匹配安慰剂下的内容差。安慰剂也可能有帮助或造成干扰，因此三组都要报告。第 6.2 节进一步推导它能识别什么。

留出一批从未用于写榜或挑榜的任务，冻结输入和评分。
每个任务独立跑三组，随机化执行顺序，记录原点版本、预算与失败。
按任务配对分析，报告三个均值、内容差与总效应及其区间。

每次改规则，产生一个新版本

更新经验内容属于内环，改变合并规则、容量或评分属于外环。外环有自己的训练与验证记录。若它持续看到同一留出成绩，留出集也会被用于挑选，最后还需要新的确认集。

反思检查可以提出新版本，不能悄悄改写过去的评分。固定评估点，保留所有尝试，把当前榜版本与学习规则版本一起记录。

研究问题与任务难度的核查

有些经验会让任务变得容易：只选自己擅长的问题，预测写得很宽，结果说明避开主要比较。表面命中率会升高。

把任务难度与问题尺度也放进复盘。比较每轮的问题与最初的问题，解释变化来自哪项证据。缺支撑的方向先列补证实验，避免用更简单的问题替代进步。

练习

选一条你相信有效的经验，先写它会改善哪类任务，再做一个小规模三组试验。小样本只用于检查设计与波动，正式主张需要按效应大小规划样本。条目移除后的差值也记录，看看使用声明是否真的指向贡献。

常见错误与处理方法

每次成功都写成通则。 保存具体条件，预留新任务验证。

作者自评帮上忙就加分。 使用声明与客观结果分开，贡献用随机化对照或消融检验。

不停看留出集挑榜。 每次选择保留记录，最终用未反馈给更新器的确认集。

4.2 Managing and evaluating playbooks

After-class deep dive, about 70 minutes.

A smoke test found a missing column. The agent added the check to the playbook as an entry, and the next round followed it. That shows the entry was used; the next batch of tasks still has to show that it reduced errors.

Write actionable playbook entries

Conditions of use: the format of experiment output has changed
Action: after a short run, check all expected columns, the number of rows and that values are finite, then commit the version for full execution
Source: which round showed which failure, and which round caught the same kind of problem through the check
Test: compare the miss rate and added time on later unseen tasks
Status: candidate

A good entry specifies what to check on the next task. Write the source as a link, and keep the data and failure records of the time. The trigger condition should be recognizable from information visible when the task starts.

From reward to update

Treat each task as one attempt. The agent reads the current playbook and chooses a method, the environment or checker gives a reward, and the updater adds, merges or deletes entries accordingly.

There are two different signals here: the author saying it used a particular entry, and how it actually performed with that entry. The first is a usage claim; the second needs a control. Claims can be used to propose ablation candidates, but cannot on their own be taken as a causal contribution.

New entries go into a candidate set first. They are kept after comparison on validation tasks, then evaluated on tasks that took no part in selection. When capacity is limited, delete redundant entries and keep each entry’s specific conditions of use.

Three groups separate the gains

On the same batch of unseen tasks, the three groups carry the target playbook, a placebo matched in format and length, or no playbook. Execution budget and scoring rules are the same, and outputs are anonymized and shuffled before scoring with a fixed reviewer and rubric.

Target playbook minus no playbook gives the total effect; target playbook minus placebo gives the content difference under a matched placebo. The placebo may also help or interfere, so all three groups are reported. Section 6.2 examines which effects these comparisons can identify.

Set aside a batch of tasks never used for writing or choosing the playbook, and freeze their inputs and scoring.
Run the three groups independently on each task, randomize the execution order, and record the origin version, budget and failures.
Analyze paired differences by task, reporting the three means, the content difference and the total effect with their intervals.

Every rule change produces a new version

Updating entry content belongs to the inner loop; changing the merge rule, capacity or scoring belongs to the outer loop. The outer loop has its own training and validation records. If it keeps seeing the same held-out scores, the held-out set is also being used for selection, and in the end a new confirmation set is needed.

A reflection check can propose a new version, but cannot quietly rewrite past scores. Fix the evaluation points, keep all attempts, and record the current playbook version together with the learning-rule version.

Check whether entries steer the questions off course

Some entries make tasks easier: choose only questions you are good at, make vague predictions, or explain results while avoiding the main comparison. The apparent hit rate goes up.

Put task difficulty and the scale of the question into the review as well. Compare each round’s question with the original one, and explain which evidence the change came from. For directions lacking support, first list the experiments that would add evidence, so a simpler question does not stand in for progress.

Exercise

Choose a playbook entry you believe works, first write which kind of task it will improve, then run a small three-group trial. A small sample is only for checking the design and the variation; a substantive claim requires sample-size planning based on the effect size. Also record the difference after the entry is removed, and see whether the usage claim really points to a contribution.

Common mistakes and how to fix them

Writing every success as a general rule. Save the specific conditions and reserve new tasks for verification.

Adding points because the author judged that it helped. Keep usage claims apart from objective results, and test contribution with randomized controls or ablations.

Choosing the playbook by looking at the held-out set again and again. Keep a record of every selection, and in the end use a confirmation set that was never fed back to the updater.

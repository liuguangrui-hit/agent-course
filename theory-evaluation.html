6.2 学习收益评估

课后深入，约 75 分钟。

带经验组比无经验组高了十分。这十分可能来自条目内容，也可能来自更长的输入、更完整的答题格式，或评审偏爱更长的回答。评估学习系统时，需要区分这些影响来源。

先明确要估计的干预

冻结原点，工具，预算与任务分布，随机分配所带经验。每个任务都独立运行三组，顺序随机，输出匿名后评分。

d̂=1n∑i(riB−riP),ĝ=1n∑i(riB−ri0).\widehat d=\frac1n\sum_i(r_i^B-r_i^P),\qquad \widehat g=\frac1n\sum_i(r_i^B-r_i^0).

dd 比较目标经验与安慰剂，gg 比较目标经验与无经验。按任务配对保留相关性，重复采样时把同一任务当作一个簇。

这项随机化首先估计换一份输入文本对回报的作用。进一步把 dd 解释为学到的知识，还需要安慰剂隔离非特异影响。

安慰剂的要求写进模型

用一个简化分解说明混淆。设目标经验得分由任务基线，内容作用 kBk_B，非特异作用 hBh_B 与噪声组成；安慰剂有对应的 kPk_P 和 hPh_P。于是：

𝔼[rB−rP]=(kB−kP)+(hB−hP).\mathbb E[r^B-r^P]=(k_B-k_P)+(h_B-h_P).

当两组非特异作用一致，差值才消去这一项。安慰剂若带有可用知识，比较对象也会随之改变；若安慰剂造成干扰，目标经验的相对优势会被抬高。

因此同时报告三组，检查安慰剂对无经验的差，再尝试另一份匹配安慰剂。必要时增加格式骨架对照，把格式与内容分得更细。

篇幅配平不止输入长度

匹配结构、语气和领域相关程度，记录输入 token。输出长度也要看：长答案可能有更多正确内容，也可能只得到评审偏好。

优先用可执行结果、固定字段或明确评分规则。若模型评审不可避免，冻结规则与评审版本，随机交换位置，盲化组别，抽查不同厂商的复核分歧。

不能为了配平输出，把正确论证任意截掉。可以事前规定共同输出预算，再报告评分对长度的敏感性。

先考后学与数据污染

第 tt 个任务先用 BtB_t 作答，评分以后才用这份反馈生成 Bt+1B_{t+1}。这阻止更新器从本题答案直接获益于本题成绩。

它仍有两个前提要处理。任务流变化时，累计成绩描述的是这条流上的在线表现；原点预训练见过旧论文时，遮住结果不等于抹去模型记忆。

把学习期、选榜验证期和最终确认期分开。论文按时间回放，保存日期口径，尽量增加可验证晚于原点训练材料的任务。商业模型训练截止若无法确认，就保留污染诊断，并加入前瞻性新实验。

论文发表本身也携带成功线索。加入失败复现、被拒工作或自己新做的实验，检查经验是否仍能识别失败。

外环选择与验证偏差

外环看过一次成绩，再改规则，这次成绩就进入选择。试很多规则再报最好的，会放大噪声。固定 MM 个同等真值候选、每个估计由 nn 个独立有界回报组成时，最佳估计的噪声乐观偏差可用随 log⁡M/n\sqrt{\log M/n} 增长的界描述。

实际外环还会自适应地产生候选，简单固定候选界不足以覆盖全部过程。保留尝试总数和版本树，预先登记评估点，最后用从未反馈给更新器的任务确认。

练习

读 protocol.md，为自己的任务填一份冻结协议。至少写明原点与任务身份，再确定三组构造和输出预算。评分规则、失败处理与分析单位也要事先规定。再运行 analyze_experience.py，解释为什么缺一组数据时脚本拒绝继续。

常见错误与处理方法

安慰剂写得明显无用且干扰任务。 匹配结构与相关程度，报告它相对无经验的作用，再换一份检验敏感性。

先考后学就宣布排除了记忆。 增加时间外与前瞻任务，记录训练截止的不确定性。

评审也读目标经验，评分一起变。 评审输入与规则冻结，学习对象只在被评系统中更新。

6.2 Evaluating learning gains

After-class deep dive, about 75 minutes.

The group with experience scores ten points higher than the group without. Those ten points may come from the content of the entries, or from longer input, a more complete answer format, or a reviewer who prefers longer answers. A learning system needs to distinguish these sources of improvement.

Define the intervention and estimand

Freeze the origin, tools, budget and task distribution, and randomly assign which experience is supplied. Every task runs the three groups independently, in random order, and outputs are anonymized before scoring.

d̂=1n∑i(riB−riP),ĝ=1n∑i(riB−ri0).\widehat d=\frac1n\sum_i(r_i^B-r_i^P),\qquad \widehat g=\frac1n\sum_i(r_i^B-r_i^0).

dd compares the target playbook with the placebo, and gg compares the target playbook with no playbook. Pairing by task preserves within-task correlation, and with repeated sampling the same task is treated as one cluster.

This randomization first estimates the effect on reward of switching one piece of input text. Interpreting dd further as learned knowledge also needs a placebo that isolates non-specific effects.

Model the placebo’s assumptions

A simplified decomposition shows the confounding. Suppose the score with the target playbook is made of a task baseline, a content effect kBk_B, a non-specific effect hBh_B and noise; the placebo has corresponding kPk_P and hPh_P. Then:

𝔼[rB−rP]=(kB−kP)+(hB−hP).\mathbb E[r^B-r^P]=(k_B-k_P)+(h_B-h_P).

Only when the two groups’ non-specific effects are equal does the difference cancel this term. If the placebo carries usable knowledge, the object of comparison changes with it; if the placebo interferes, the target playbook’s relative advantage is inflated.

So report all three groups, check the placebo’s difference from no playbook, and then try another matched placebo. Where needed, add a format-only control to separate format from content more finely.

Balancing length is more than input length

Match structure, tone and degree of domain relevance, and record input tokens. Look at output length too: a long answer may contain more correct content, or may only win the reviewer’s preference.

Prefer executable results, fixed fields or explicit scoring rules. If a model reviewer is unavoidable, freeze the rules and the reviewer version, randomly swap positions, conceal group labels, and spot-check disagreements with a re-review from another vendor.

Do not cut correct reasoning arbitrarily to balance outputs. You can set a shared output budget in advance, then report how sensitive scoring is to length.

Test-then-learn and data contamination

Task tt is first answered with BtB_t, and only after scoring is this feedback used to generate Bt+1B_{t+1}. This keeps the updater from turning the answer to a question directly into a better score on that same question.

Two issues remain. When the task stream changes, the cumulative score describes online performance on this stream; when the origin saw old papers in pretraining, hiding the results does not erase the model’s memory.

Keep the learning period, the playbook-selection validation period and the final confirmation period separate. Replay papers in time order, save how dates are defined, and add as many tasks as possible that can be verified to come after the origin’s training material. If a commercial model’s training cutoff cannot be confirmed, keep contamination diagnostics and add prospective new experiments.

Paper publication itself also carries a clue of success. Add failed replications, rejected work or experiments you have newly run yourself, and check whether experience can still recognize failure.

Validation bias in the outer loop

Once the outer loop has seen a score and then changes a rule, that score has entered selection. Trying many rules and reporting the best amplifies noise. With MM fixed candidates of equal true value, each estimated from nn independent bounded rewards, the optimistic noise bias of the best estimate can be described by a bound that grows like log⁡M/n\sqrt{\log M/n}.

A real outer loop also generates candidates adaptively, and a simple fixed-candidate bound is not enough to cover the whole process. Keep the total number of attempts and the version tree, register evaluation points in advance, and finally confirm on tasks never fed back to the updater.

Three testable predictions

Claim Main comparison Further evidence if unsupported
Experience content improves future performance Target playbook against several matched placebos, also compared with no playbook Add independent tasks, check balancing and the task distribution, locate the effective content

Exercise

Read protocol.md and fill in a frozen protocol for your own task. At minimum, specify the origin, task identity, construction of the three groups, output budget, scoring, failure handling and unit of analysis. Then run analyze_experience.py and explain why the script refuses to continue when one group’s data are missing.

Common mistakes and how to fix them

A placebo written to be obviously useless that interferes with the task. Match structure and degree of relevance, report its effect relative to no playbook, then switch to another to test sensitivity.

Declaring memory ruled out because of test-then-learn. Add out-of-time and prospective tasks, and record the uncertainty about the training cutoff.

The reviewer also reads the target playbook, so scoring shifts with it. Freeze the reviewer’s input and rules, and update the learnable component only in the system being evaluated.

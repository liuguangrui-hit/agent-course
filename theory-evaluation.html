6.2 学习收益评估

学习目标

  1. 明确评估所估计的干预，并用简化分解说明安慰剂对照在何种条件下能分离内容作用与非特异作用。
  2. 设计配平输入与输出、先考后学、时间留出与前瞻任务，以控制评审偏好与数据污染。
  3. 分析外环选择造成的验证偏差，为内容收益、反馈依赖与规则改进分别设计可检验预测。

课后深入专题，约 75 分钟。

带经验组比无经验组高出十分。这十分可能来自条目内容，也可能来自更长的输入、更完整的答题格式，或评审对较长回答的偏好。评估学习系统时，需要区分这些影响来源。

待估计的干预

冻结原点、工具、预算与任务分布，随机分配所带的经验。每个任务都独立运行三组，顺序随机，输出匿名后评分。

d̂=1n∑i(riB−riP),ĝ=1n∑i(riB−ri0).\widehat d=\frac1n\sum_i(r_i^B-r_i^P),\qquad \widehat g=\frac1n\sum_i(r_i^B-r_i^0).

dd 比较目标经验与安慰剂，gg 比较目标经验与无经验。按任务配对以保留相关性；重复采样时，把同一任务视为一个簇。

这种随机化首先估计的是更换一份输入文本对回报的作用。要进一步把 dd 解释为学到的知识，还需要安慰剂隔离非特异影响。

安慰剂条件的形式化

用一个简化分解说明混淆。设目标经验的得分由任务基线、内容作用 kBk_B、非特异作用 hBh_B 与噪声组成；安慰剂有相应的 kPk_P 和 hPh_P。于是：

𝔼[rB−rP]=(kB−kP)+(hB−hP).\mathbb E[r^B-r^P]=(k_B-k_P)+(h_B-h_P).

只有两组的非特异作用相同时，差值中的这一项才会消去。若安慰剂含有可用的知识，比较对象也随之改变；若安慰剂造成干扰，目标经验的相对优势会被抬高。

因此应同时报告三组结果，检查安慰剂相对无经验的差，再尝试另一份匹配安慰剂。必要时增加格式骨架对照，把格式与内容的作用分得更细。

篇幅配平不限于输入长度

安慰剂须匹配结构、语气和领域相关程度，并记录输入 token。输出长度也要检查：较长的回答可能包含更多正确内容，也可能只是得到了评审的偏好。

优先使用可执行的结果、固定字段或明确的评分规则。若无法避免模型评审，应冻结规则与评审版本，随机交换位置，盲化组别，并抽查不同厂商复核之间的分歧。

不能为配平输出而任意截掉正确的论证。可以事先规定共同的输出预算，再报告评分对长度的敏感性。

先考后学与数据污染

第 tt 个任务先用 BtB_t 作答，评分完成后才用这份反馈生成 Bt+1B_{t+1}。这样可以阻止更新器利用本题答案提高本题成绩。

此设计仍有两个前提需要处理。任务流发生变化时，累计成绩描述的是这条任务流上的在线表现；原点在预训练中可能见过旧论文，遮住结果并不等于消除模型记忆。

把学习期、选榜验证期和最终确认期分开。论文按时间回放，保存日期口径，并尽量增加可证实晚于原点训练材料的任务。商业模型的训练截止时间若无法确认，应保留污染诊断，并加入前瞻性的新实验。

论文发表本身也带有成功的线索。应加入失败的复现、被拒的工作或自己新做的实验，检验经验是否仍能识别失败。

外环选择与验证偏差

外环一旦看过某次成绩再修改规则，这次成绩就参与了选择。尝试许多规则后只报告最好的一个，会放大噪声。固定 MM 个真值相同的候选、每个估计由 nn 个独立有界回报构成时，最佳估计的噪声乐观偏差可以用随 log⁡M/n\sqrt{\log M/n} 增长的界描述。

实际的外环还会自适应地产生候选，简单的固定候选界不足以覆盖全过程。应保留尝试总数和版本树，预先登记评估点，最后用从未反馈给更新器的任务确认。

练习

阅读 protocol.md，为自己的任务填写一份冻结协议。至少写明原点与任务身份，再确定三组的构造和输出预算；评分规则、失败处理与分析单位也须事先规定。然后运行 analyze_experience.py，解释为何缺少一组数据时脚本拒绝继续运行。

常见错误与处理方法

安慰剂写得明显无用，且干扰任务。 匹配结构与相关程度，报告它相对无经验的作用，再换一份检验敏感性。

采用先考后学即宣称排除了记忆。 增加时间外与前瞻性任务，记录训练截止时间的不确定性。

评审也读取目标经验，评分随之改变。 冻结评审的输入与规则，学习对象只在被评系统中更新。

近邻工作可对照 ExpeL 与 ACE。DeepLearning.AI Evaluating AI Agents进一步讨论怎样选择组件指标，并把它们与端到端评价联系起来。

6.2 Evaluating learning gains

Learning outcomes

After this section, students should be able to:

  1. Define the intervention and estimands of a learning evaluation, and state the assumptions under which a placebo comparison identifies a content effect.
  2. Design an evaluation protocol that controls for length and format, reviewer preference, data contamination and validation bias in the outer loop.
  3. Formulate claims about content gain, reward dependence and rule improvement as testable predictions with a main comparison and a plan for further evidence.

Extension reading and exercises, about 75 minutes.

Suppose the group with experience scores ten points higher than the group without. Those ten points may come from the content of the entries, or from longer input, a more complete answer format or a reviewer who prefers longer answers. Evaluation of a learning system must distinguish these sources of improvement.

Defining the intervention and estimand

Freeze the origin, tools, budget and task distribution, and randomly assign which experience is supplied. Every task runs the three groups independently, in random order, and outputs are anonymized before scoring.

d̂=1n∑i(riB−riP),ĝ=1n∑i(riB−ri0).\widehat d=\frac1n\sum_i(r_i^B-r_i^P),\qquad \widehat g=\frac1n\sum_i(r_i^B-r_i^0).

dd compares the target playbook with the placebo, and gg compares the target playbook with no playbook. Pairing by task preserves within-task correlation, and under repeated sampling the same task is treated as one cluster.

This randomization first estimates the effect on reward of replacing one piece of input text. Interpreting dd further as learned knowledge also requires a placebo that isolates non-specific effects.

Modeling the placebo’s assumptions

A simplified decomposition shows the confounding. Suppose the score with the target playbook consists of a task baseline, a content effect kBk_B, a non-specific effect hBh_B and noise; the placebo has corresponding kPk_P and hPh_P. Then:

𝔼[rB−rP]=(kB−kP)+(hB−hP).\mathbb E[r^B-r^P]=(k_B-k_P)+(h_B-h_P).

The difference cancels the non-specific term only when the two groups’ non-specific effects are equal. If the placebo carries usable knowledge, the object of comparison changes with it; if the placebo interferes, the target playbook’s relative advantage is inflated.

All three groups are therefore reported, the placebo’s difference from no playbook is checked, and a second matched placebo is then tried. Where needed, a format-only control separates format from content more finely.

Balancing involves more than input length

Match structure, tone and degree of domain relevance, and record input tokens. Output length must also be examined: a long answer may contain more correct content, or may merely win the reviewer’s preference.

Executable results, fixed fields or explicit scoring rules are preferred. If a model reviewer is unavoidable, freeze the rules and the reviewer version, randomly swap positions, conceal group labels, and spot-check disagreements with a re-review from another vendor.

Correct reasoning is not truncated arbitrarily to balance outputs. A shared output budget can be set in advance, and the sensitivity of scoring to length is then reported.

Test-then-learn and data contamination

Task tt is first answered with BtB_t, and only after scoring is this feedback used to generate Bt+1B_{t+1}. This prevents the updater from turning the answer to a question directly into a better score on that same question.

Two issues remain. When the task stream changes, the cumulative score describes online performance on this stream; when the origin saw older papers in pretraining, concealing the results does not erase the model’s memory.

Keep the learning period, the validation period for playbook selection and the final confirmation period separate. Replay papers in chronological order, record how dates are defined, and include as many tasks as possible that can be verified to postdate the origin’s training material. If a commercial model’s training cutoff cannot be confirmed, keep contamination diagnostics and add prospective new experiments.

Publication itself also signals success. Include failed replications, rejected work or newly run experiments, and check whether experience can still recognize failure.

Validation bias in the outer loop

Once the outer loop has seen a score and then changes a rule, that score has entered selection. Trying many rules and reporting the best amplifies noise. With MM fixed candidates of equal true value, each estimated from nn independent bounded rewards, the optimistic noise bias of the best estimate can be described by a bound that grows like log⁡M/n\sqrt{\log M/n}.

A real outer loop also generates candidates adaptively, and a simple fixed-candidate bound does not cover the whole process. Keep the total number of attempts and the version tree, register evaluation points in advance, and finally confirm on tasks never fed back to the updater.

Three testable predictions

Claim Main comparison Further evidence if unsupported
Experience content improves future performance Target playbook against several matched placebos, also compared with no playbook Add independent tasks, check balancing and the task distribution, locate the effective content
The gain depends on correct reward Playbook learned with normal reward against playbook learned with shuffled reward Check whether feedback actually changes the update, and run reward-sensitivity ablations
Changing the rule produces lasting improvement New update rule against the old, measuring learning curves on a shared confirmation set Expand the same-budget comparison, keeping all candidates and failures

Exercise

Read protocol.md and complete a frozen protocol for your own task. At minimum, specify the origin, task identity, construction of the three groups, output budget, scoring, failure handling and unit of analysis. Then run analyze_experience.py and explain why the script refuses to continue when one group’s data are missing.

Common errors and corrections

A placebo written to be obviously useless that interferes with the task. Match structure and degree of relevance, report its effect relative to no playbook, then substitute another placebo to test sensitivity.

Concluding that memory is ruled out because of test-then-learn. Add out-of-time and prospective tasks, and record the uncertainty about the training cutoff.

A reviewer that also reads the target playbook, so that scoring shifts with it. Freeze the reviewer’s input and rules, and update the learnable component only in the system being evaluated.

For closely related work, compare ExpeL and ACE. DeepLearning.AI Evaluating AI Agents discusses how to choose component metrics and connect them to end-to-end evaluation.

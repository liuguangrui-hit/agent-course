2.1 文献获取

学习目标

  1. 区分论文身份与文件身份，为同一论文的不同版本分别建立可核查记录。
  2. 依据当前判断所需的信息选择文献版本，并分层检验文件、身份与版本完整性。
  3. 对获取失败进行分类，记录可供他人继续处理的状态，并评估版本变化对已有证据的影响。

课后深入专题，约 45 分钟。

下载器返回成功，文件名也正确，打开后却可能只是一张登录页。全文获取完成的标准，是能够确认所得文件是哪一份原件。

论文与文件分别编号

论文以 DOI 或 arXiv 标识识别，文件以版本和 SHA-256 识别。同一篇论文可以有预印本、正式版与补充材料，每个文件单独记录一行。

paper_id, version, source_url, retrieved_at, filename, sha256, pages, identity_status

题目检索用于发现候选，标识用于确认对象。接口中的在线发表年份、卷期年份与首次提交年份分别保存，展示时再选择口径。文献名单先核对身份，再安排下载顺序。

按当前判断选择版本

开放预印本通常便于取得，正式版可能修改过结论，关键设置可能只在补充材料中。开始阅读前，先明确需要哪一类信息：方法细节、主要结果，还是经过审稿后的结论，再确认对应版本是否包含该信息。

文献接口提供元数据和开放获取位置，出版社页面提供正式记录，作者主页或机构库可能提供允许公开的稿件。需要机构登录的，在已授权的浏览器中完成。访问资格不足或真人验证未完成时，记录获取状态，继续处理其他材料。

文件检查与身份检查

第一层检查文件头和 PDF 解析结果，确认文件确实是 PDF 且含有页面。第二层读取首页与正文，核对标题、作者和标识。第三层检查版本与完整性，确认正文、参考文献和所需补充材料是否齐全。

对每个下载文件解析 PDF，记录页数并提取前两页。
与清单核对身份，再渲染首页和一页包含关键结果的页面查看。
逐项记录 file_ok，identity_ok，version_ok。失败的保留原因和来源页面。

任何一层通过都不能代替其他各层。出版社返回的附件同样能通过 PDF 解析，错误版本的论文同样能通过标题核对。

获取失败的分类与处理

获取失败分为五类：等待登录、无访问资格、频率限制、网络错误和身份待核。每一类都写明下一步：由用户登录，寻找公开版本，按服务提示退避，或人工核对。

批量调用接口时遵守当前配额，保留查询字符串和时间。同一失败反复出现时，先调整获取计划，不要一轮轮重试同一路径。知识库可以保留尚未取得全文的记录，但须写明目前只读到摘要。

订阅页面跳回登录时，先确认浏览器中的机构身份是否仍然有效。需要用户重新登录或完成人机验证时，保留当前页面，恢复后从该位置继续下载。

版本变化对证据的影响

取得新版本后，先比较正在使用的图表与方法段落。数字改变时更新论文页；比较条件改变时，概念页的综合也可能需要修改。原笔记保留原文件身份，新笔记说明修正之处。

同名 PDF 不能覆盖旧版本。旧结论仍应能追溯到当时阅读的那份材料。

练习

选一篇同时有预印本与正式版的论文，为两份文件分别建立记录。选一条结果，在原文与笔记之间往返核对。再为一次失败的下载建立状态记录，说明下一位读者可以从哪里继续处理。

常见错误与处理方法

以文件扩展名判断内容类型。 解析文件，并核对实际页面。

最新版本自动覆盖旧证据。 新文件另行保存，先查明已有结论依赖哪一版。

未取得全文却记为已通读。 记录当前阅读范围，把基于摘要的判断与基于全文的结果分开。

相关文档：arXiv API，OpenAlex，Ego Lite。

2.1 Finding full texts

Learning outcomes

After this section, students should be able to:

  1. Distinguish the identity of a paper from the identity of a file, and verify a retrieved document at the levels of file integrity, bibliographic identity and version.
  2. Select the version of a paper that contains the evidence required, and assess how differences between versions affect recorded evidence.
  3. Record retrieval failures by cause so that another reader can continue the retrieval without repeating failed attempts.

Extension reading and exercises, about 45 minutes.

A downloader may report success and produce a correctly named file that opens as a sign-in page. Full-text retrieval is complete only when the source document obtained has been verified.

Identifying papers and files separately

A paper is identified by its DOI or arXiv identifier; a file is identified by its version and SHA-256. One paper may have a preprint, a published version and supplementary material, and each file receives its own row.

paper_id, version, source_url, retrieved_at, filename, sha256, pages, identity_status

Title searches find candidates; identifiers confirm the paper. The online publication year, volume year and initial submission year reported by the API are stored separately, and the year to display is chosen explicitly. The identities on the list are checked before the download order is considered.

Choosing the version that contains the required evidence

Open preprints are often easy to obtain, the published version may have revised conclusions, and key settings may appear only in the supplementary material. Before reading, decide which information is needed: method details, the main results or the conclusions after peer review. In each case, confirm that the chosen version contains it.

Literature APIs provide metadata and open-access locations; publisher pages provide the formal record; authors’ home pages or institutional repositories may offer manuscripts cleared for public sharing. Institutional sign-in, where needed, takes place in the browser the user has authorized. If access rights are insufficient or a human-verification challenge has not been completed, record a retrieval status and continue with other material.

Checking the file, then the identity

The first level checks the file header and PDF parsing, confirming that the file is a PDF with pages. The second level reads the first page and the body, confirming title, authors and identifier. The third level checks version and completeness: whether the main text, references and required supplementary material are all present.

Parse each downloaded PDF, record its page count and extract the first two pages.
Check its identity against the list, then render and look at the first page and one page with a key result.
Record file_ok, identity_ok and version_ok for each. For failures, keep the reason and the source page.

Passing one level does not replace the others. An attachment returned by a publisher also parses as a PDF, and the wrong version of a paper also passes a title check.

Recording retrieval failures and next steps

Failures are classified as awaiting sign-in, no access rights, rate limiting, network error and identity pending. Each is recorded with its next step: sign-in by the user, a search for a public version, back-off as the service specifies, or a manual check.

Bulk API calls must respect the current quota and record the query string and time. When the same failure recurs, the retrieval plan is changed rather than retrying the same route repeatedly. The literature base can hold records without full texts, provided it states that only the abstract has been read.

When a subscription page returns to sign-in, first confirm that the institutional identity in the browser is still valid. When re-authentication or a human-verification challenge is required, keep the current page open and resume downloading from that point once access is restored.

Version changes can change the evidence

When a new version arrives, first compare the figures, tables and method sections being used. If numbers changed, update the paper page; if the comparison conditions changed, the synthesis on the concept page may also need to change. Old notes keep the identity of the original file; new notes state what was corrected.

A PDF with the same name must not overwrite the old version. An earlier conclusion should remain traceable to the material read at the time.

Exercise

Take a paper that has both a preprint and a published version and create a record for each file. Choose one result and check it in both directions between original and notes. Then create a status record for one failed download, stating the action the next reader can take to continue without retrying blindly.

Common errors and corrections

Treating the file extension as the content type. Parse the file and inspect the actual pages.

Allowing the newest version to overwrite old evidence. Save the new file separately, and first check which version the existing conclusions relied on.

Recording a paper as read in full when the full text is missing. Record the current reading scope, and keep judgments based on the abstract separate from results in the full text.

Documentation: arXiv API, OpenAlex, Ego Lite.

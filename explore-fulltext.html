2.1 文献获取

课后深入，约 45 分钟。

下载器返回成功，文件名也对，打开却是一张登录页。全文获取完成后，应能确认取得的是哪份原件。

把论文与文件分开编号

论文以 DOI 或 arXiv 标识识别，文件以版本和 SHA-256 识别。同一论文可以有预印本、正式版与补充材料，每个文件各记一行。

paper_id, version, source_url, retrieved_at, filename, sha256, pages, identity_status

题目检索用来发现候选，标识用来确认对象。接口里的在线年份、卷期年份与首次提交年分别保存，展示时再选口径。名单先核对身份，再考虑下载顺序。

选择能完成当前判断的版本

开放预印本常便于取得，正式版可能改过结论，补充材料可能才有关键设置。阅读开始前先问要用哪项信息：方法细节、主结果还是审稿后的结论。需要哪一项，就确认对应版本是否包含它。

文献接口提供元数据和开放位置；出版社页面给正式记录；作者主页或机构库可能提供允许公开的稿件。需要机构登录的，在你已授权的浏览器中完成。访问资格不足或真人验证未完成，留下获取状态，继续处理其他材料。

检查文件，再检查身份

第一层检查文件头和 PDF 解析，确认它确实是 PDF 且有页面。第二层读取首页与正文，确认标题，作者和标识。第三层检查版本与完整性，看主文，参考文献和所需补充材料是否齐全。

对每个下载文件解析 PDF，记录页数并提取前两页。
与清单核对身份，再渲染首页和一页包含关键结果的页面查看。
逐项记录 file_ok，identity_ok，version_ok。失败的保留原因和来源页面。

某一项通过不能替代其余项。出版社返回的附件也能通过 PDF 解析，论文的错误版本也能通过标题核对。

获取失败的分类与处理

失败分为五类：等待登录与无访问资格、频率限制与网络错误，以及身份待核。每一类写下一步：用户登录，找公开版本，按服务提示退避，或人工核对。

接口批量调用要遵守当前配额，保留查询字符串和时间。相同失败持续出现时先改获取计划，避免一轮轮重新尝试同一路径。文献库中可以保留未得全文的记录，明确目前只看到了摘要。

订阅页跳回登录时，先确认浏览器里的机构身份是否仍有效。需要你重新登录或完成人机验证时，把当前页面留好，恢复后再从这个位置继续下载。

版本变化会改变证据

新版本到来后，先比较你正在使用的图表与方法段。数字变了，更新论文页；比较条件变了，概念页的综合也可能要变。原笔记保留原文件身份，新笔记说明修正的地方。

不要让同名 PDF 覆盖旧版。旧结论仍应能追回当时阅读的那份材料。

练习

拿一篇同时有预印本与正式版的论文，为两份文件分别建记录。挑一条结果，从原文到笔记来回查。再给一次失败下载建状态，说明下一位读者可以从哪里继续处理。

常见错误与处理方法

文件扩展名等于内容类型。 解析文件，并核对实际页面。

最新版本自动覆盖旧证据。 新文件另存，先查已有结论依赖了哪一版。

缺全文仍写成已通读。 保存当前阅读范围，摘要判断与全文结果分开。

入口文档：arXiv API，OpenAlex，Ego Lite。

2.1 Finding full texts

After-class deep dive, about 45 minutes.

The downloader reports success and the file name is right, but it opens as a login page. Full-text retrieval is complete only when you have verified which source document you obtained.

Identify papers and files separately

A paper is identified by its DOI or arXiv identifier; a file is identified by its version and SHA-256. One paper can have a preprint, a published version and supplementary material, and each file gets its own row.

paper_id, version, source_url, retrieved_at, filename, sha256, pages, identity_status

Title searches find candidates; identifiers confirm the paper. Save the online publication year, volume year and initial submission year from the API separately, and choose which one to show when displaying. Check the identities on the list first, then think about download order.

Choose the version that contains the evidence you need

Open preprints are often easy to get, the published version may have changed conclusions, and the key settings may be only in the supplementary material. Before reading, ask which information you need: method details, the main results, or the conclusions after peer review. Whichever you need, confirm that the corresponding version contains it.

Literature APIs provide metadata and open-access locations; publisher pages give the formal record; author home pages or institutional repositories may offer manuscripts cleared for public sharing. Institutional login, where needed, happens in the browser you have authorized. If access rights are insufficient or a human-verification challenge has not been completed, leave a retrieval status and carry on with other material.

Check the file, then check the identity

The first layer checks the file header and PDF parsing, confirming it is really a PDF with pages. The second layer reads the first page and the body, confirming title, authors and identifier. The third layer checks version and completeness: whether the main text, references and needed supplementary material are all there.

Parse each downloaded PDF, record its page count and extract the first two pages.
Check its identity against the list, then render and look at the first page and one page with a key result.
Record file_ok, identity_ok and version_ok for each. For failures, keep the reason and the source page.

Passing one layer does not replace the others. An attachment returned by a publisher also parses as a PDF, and a wrong version of a paper also passes a title check.

Record retrieval failures and next steps

Split failures into waiting for login, no access rights, rate limiting, network error and identity pending. For each, write the next step: the user logs in, look for a public version, back off as the service says, or check by hand.

Bulk API calls must respect the current quota, and keep the query string and time. When the same failure keeps happening, change the retrieval plan first, instead of retrying the same route round after round. The literature base can keep records without full texts, stating clearly that only the abstract has been seen so far.

When a subscription page bounces back to login, first confirm that the institutional identity in the browser is still valid. When you need to log in again or complete a human-verification challenge, keep the current page open, and once access is restored, continue downloading from that point.

Version changes can change the evidence

When a new version arrives, first compare the figures, tables and method sections you are using. If numbers changed, update the paper page; if comparison conditions changed, the synthesis on the concept page may have to change as well. Old notes keep the original file’s identity; new notes say what was corrected.

Do not let a PDF with the same name overwrite the old version. An old conclusion should still trace back to the material read at the time.

Exercise

Take a paper that has both a preprint and a published version, and create a record for each file. Pick one result and check back and forth between original and notes. Then create a status for one failed download, writing the action the next reader can take to continue without retrying.

Common mistakes and how to fix them

Treating the file extension as the content type. Parse the file and check the actual pages.

The newest version automatically overwrites old evidence. Save the new file separately, and first check which version existing conclusions relied on.

Writing “read in full” when the full text is missing. Save the current reading scope, and keep judgments from the abstract apart from results in the full text.

Documentation: arXiv API, OpenAlex, Ego Lite.

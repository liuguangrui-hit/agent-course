5.1 权限与沙箱

课后深入，约 60 分钟。

允许 uv run，究竟允许了什么？它启动的脚本可以再启动程序，也可以使用环境里的凭据。理解这一点，才能判断权限表的实际范围。

四类能力与权限边界

能力 需要检查的边界
读文件 模型直接读取工具，子进程可见目录
写文件 工作目录、临时目录和挂载点
访问网络 可连接目标、协议与代理路径
产生外部效果 凭据的作用域，远端允许的动作

权限模式是这些边界的起点。当前配置可能同时来自组织、用户和项目，需要读取最终有效值，再解释实际生效范围。

命令规则只覆盖特定入口

拒绝一个删除命令的写法，可以挡住那种工具请求。其他脚本也能执行删除，允许的 shell 还可以组合命令。规则应按任务选择最小入口，进程层再限制目录和网络。

只读资料任务优先用只读执行环境。需要写入的任务只挂载专用输出目录。高权限发布凭据不要放进会读取外部资料的执行进程。

沙箱行为测试

macOS，Linux，Windows 的隔离机制和支持范围不同。当前 Agent 的某种默认模式，也可能被组织配置覆盖。先记录版本和生效配置，再测试读写，子进程与网络。

练习材料提供配置起点，具体字段按 Claude 权限、Claude 沙箱和 Codex 安全说明核对。配置解析成功之后仍要做行为测试。

在演示目录内为每条边界建一个用例，包含预期与实际结果。
直接工具和子进程分别尝试读取普通测试文件。
允许目录写入应成功，预定隔离目录写入应失败。
测试一个允许网络目标与一个未允许目标，记录实际行为。

测试只能说明这些路径在当前配置下怎样工作。新增工具、改变启动方式或更新版本，重测受影响路径。

SSH 例外是另一项能力

把 SSH 放到本机沙箱外，它会拿到本机进程可用的连接能力；远端命令又受服务器账号控制。最小化远端账号权限，限定工作目录，使用集群已有的调度与网络管理。

如果一次任务只需查询作业状态，可提供只返回固定字段的查询入口。给任意远端 shell 的权限比查询状态宽，配置说明应当明确这个选择。

按信息流组织角色

外部资料进入阅读角色，带来源的笔记进入分析角色，批准的产物进入发布角色。来源标签贯穿传递，发布操作核对目标与授权。

摘要和结构化 JSON 也可能包含不可信要求。把资料格式变整齐，并没有改变来源。权限在执行端落实，模型判断再谨慎也只是其中一层。

练习

从第 4 课选一次收工，逐项列出读写文件、网络和凭据。给每项动作找最小可用入口。然后换一个入口运行同样的无害测试，记录哪里发生了权限扩张。

常见错误与处理方法

把两家的配置逐字段翻译。 先写所需能力，再分别实现与实测同一种语义。

名单只写域名，忽略外部工具例外。 把沙箱外命令和连接器分别列进能力表。

本机目录隔离等于远端隔离。 远端账号与进程另做边界测试。

5.1 Permissions and sandboxes

After-class deep dive, about 60 minutes.

When you allow uv run, what exactly have you allowed? The script it starts can start other programs, and can use the credentials in the environment. Understanding this helps you assess the actual scope of a permission table.

Four capabilities and their boundaries

Capability Boundary to check
Reading files The model’s direct read tools, and the directories a subprocess can see
Writing files Working directory, temporary directories and mount points
Network access Reachable targets, protocols and proxy paths
External effects The scope of credentials, and the actions the remote side allows

The permission mode is the starting point for these boundaries. The current configuration may come from the organization, the user and the project at once, so read the final effective values before explaining the scope actually in force.

Command rules cover only specific entry points

Denying one way of writing a delete command blocks that kind of tool request. Other scripts can also delete, and an allowed shell can combine commands. Allow only the commands the task needs, and the process layer then limits directories and networks.

Tasks that only read source material should use a read-only execution environment where possible. For tasks that need to write files, mount only a dedicated output directory with write access. Do not put high-privilege publishing credentials into an execution process that reads external material.

Test the sandbox’s actual behavior

macOS, Linux and Windows differ in isolation mechanisms and what they support. A default mode of the current agent may also be overridden by organization configuration. First record the version and the effective configuration, then test reads and writes, subprocesses and the network.

The exercise materials provide a configuration starting point; check specific fields against Claude permissions, the Claude sandbox and Codex security. Even after the configuration parses, you still need behavioral tests.

In the demonstration directory, create one test case for each boundary, with the expected and actual results.
Try to read an ordinary test file with the direct tool and with a subprocess, separately.
Writing to an allowed directory should succeed; writing to the designated isolated directory should fail.
Test one allowed network target and one not allowed, and record the actual behavior.

Tests only show how these paths work under the current configuration. When you add tools, change how things are started or update versions, retest the affected paths.

An SSH exception is another capability

Put SSH outside the local sandbox and it gets the connection ability available to local processes; remote commands are then controlled by the server account. Minimize the remote account’s permissions, restrict the working directory, and use the cluster’s existing scheduling and network management.

If a task only needs to query job status, provide a query entry that returns only fixed fields. Access to an arbitrary remote shell grants more capability than a status query, and the configuration notes should state this choice clearly.

Organize roles by information flow

External material goes to the reading role, notes with sources go to the analysis role, and approved products go to the publishing role. The source label travels with every handoff, and publishing checks the target and authorization.

Summaries and structured JSON can also contain untrusted requests. Making material tidier does not change its source. Permissions are enforced at the executor; however careful the model’s judgment, it is only one layer.

Exercise

Choose one finishing step from Lesson 4 and list, item by item, the files it reads and writes, the network and the credentials. Find the smallest usable entry point for each action. Then run the same harmless test through another entry point and record where permissions expanded.

Common mistakes and how to fix them

Translating one vendor’s configuration into the other’s field by field. First write the capability needed, then implement and test the required behavior separately in each.

The allowlist names only domains and ignores exceptions for external tools. List commands outside the sandbox and connectors separately in the capability table.

Treating local directory isolation as remote isolation. Test the remote account and processes as a separate boundary.

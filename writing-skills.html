1.5 经验留档

学习目标

  1. 区分任务卡、项目约定、Skill 与运行记录各自应保存的内容，并为一项有效方法选择合适的存放位置。
  2. 从一次修订过程中抽象出输入、关键判断、调用入口和交付条件，形成不依赖具体文件名的方法描述。
  3. 设计分别检验入口加载、跨材料迁移和工作量选择的测试，并据测试结果定位失败原因。

课后深入专题，约 25 分钟。

第二次修订论文时，若仍需完整重复上次的全部要求，说明经验尚未形成可调用的方法。应找出反复有效的判断，把它们保存为后续任务可以加载的约定或 Skill。

稳定约定与可调用方法

项目约定记录每次都适用的事项：原件放在哪里，编译入口是什么，哪些数据不能覆盖。Skill 记录只在某类任务中使用的方法：怎样分析范文，怎样从数据核对推进到整稿重写，修订稿交给谁审阅。

位置 内容 读取时机
本次任务卡 当前材料和交付位置 开始本项任务时
AGENTS.md 稳定的工程约定 项目开工时
SKILL.md 及附件 完整方法、模板与脚本入口 命中相应任务时
运行记录 本次实际发生的过程 复现或复盘时

每次新增约定前先删除重复内容。对于反复出现的问题，优先考虑能否修进生成脚本或检查器。

可复用方法的提炼

回顾这次改稿的产物和我的纠正，提炼 paper-retell Skill。
说明输入与适用任务，再列出关键判断、需要调用的脚本及交付条件。
把本次论文的专用配置留在项目里，Skill 使用相对路径。

入口至少包括名称与描述：

---
name: paper-retell
description: Retell a complete research paper around its central finding, verify results against data, and hand the new version to an independent editorial reader.
---

描述决定 Skill 会在哪些任务中被发现。正文解释方法，附件提供表达对照表和脚本。对于只改一句话的请求，Skill 应能判断无需启动全文流程。

双平台共用时的入口检查

Claude Code 使用自己的 CLAUDE.md 入口，可通过 @AGENTS.md 导入共用约定。Skill 通常放在项目的 .claude/skills/；Codex 的项目技能可放在 .agents/skills/。用户级目录按各自当前文档配置，不要照抄旧文章。

同一份内容可以链接或复制到各个入口。若采用复制，应写明哪一份是维护源，并在每次修改后同步。Skill 能否被发现和加载，需用新会话验证。具体入口见 Claude Code Skills 与 Codex Skills。

可复用性的三项测试

第一项测试使用刚完成的稿件，检查 Skill 能否被调用。第二项换用一份结构相似的材料，检查它是否仍依赖第一篇材料的隐含信息。第三项只给出摘要编辑任务，检查它能否选择合适的工作量。

另记录一次失败。若 Skill 跳过了数字核查，先检查入口是否实际加载，再检查脚本路径和停止条件。把失败原因修正到对应位置，不要反复追加务必遵守之类的叮嘱。

练习

把参考答案中的 skills/paper-retell 安装到自己的练习项目，新开会话完成三项测试。每次只记录触发结果、调用的文件与缺失环节。比较修改前后的版本，保留能够迁移的最小版本。

常见错误与处理方法

把整段对话存为 Skill。 读者无法区分哪些是方法，哪些只是本次的决定。应提炼输入和判断，运行过程另行保存。

Skill 写死本机路径。 换一个项目就会失败。路径应相对于项目或 Skill 文件夹，机器信息由配置提供。

内容写得完整，却从未在新会话中调用。 先用新会话实测入口，再换材料测试方法。两项分别通过，才能判定为可复用。

1.5 Reusable methods

Learning outcomes

After this section, students should be able to:

  1. Distinguish stable project conventions, reusable task methods, task instructions and run records, and assign each to the appropriate location.
  2. Abstract a method from a completed task into a Skill that states its inputs, key judgments, scripts and delivery conditions without task-specific details.
  3. Evaluate whether a Skill is reusable through discovery, transfer and scope tests, and locate the cause of a failure.

Extension reading and exercises, about 25 minutes.

If every requirement from the first paper revision has to be stated again for the second, the experience has not yet become a tool. Reuse begins with identifying which judgments proved effective, and then recording them where a new session can find them.

Stable conventions and callable methods

Project conventions record what applies every time: where originals are kept, how the paper is compiled, which data must not be overwritten. A Skill records a method used only for a certain kind of task: how to analyze an exemplar, how to check data and restructure the full draft, and to whom the result is handed for review.

Location Content When it is read
This task card Current materials and delivery location When this piece of work starts
AGENTS.md Stable engineering conventions When work on the project starts
SKILL.md and attachments The full method, templates and script entry points When a matching task arises
Run record What happened in this run When reproducing or reviewing

Before a convention is added, duplicates are removed. For a problem that keeps recurring, first consider whether it can be corrected in the generation script or the checker.

Extracting a reusable method

Look back over the products of this revision and my corrections, and distill a paper-retell Skill.
State its inputs, the tasks it applies to, the key judgments, the scripts to call and the delivery conditions.
Leave the configuration specific to this paper in the project, and use relative paths in the Skill.

A Skill requires at least a name and a description:

---
name: paper-retell
description: Retell a complete research paper around its central finding, verify results against data, and hand the new version to an independent editorial reader.
---

The description allows the agent to discover the Skill for relevant tasks. The body explains the method, and attachments provide the style table and scripts. For a request to change a single sentence, the Skill should be able to determine that the full-paper process is unnecessary.

Checking entry points when both vendors share a Skill

Claude Code uses its own CLAUDE.md entry and can import shared conventions with @AGENTS.md. Skills are usually placed in the project’s .claude/skills/; Codex project skills can be placed in .agents/skills/. User-level directories are configured according to each vendor’s current documentation rather than older articles.

The same content can be linked or copied to each entry point. When copying, state which copy is the maintained source and synchronize every change. Confirm in a new session that the agent discovers and loads it. For the specific entry points, see Claude Code Skills and Codex Skills.

Three tests of reusability

The first test uses the draft just completed, to check that the Skill can be invoked. The second uses material with a similar structure, to check whether the Skill still depends on hidden information from the first case. The third gives only an abstract-editing task, to check whether the Skill selects an appropriate amount of work.

One failure is then recorded. If the Skill skips the number check, first check whether it was actually loaded, then the script paths and the stop conditions. The cause of the failure is corrected where it arises, rather than by adding a further instruction that the method must be followed.

Exercise

Install skills/paper-retell from the reference answers in your own exercise project and carry out the three tests in new sessions. For each test, record only whether the Skill was triggered, which files it used and which steps were missing. Compare the results before and after revision, and keep the smallest version that transfers.

Common errors and corrections

Saving an entire conversation as a Skill. A reader cannot separate the reusable method from decisions specific to the task. Distill the inputs and judgments, and keep the run record separately.

Hard-coding the local machine’s paths in the Skill. It then fails in another project. Paths are relative to the project or the Skill folder, and machine-specific information comes from configuration.

A complete Skill that has never been invoked in a new session. Test the entry point in a new session, then test the method on other material. The Skill is reusable only when both tests pass.

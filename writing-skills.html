1.5 把做法留下来

课后深入，约 25 分钟。

一次成功的改稿，如果下次还要从头讲一遍要求，就只是一次成功。把要求和流程存进文件，Agent 每次开工自己去读，这次的经验才会变成你的工具。存的地方有两个：AGENTS.md 和 Skill。

三个层次

放在哪里 什么时候加载 适合放什么
对话里说 只在这次对话 这一次的具体任务
AGENTS.md 每次开工都读，一直占着上下文 长期不变的约定：文件放哪，什么不能改，写作的基本口味
Skill 用到时才加载 一整套做法：步骤，对照表，脚本

判断的办法：一条要求是不是每次都适用。原稿只读，数字来自数据，这些每次都适用，放 AGENTS.md。怎样重讲一篇论文是一套九步的流程，只有改论文时才用，做成 Skill。

AGENTS.md 与 CLAUDE.md

Codex 每次开工读项目里的 AGENTS.md，Claude Code 读 CLAUDE.md。两家共用一套约定的办法，是只维护 AGENTS.md，在 CLAUDE.md 里只写一行：

@AGENTS.md

@ 表示把那个文件的内容引进来。子文件夹里也可以有自己的 AGENTS.md，只在那个文件夹里工作时生效。个人的长期偏好，比如回答用中文，放在用户目录的全局配置里，不放进项目。

AGENTS.md 最常见的问题是越写越长。每出一次问题就加一条，几周后几百行，互相重复甚至矛盾，Agent 反而不照做了。两条纪律：只放稳定的约定，不放操作步骤和一次性的调试记录；加新条之前，先删掉重复的，合并相近的。参考答案里的 AGENTS.md 只有五行。

Skill 的结构

一个 Skill 是一个文件夹，里面至少有一个 SKILL.md：

paper-retell/
├── SKILL.md            必需：说明和步骤
├── style_table.md      对照表，SKILL.md 里引用
└── check_numbers.py    脚本，步骤里调用

SKILL.md 开头是一段元数据：

---
name: paper-retell
description: Retell an academic paper from title to conclusion around its single most
  striking result, redraw its data figures at final size, and check every number against
  the data. Use when asked to revise, rewrite, polish or de-AI a paper draft.
---

description 最重要。Agent 平时只看到每个 Skill 的名字和这段描述，靠它判断什么时候该用。描述写清两件事：这个 Skill 做什么，什么样的请求应该触发它。描述太笼统，比如 helps with writing，它就几乎不会被自动调用。

元数据下面是正文：分步骤写清做法，引用同文件夹里的对照表和脚本。参考答案里有完整的 paper-retell，可以直接看。

放在哪里，怎么调用

Claude Code Codex
本项目可用 .claude/skills/<名字>/ .agents/skills/<名字>/
所有项目可用 ~/.claude/skills/<名字>/ ~/.codex/skills/<名字>/

两家的 SKILL.md 格式相同。只维护一份，在另一处放一个指向它的链接；如果某一家的版本不认链接，就复制一份，改动时两边一起更新：

把 .claude/skills/paper-retell 链接到 .agents/skills/paper-retell，让 Codex 也能用同一个 Skill。

调用有两种方式：Agent 根据描述自动判断，或者你直接点名。在 Claude Code 里输入 /paper-retell 就会加载它；在任何一家里说用 paper-retell 改这篇论文，也会加载。

什么时候做 Skill

第三次粘贴同一段要求时，就该做成 Skill 了。而且要在一次成功之后做，不要在开始之前凭想象写。最好的 Skill 是从一次真实的成功里提炼出来的：

回顾这次对话里我们改论文的全过程，哪些步骤是有效的，哪些是我纠正过你的。
把有效的步骤和我的纠正整理成一个 Skill，名字叫 paper-retell，放在 .claude/skills/ 下。
description 要写清楚什么样的请求应该用它。

测试一个 Skill

做好以后，开一个新对话，只说一句简短的请求，比如帮我改一下这篇论文的写法，看它是否自动用上了 Skill，是否按步骤走。没有用上，多半是描述没写清；用上了但跳了步骤，就把那一步在正文里写得更明确。

练习

把参考答案里的 skills/paper-retell 复制到你自己项目的 .claude/skills/ 下，用一篇你自己的论文测试。然后改它的 description，让它在用户说润色一下摘要时不触发，只在要求改整篇论文时触发。

提示

在 description 里写明触发和不触发的边界，例如 Use when asked to revise or rewrite a whole paper. For edits to a single paragraph or the abstract alone, do not use this skill. 改完在新对话里分别用两种说法测试。

最容易出错的地方

AGENTS.md 当日记写。 每次出问题都追加一条，几百行后 Agent 不再照做。只留稳定约定，加之前先删重。

把流程塞进 AGENTS.md。 九步的改稿流程写进 AGENTS.md，每次对话都要背着它，写代码时也背着。流程做成 Skill，用到时才加载。

描述写得太泛。 helps with writing 这样的描述，Agent 不知道什么时候该用，结果从来不用。写清做什么和什么时候用。

Skill 里写死本机路径。 写着 /Users/你的名字/ 的 Skill，换台电脑或者分享给同学就失效。路径一律相对于项目或者 Skill 自己的文件夹。

1.5 Keeping the method

Self-study, about 25 minutes.

A successful revision that you have to explain from scratch next time stays a one-off success. Save the requirements and the workflow in files the agent reads on its own whenever it starts work, and what worked this time becomes your tool. There are two places to keep them: AGENTS.md and Skills.

Three layers

Where it lives When it loads What belongs there
Said in the conversation Only in this conversation The specific task at hand
AGENTS.md Read at the start of every job, always taking up context Lasting conventions: where files go, what must not change, your basic taste in writing
Skill Loaded only when needed A whole method: steps, a style table, scripts

To decide, ask whether a requirement applies every time. The draft is read-only, and numbers come from data: these apply every time, so they go in AGENTS.md. Retelling a paper is a nine-step workflow used only when revising a paper, so it becomes a Skill.

AGENTS.md and CLAUDE.md

Codex reads the project’s AGENTS.md at the start of every job; Claude Code reads CLAUDE.md. To give both agents one set of conventions, maintain only AGENTS.md and put a single line in CLAUDE.md:

@AGENTS.md

The @ pulls in that file’s contents. Subfolders can have their own AGENTS.md, which applies only when working in that folder. Lasting personal preferences, such as answering in Chinese, go in the global configuration in your home directory, outside the project.

The most common problem with AGENTS.md is that it keeps growing. Add a line every time something goes wrong, and a few weeks later it runs to hundreds of lines that repeat and even contradict each other, and the agent stops following it. Two rules keep it in check: hold only stable conventions, never operating steps or one-off debugging notes; and before adding a line, delete duplicates and merge similar ones. The AGENTS.md in the reference answers is five lines long.

How a Skill is built

A Skill is a folder holding at least one SKILL.md:

paper-retell/
├── SKILL.md            required: description and steps
├── style_table.md      style table, referenced from SKILL.md
└── check_numbers.py    script, called from the steps

SKILL.md opens with a block of metadata:

---
name: paper-retell
description: Retell an academic paper from title to conclusion around its single most
  striking result, redraw its data figures at final size, and check every number against
  the data. Use when asked to revise, rewrite, polish or de-AI a paper draft.
---

The description matters most. Day to day, the agent sees only each Skill’s name and this description, and uses them to decide when to reach for it. A description says two things clearly: what the Skill does, and which requests should trigger it. Make it too vague, such as “helps with writing”, and it almost never gets called automatically.

Below the metadata comes the body, which lays out the method step by step and refers to the style table and script in the same folder. The reference answers include the complete paper-retell, ready to read.

Where to put it and how to call it

Claude Code Codex
Available in this project .claude/skills/<name>/ .agents/skills/<name>/
Available in every project ~/.claude/skills/<name>/ ~/.codex/skills/<name>/

Both use the same SKILL.md format. Keep one copy and put a link to it in the other location. If one vendor’s version doesn’t follow links, copy it instead, and update both copies whenever you change it:

Link .claude/skills/paper-retell to .agents/skills/paper-retell so Codex can use the same Skill.

There are two ways to call a Skill: the agent decides from the description on its own, or you name it. Typing /paper-retell in Claude Code loads it, and so does saying “use paper-retell to revise this paper” in either app.

When to make a Skill

The third time you paste the same requirements, it is time to make a Skill. Make it after a success; don’t write one in advance from imagination. The best Skills are distilled from a real success:

Go over how we revised the paper in this conversation: which steps worked, and where I corrected you.
Turn the steps that worked and my corrections into a Skill called paper-retell, saved under .claude/skills/.
The description must say clearly which requests should use it.

Testing a Skill

Once it is built, open a new conversation and make one short request, such as “help me improve the writing of this paper”, then watch whether it picks up the Skill on its own and follows the steps. If it doesn’t use the Skill, the description is most likely unclear. If it uses the Skill but skips a step, write that step more explicitly in the body.

Exercise

Copy skills/paper-retell from the reference answers into .claude/skills/ in your own project and test it on a paper of your own. Then change its description so it does not trigger when the user says “polish the abstract”, and triggers only when asked to revise the whole paper.

Hint

State the boundary between triggering and not triggering in the description, for example: Use when asked to revise or rewrite a whole paper. For edits to a single paragraph or the abstract alone, do not use this skill. Then test both phrasings, each in a new conversation.

Where agents go wrong most

Writing AGENTS.md like a diary. Append a line every time something goes wrong, and after a few hundred lines the agent stops following it. Keep only stable conventions, and remove duplicates before adding.

Stuffing a workflow into AGENTS.md. Put the nine-step revision workflow in AGENTS.md and every conversation carries it, even while writing code. Turn workflows into Skills, loaded only when needed.

A description that’s too broad. With a description like “helps with writing”, the agent can’t tell when to use the Skill, so it never does. Say what it does and when to use it.

Local paths hard-coded in a Skill. A Skill that says /Users/yourname/ breaks on another computer or when shared with a labmate. Make every path relative to the project or to the Skill’s own folder.
